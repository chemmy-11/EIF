## 2. 烧写：BitElf（位流 + ELF 一起）+ 串口 `d`

```powershell
# ① 烧（-Root/-Config 决定烧哪片；哈希不符会拒绝烧）
powershell -NoProfile -ExecutionPolicy Bypass -File D:\FPGA\prj\project_12\out\twin_burn.ps1 `
  -Board A -Mode BitElf -Run `
  -Root D:\FPGA\prj\project_13 -Config D:\FPGA\prj\project_13\out\twin_config_13.json
# 期望：BURN_OK + BURN_ELF_DONE

# ② 串口进 DMA（翻转命令，只看最后一条 banner）
powershell -File scripts\serial_dma_mode.ps1 -Com COM6    # PC2: -Com COM5
# 期望：SERIAL_RESULT: PASS / now=DMA
```

**配对纪律（今天最容易错的一步）**

1. 烧哪片位流，`twin_config` 的 `expect_bit_sha256` 就必须是那片的哈希：`CFA98553…` 或 `F16FCE70…`。跨片混用 → `twin_burn` 直接拒烧（这是保护，不是故障）。
2. **位流 + ELF + ltx 三者成对**；ltx 两片共用 `B30C3903`。
3. `d` 是**翻转**命令：连发两次会切回去，只看**最后一条** banner。
4. 位流在 JTAG SRAM、ELF 在软核 RAM、`d` 在固件 RAM —— **每次上电都要重来一遍**。

> **为什么必须 `d`**（行号可核）：`d` 会让固件把 `R_MODE` 置 `MODE_SEQ`（`sw/src_j3/main.c:638-660`），而 RTL 在 `cfg_mode_eff==0` 时**自动读 mem1**（`rtl/aurora_mem_bridge.v:384-386`），固件空闲循环每圈 `serve_any()`（`main.c:611-616`）。所以 `now=DMA` 一成立，发一帧就该在六点上各 +1。

## 3. 档 1：**不接光纤** —— 本地通路（先做，最便宜）

### 3.1 前提（别误判）

无光纤时 `channel_up=0` → `aurora_rst=1`（`rtl/aurora_mem_bridge.v:234`）→ **P2 转发侧（extract/buf/steer/rewrap）处于复位**，这是设计使然；
而本地栈/`stack_takeover` 走 `eth_rst_n = sys_rst_n`（`:183`）**不受链路门控**。⇒ 本档只看 PC 侧现象，**不看任何 Aurora 计数**（`pfwd_wr/pk_frames/up_frames/prev_wr` 全 0 是预期，`ch_up=0` 也不是失败）。

### 3.2 判据

| # | 操作 | 期望 | 不通过 → 说明什么 |
|---|---|---|---|
| L1 | `arp -d 10.10.0.11` 后 `ping 10.10.0.11 -n 20`；再 `arp -a \| findstr 10.10.0.11` | 学到 `02-00-00-00-0a-01`；20/20 回、<1 ms | ARP 应答没从本板 GE2 出去（`stack_takeover`/mux 没生效） |
| L2 | `ping 10.10.0.2 -n 3`（对端 PC，本档应不通） | **3/3 超时** | 若居然通 → 无链路还在转发，**异常，立即报** |

> L1 一通，就已经证明了 P1 做不到的事（P1 位流下板卡应答只往 Aurora 走，本板 PC 收不到）。

## 4. 档 2：**SFPA 自环** —— 转发通路

### 4.1 物理接法

一根光纤跳线把 **SFPA（X1Y11）的 TX 接到 RX**（同一模块自环；prj8 用过的成熟配置）。

### 4.2 判据链

| # | 动作 | 判据 |
|---|---|---|
| S0 | 抓 ILA6 | `ch_up=1 lane_up=1 gt_pll_lock=1 link_ok=1 aurora_rst=0 hard/soft=0` |
| S1 | 起抓包（30 s）→ 发 1 帧 `dst=10.10.0.2` | 六点差分各 **+1**：`pfwd_wr → mem_wr_frm/rd_frm → pk_frames → up_frames → mem2_wr/rd_frm → prev_wr` |
| S2 | pcap 逐字节 | 回来 = `dst=A8:2B:DD:76:DF:A2`、`src=02:00:00:00:0A:01`、`0x0800`，**IP 包逐字节相同** |
| S3 | 小包（IP 总长 40） | 帧长 **60**，后 20 B 全 `0x00` |
| S4 | 分片（MF=1、offset≠0） | 逐字节相同、**不重组** |
| S5 | 反向：`dst=10.10.0.11`（BOARD_IP） | 自环上**零帧**（走本地通路），`pfwd_wr` 不动 |
| S6 | 反向：`dst=8.8.8.8` ×3 | 自环上**零帧**（防乒乓红线） |

### 4.3 命令（有管理员 / 无管理员两条路，按本机情况选）

```powershell
# --- 抓包（免管理员，Npcap）---
py pc\npcap_capture.py --iface "<数据网卡>" --seconds 30 --out out\tier2_rx.pcap

# --- 发帧 A：OS 栈路径（需管理员配好 10.10.0.1/24 + 静态 ARP）---
py pc\static_arp.ps1 -Scheme handbook -BoardPcPair A -IfAlias "<数据网卡>" -Apply
py pc\twin_send.py --scheme handbook --dst-ip 10.10.0.2 --dst-port 1234 --count 1 --len 100 --run-id 0x11 --interval-ms 0

# --- 发帧 B：免管理员（UAC 过滤令牌下唯一可用路径）---
py pc\p2_rawsend.py --list
py pc\p2_rawsend.py --iface <设备名片段> --dst-ip 10.10.0.2 --count 1 --len 100 --run-id 0x11
# 期望：SEND_DONE: ok=1 bad=0

# --- 判据 ---
py pc\twin_recv.py --from-pcap out\tier2_rx.pcap --scheme handbook --no-bcast `
    --expect-count 1 --expect-len 100 --expect-run-id 0x11
```

**两个坑（今天必须知道）**

1. **MAC 过滤**：回环帧 `dst = PEER_MAC = A8:2B:DD:76:DF:A2`（PC2 网卡），发到 PC1 → **PC1 网卡按 MAC 丢弃，应用层收不到**。所以判据**必须走 pcap**（promiscuous）。做不到应用级收包是**预期**，不是失败。
2. **`p2_rawsend.py` 的 `--src-mac` 默认是 PC2 网卡**。档 2 用它没问题（回环帧的 dst 由 RTL 参数决定），但**档 1 类判据（ping/ARP/本地通路）不能用它** —— 板卡回包会打到 `src_mac` 上，你收不到；档 1 必须走 OS 栈（提权）。

### 4.4 抓 ILA 的命令

```powershell
$env:TEMP='D:\FPGA\.tmp'; $env:TMP='D:\FPGA\.tmp'
$ltx = 'out\b_p2_CFA98553\probes_p2_B30C3903.ltx'   # 两片通用
vivado -mode batch -source scripts\ila_capture_any.tcl -tclargs localhost:3121 210512180081 out\ila6_p2.csv $ltx dbg_pk_frames none
vivado -mode batch -source scripts\ila_capture_any.tcl -tclargs localhost:3121 210512180081 out\ila3_p2.csv $ltx dbg_mem_wr_frm none
vivado -mode batch -source scripts\ila_capture_any.tcl -tclargs localhost:3121 210512180081 out\ila0_p2.csv $ltx dbg_pfwd_en    none
```
> 第 5 个参数 `none` 会打 `ILA_TRIGGER_SKIP` 然后**立即抓**（计数器类判据要的就是这个），不是错误。
> ILA0 的 `dbg_pfwd_data/dbg_pfwd_en` 是**转发流的原始字节**，抓一次就能看到 IP 包头 `45 00 …` —— 这是当前唯一能"眼看字节"的探针。

## 5. 顺手采集（v1.1 能力文件要的四个数，只有上板能填）

| 字段（v1.1 §5.4） | 怎么测 | 记录 |
|---|---|---|
| `max_udp_payload_bytes` | `--len` 扫 100 / 1200 / 1400 / 1472，各 1 帧看 S2 是否仍逐字节 | 最大通过的 len |
| `buffer_full_behavior` | 连发 3 / 5 / 8 帧背靠背（`--count N --interval-ms 0`） | `pfwd_wr` 与 `st_rx_drop` 实测值；**丢是整帧丢** |
| `max_safe_rate_mbps` | `--interval-ms` 扫 20 / 5 / 1 / 0，各 20 帧 | 0 丢的最高档 |
| `max_inflight_segments` | 本轮**不测**（属协议层，B 组口径） | 写 `TO_MEASURE` |

> 无板时这些一律写 `TO_MEASURE`，**不许外推**（现有唯一数据点是 I10：3 帧 × 1472 B 背靠背 3/3）。
