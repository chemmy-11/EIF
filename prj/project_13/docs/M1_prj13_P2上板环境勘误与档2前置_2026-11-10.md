## 3. 环境勘误三则

### 3.1 `D:\fpga\prj` junction 被替换成实体目录

**现象**：`build_synth_only.tcl:16` 的 `open_project $proj/vivado/prj13.xpr`（`$proj=D:/FPGA/prj/project_13`）报

```
ERROR: [Coretcl 2-27] Can't find specified project.
```

**根因（磁盘直读）**：

- 该脚本第 14 行 `file mkdir $proj/out` 执行后，`D:\fpga\prj` 的 **CreationTime 变成 2026-11-10 15:37:46**，`fsutil reparsepoint query D:\fpga\prj` 报 `Error 4390: The file or directory is not a reparse point.`
- 即：原本指向 `D:\fpga\FPGA_Project\EIF-master\prj` 的 junction 已经不存在，`file mkdir` 把 `D:\fpga\prj\project_13\out` 建成了**实体目录**（内含 0 个文件）。

**官方口径**：`open_project`（UG835）要求 `<file>` 是**可解析的完整路径**，路径不可解析时报的就是找不到文件 —— 与实测一致，不是 Vivado 缺陷。

**处置（不删数据）**：把误建的实体树改名为 `D:\fpga\prj.stray-20261110_153746`（保留，内含 0 文件），再
`mklink /J D:\fpga\prj D:\fpga\FPGA_Project\EIF-master\prj`；复验 `xpr`/`rtl`/`prj9` 三个路径全部 True。

> 纪律提示：所有构建脚本硬编码 `D:/FPGA/prj/project_13`，因此**该 junction 是构建的硬前提**；每次长构建前应先 `Test-Path <xpr>` 自检，掉了就尽早失败，别让 `file mkdir` 把路径实体化。

### 3.2 Vivado 安装文件瞬时读失败（伪装成 MIG 失败）

**现象**：`build_impl.tcl` 在 `implement_debug_core` 的 `Phase 1 Generate And Synthesize MIG Cores` 崩：

```
ERROR: [IP_Flow 19-3805] Failed to generate and synthesize debug IP xilinx.com:ip:ddr4_phy:2.2.
ERROR: [Common 17-69] Command failed: Vivado Synthesis failed
ERROR: [Mig 66-119] Phy core regeneration & stitching failed.
ERROR: [Opt 31-306] MIG/Advanced IO Wizard Cores generation Failed.
```

**真根因**（Vivado 自己指出的 `debug_core_synth.log` 原文）：

```
14 Infos, 0 Warnings, 0 Critical Warnings and 1 Errors encountered.
```

**不是缺件**：该文件存在且可读，`1097 B`，`SHA256` 前 16 = `7A0B662B235EFCC6`，在
`D:\vavido\Vivado\2023.1` 与 `D:\Xilinx\Vivado\2023.1` 两份安装里**完全一致**。

**官方口径**：AR 73052 列出的正是这一对错误（`Mig 66-119` + `Opt 31-306`），并说明除特定版本缺陷外，其余情形多为环境/产物问题，建议"reset and regenerate the IP output products"并排查环境。

## 4. 无管理员主机上的 PC 侧注入：`pc/p2_rawsend.py`

**为什么需要**：`pc/twin_send.py:11` 自述
> standard library only, plain UDP socket, no admin / no Npcap

即它走 OS 协议栈，要求网卡拥有 `10.10.0.1/24` 且 `10.10.0.2 → 02:00:00:00:0A:01` 有静态 ARP —— 两件都要**提权**。
本机 agent shell 是 UAC 过滤后的管理员令牌（`whoami /groups`：`BUILTIN\Administrators ... Group used for deny only`，完整性级别 `Medium`），`net session` 返回 `System error 5`，因此**无法改 IP/路由/邻居表**。

**方案**：用 Npcap 的 `pcap_sendpacket` 直接注入二层帧，完全绕开 OS 路由。
载荷与 42 B 头**从 `twin_send.py` 导入**（`build_payload` / `build_frame_header`），保证与 `twin_recv.py --from-pcap` 判据逐字节兼容。

**实测**（2026-11-10，非提权令牌）：

```
SEND_DONE: ok=1 bad=0
```
抓包侧同样免管理员可用：
```
CAPTURE_OK: frames=0 ... linktype: 1 (1=Ethernet)
```

**用法**：见文件头；默认即板 A 的 handbook 参数集（`10.10.0.1 → 10.10.0.2`，eth dst `02:00:00:00:0A:01`）。
