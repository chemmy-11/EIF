## 5. 这份位流**是什么**（功能集合，必须照此使用）

- **P2 v0.2 透明 IPv4 转发**：`dst==PEER_IP` 的 IPv4 包 → 剥 14 B 以太头 → Aurora → 对端板重加 14 B 头 → 对端 PC；**IP 包逐字节不变**。
- **地址（手册 §8 裁决）**：本板 `BOARD_IP=10.10.0.11`、`BOARD_MAC=02:00:00:00:0A:01`、`PEER_IP=10.10.0.2`、`PC_IP=10.10.0.1`、`PEER_MAC=A8-2B-DD-76-DF-A2`（**这是板 A 的参数集**；板 B 需另出一份：`.12 / 0B:01 / .1 / .2`）。
- **本地栈改走本板 GE2**：ARP/ICMP/管理 UDP 应答不再跨板（P1 的"跨板回声"结构上消失）。
- **ARP 本地终结**、`BOARD_IP` 走本地栈、其余 dst/VLAN/IPv6/广播/组播/超长/坏 checksum/截断 → DROP（计数器在 RTL 里，但**本候选未挂 ILA**，见 §7）。

## 7. 已知限制 / 使用红线

1. **未经上板**：V4 全部验收项待板；`check_bitstream_readiness` 对 checkpoint 式构建只覆盖"位流已写出"事实，**不能证明可烧、更不能证明功能正确**。
2. **P2 计数器未挂 ILA**：11 个 drop 计数器 + relay/local/arp 已在 RTL，但为保那 15/4 ps 余量没有加 `mark_debug`。V4 前必须补一路探针（32–48 bit）并重跑守门。
3. **不能用这份位流跑 P1 判据**：P1 的回声语义已被替换，`twin_recv --scheme p1`（`00:11:22:33:44:55`）在这份位流上必然全丢。用 `--scheme handbook`。
4. **吞吐上限未证**：2-bank + 暂存转发，实测 3 帧满帧背靠背 3/3；>3 连发未测，不外推。
5. **`stack_takeover` 抢帧风险**：本地栈应答与回程帧同拍起帧时，被抢那一帧会坏（不静默通过）。
6. **板 B 需另出一份位流**（参数不同，源码同一份）。
