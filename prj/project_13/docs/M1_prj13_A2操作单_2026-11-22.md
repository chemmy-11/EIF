## 2. 固定 B 组实验输入

2026-11-23 复核 [交付 PR #36](https://github.com/chemmy-11/GSnFPipe-FPGA-PP/pull/36) 为打开的 Draft，head `110265b335030fcbd3c9574a1f551858b16c9f6d`。线格式 [PR #38](https://github.com/chemmy-11/GSnFPipe-FPGA-PP/pull/38) 已合入交付分支（`5efb795`）。冻结源 `docs/protocol_v2_GPP2.md` 与 [#6 最新决议](https://github.com/chemmy-11/GSnFPipe-FPGA-PP/issues/6#issuecomment-6949601843) 一并应用。交付包尚未合入 main，按其固定提交取向量。

- GPP2/v1 固定头 52 B，META / DATA / ACK / ERROR，前 48 B 头与消息 payload 做 CRC32。固定向量中的 META ACK 使用 `0xFFFFFFFF`，DATA ACK 逐片返回并保留原传输方向字段。同一 GPP2 方向可以对应一对相反方向的 IP 流。
- UDP 应用数据报上限 **1200 B**（含头），DATA 净数据每片最多 **1148 B**。无 IPv4 选项时最大 IP 总长 **1228 B**。单 Tensor 协议上限 8 MiB。两端均绑定业务地址的 UDP **47001**。模板历史地址和 demo 默认端口仅用于原场景。
- 空 Tensor 依 #6 勘误按 `segment_count=0`，仅 META/META ACK。该向量在本批未提供，空 Tensor 用例记 `BLOCKED`。labels 作为独立 int64 transfer，留给 J1/J2 应用联调。
- P2 只换每跳的 L2 头，保留完整 IP 包。板卡本地 ARP 和 GPP2 的 ACK 是不同层的流量。校验、去重、重组、应用错误和送达语义由 PC 端负责，FPGA 保持 GPP2 内容透明。
- PR 包内 `b2_m3_api.py` 的 `fpga_udp` 分支仍显式返回 `NotImplementedError`。本单用普通 UDP socket 直接承载固定向量。J1/J2 调用后端之前确认 B 组的实机适配及验证入口。

## 4. 发送真实 GPP2 样包

最小实板集按两方向对称执行。PC1→PC2 用 `FWD_short_1B`、`FWD_max_1148B`，PC2→PC1 用 `BWD_short_1B`、`BWD_max_1148B`。每个用例发送 META 后等 META ACK，再发一片 DATA 并等对应 ACK。分别再用最大包用例的 META 标识构造一帧合法 ERROR 跑单向承载，反向交换端点。所有 ACK 从对端业务 IP:47001 返回，顺序与内容取自固定向量。

将下段在两端的调试终端执行。填写 `$Side='rx'/'tx'`、`$Mode='data'/'error'`、`$VectorCase`，同一轮两端的模式和向量一致。`$SelfIP/$PeerIP` 取本侧与对端，`$VectorLog` 取本轮新文件。每轮送完等对方输出 RESULT 后再换向。该步骤以预期向量校验承载与 ACK 路径，后续 B 组可靠层的实机行为仍须校验。

~~~powershell
@'
import hashlib
import json
from dataclasses import replace
from pathlib import Path
import socket
import sys
import time

tree, j0, side, mode, case, local, remote = sys.argv[1:]
sys.path.insert(0, tree)
from pp.transport import gpp2_codec as gpp2

root = Path(j0)
manifest = json.loads((root / "test_vectors" / "manifest.json").read_text(encoding="utf-8"))
entry = next(row for row in manifest["cases"] if row["case"] == case)
if entry["data_segments"] != 1 or side not in {"tx", "rx"} or mode not in {"data", "error"}:
    raise SystemExit("Use a one-segment fixture and valid tx/rx and data/error modes")
files = {Path(row["path"]).name: row for row in entry["packets"]}

def read_packet(name):
    record = files[name]
    wire = (root / record["path"]).read_bytes()
    if len(wire) != record["bytes"] or hashlib.sha256(wire).hexdigest() != record["sha256"]:
        raise ValueError(f"fixture hash/length mismatch: {name}")
    gpp2.decode(wire)
    return wire

def send(sock, wire):
    if sock.send(wire) != len(wire):
        raise RuntimeError("short socket send")
    show("TX", wire)

def receive(sock, expected):
    wire = sock.recv(65535)
    show("RX", wire)
    if wire != expected:
        raise ValueError("received datagram differs from fixture")
    return wire

def show(action, wire):
    pkt = gpp2.decode(wire)
    digest = hashlib.sha256(wire).hexdigest()
    print(action, gpp2.KIND_NAMES[pkt.kind], pkt.run_id, pkt.transfer_id,
          pkt.segment_index, len(wire), digest, flush=True)

with socket.socket(socket.AF_INET, socket.SOCK_DGRAM) as sock:
    sock.bind((local, 47001))
    sock.connect((remote, 47001))
    sock.settimeout(180 if side == "rx" else 10)
    print("UDP_READY", sock.getsockname(), sock.getpeername(), case, mode, flush=True)
    if mode == "error":
        meta = gpp2.decode(read_packet("META.bin"))
        error_wire = gpp2.encode(replace(meta, kind=gpp2.ERROR, payload=b"A2 ERROR probe"))
        if side == "tx":
            send(sock, error_wire)
        else:
            receive(sock, error_wire)
    else:
        for name, ack in (("META.bin", "ACK_META.bin"), ("DATA_0000.bin", "ACK_0000.bin")):
            wire, reply = read_packet(name), read_packet(ack)
            if side == "tx":
                send(sock, wire)
                receive(sock, reply)
                time.sleep(0.020)
            else:
                seen = receive(sock, wire)
                if name.startswith("DATA"):
                    digest = hashlib.sha256(gpp2.decode(seen).payload).hexdigest()
                    if digest != entry["payload_sha256"]:
                        raise ValueError("effective payload SHA256 mismatch")
                    print("APPLICATION_SHA256", digest, flush=True)
                send(sock, reply)
print("RESULT: PASS", case, mode, side)
'@ | py -3 - $ProtocolTree $J0 $Side $Mode $VectorCase $SelfIP $PeerIP | Tee-Object -FilePath $VectorLog
if ($LASTEXITCODE -ne 0) { throw "GPP2 socket probe failed: $VectorCase/$Side/$Mode" }
~~~

短 DATA 的 UDP payload 为 53 B，ACK 为 52 B。最大 DATA 的 UDP payload 为 1200 B，IP 总长 1228 B。检查每个端点的 TX/RX、P2 计数和 pcap。分别保留 META ACK、DATA ACK 的反向证据和 ERROR 的接收记录。当前固定样包按一片在途验证，实际可承受窗口留待专项测定。

## 5. 整个 IPv4 包逐字节对照

每个 pcap 包含完整帧。按同一业务 IP、发端 NIC MAC、收端板 MAC、接收 PC 单播 MAC 和用例窗口匹配。半程计数与端点内容共同签收。Windows 源端抓包如果受校验和卸载影响，记录原配置并在试验网卡上暂时关闭相关卸载后重抓，或使用可信的线上抓包点。字节级结论需采用可比的实际报文。

以下命令在 prj13 根目录离线运行。输入同一轮两个 pcap，`$FlowSrc/$FlowDst` 按当前被核对的 IP 方向设置。`$TxNicMac`、`$TxBoardMac`、`$RxBoardMac`、`$RxNicMac` 都用冒号格式。GPP2 DATA 用例每个物理方向应各 2 帧（META/DATA 或两个 ACK），ERROR 单方向 1 帧。TWIN 分方向填写实际预期数量。双向都用同一对文件时反向交换参数并重新对照。

~~~powershell
@'
import sys

sys.path.insert(0, "scripts")
from p1_judge import parse_frame, read_pcap

tx, rx, src, dst, tx_nic, tx_board, rx_board, rx_nic, magic, count = sys.argv[1:]

def collect(path, eth_src, eth_dst):
    frames, _ = read_pcap(path)
    packets = []
    for _, raw in frames:
        frame = parse_frame(raw)
        ip, udp = frame["ip"], frame["udp"]
        if not udp or ip["src"] != src or ip["dst"] != dst:
            continue
        if udp["dport"] != 47001 or frame["src_mac"] != eth_src.lower():
            continue
        if not udp["payload"].startswith(magic.encode("ascii")):
            continue
        if (frame["dst_mac"] != eth_dst.lower() or frame["vlan"] or frame["frag"]
                or ip["mflag"] or udp["truncated"] or len(raw) - frame["fcs"] != 14 + ip["tot"]):
            raise ValueError(f"wrong L2 destination or invalid IP in {path}")
        packets.append(raw[14:14 + ip["tot"]])
    return packets

sent = collect(tx, tx_nic, tx_board)
received = collect(rx, rx_board, rx_nic)
print(f"IP_COMPARE tx={len(sent)} rx={len(received)} expected={count}")
if len(sent) != int(count) or sent != received:
    sys.exit("FAIL: full IP stream differs")
print("PASS: all IP bytes identical")
'@ | py -3 - $TxPcap $RxPcap $FlowSrc $FlowDst $TxNicMac $TxBoardMac $RxBoardMac $RxNicMac $Magic $Expected
if ($LASTEXITCODE -ne 0) { throw "IP comparison failed" }
~~~

此命令的 `$Magic` 设为 `TWIN` 或 `GPP2`。每个输入文件只保留当前测试窗口的一次同类型业务。对比完整 IP 头、UDP 头和 UDP payload，板侧重新计算 Ethernet FCS 的证据沿用 D1 的 ILA 取证方法。另看应用接收记录，完整的 pcap 与应用实际收到均要回填。

### 6.1 正式 V4 工件与待构建项

同窗 T5、GPP2、完整 IP、ARP 和连续性可沿用成对 D-fix。**完整 V4 需要同一源码基线的软 A / 软 B 两份观察工件**。旧 `60ddcf26` 的软 A 提供入口三类和缓冲读数。本轮 A1-6 诊断软 A 只覆盖写等待超时。正式构建保持 D-fix 数据面、角色参数及 BA3C0220 ELF。G4 补测沿用已有修复后 A 参数工件。

| 采样时钟 | 正式件探针规格 |
| --- | --- |
| `gmii_rx_clk` | `p2_st_rx_frames / p2_st_relay / p2_st_local / p2_st_arp`、`p2_st_rx_drop`，以及 VLAN、IPv6、EtherType、广播、组播、未知目的 IP、超长、坏校验、截断、错误 MAC 十类计数。分类为 32 位，入口整帧缓冲丢弃源为 16 位。 |
| `user_clk` | 保留 D-fix 的链路、收发阶段及错误探针。新增 Aurora 缓冲 `p2_st_aur_frames / p2_st_aur_drop / p2_st_lan_frames`（16 位源）及 `p2_st_aur_bad_v4`（32 位）。 |
| 组包与确认 | A/B 同源码、各自绑定实际 MAC/IP 参数，各用对应编译配置实现。每件记录探针位宽、采样时钟、复位及计数清零条件。Vivado 2023.1 检查 WNS/WHS ≥ 0、失败端点为 0、保留原 VIO，交付 bit/ltx/ELF 全哈希和时序报告。换流后先跑双向 20×100 B、§4 最大 DATA+ACK，再签 T5–T8 与单类负例。 |

### 6.2 正负例顺序

先做正例 T5 和 GPP2、连续性，再注入各类负例。各轮取对应计数前后值，背景静默并归档双方原始 pcap。单类报文要能在发送口捕获，针对入口接收点取相应证据。

| 用例 | 实做与验收 |
| --- | --- |
| **T8 连续性** | 两个方向分别单次连续发流，建议 TWIN 1200 B、9201 帧、20 ms（设定的首尾间隔 184 s），用 A1 收发命令和对账方法。抓包窗先留 420 s，两边见真实发包和接收各跨 ≥180 s，捕获首尾、0 缺失和逐字节相同，链路/DMA/错误计数无异常。准备晚或 Windows 调度拉长时，延长一次完整窗口。 |
| **T6 本地 ARP** | 双端抓包。在业务网卡上移除本板**管理 IP** 那一条邻居，保留对端 PC 的静态邻居。用绑定本侧源 IP 的 `ping -4 -S $SelfIP -n 3 $BoardIP` 触发真实 ARP。源侧 pcap 必须看到本次请求及本地应答（按 SPA/TPA/MAC 匹配），对端无该请求/应答，转发计数不涨。恢复原静态邻居后跑三帧正例。 |
| **T7 防乒乓** | 给本板 MAC 发目的 IP 非 BOARD_IP、非 PEER_IP 的明确单播帧。用下例发往专用段未占用的 `10.10.0.99`。源侧证明已注入，`st_drop_unknown_dst +3`，转发和对端对应包 0，随后正常三帧仍通过。 |
| **分类 DROP** | 见下表。每类单独一个 run ID 或试验编号，先 1 帧核对命中，再按需用有间隔的 ≤3 帧复核。只有入口可证且分类计数变化对应，才能签这类。 |

T7 在发送端使用 A1 的地址与网卡变量。若 `10.10.0.99` 已占用，换同一隔离段内的其他未用地址。保留完整命令行和输出。

~~~powershell
py -3 pc/p2_rawsend.py --iface $Guid --src-ip $SelfIP --dst-ip 10.10.0.99 `
  --src-mac $NicMac --dst-mac $BoardMac --sport 47001 --dport 47001 `
  --count 3 --len 100 --run-id $RunId --interval-ms 20
if ($LASTEXITCODE -ne 0) { throw "T7 injection did not complete" }
~~~

| 单类输入（除被测字段外用已确认正例） | 期望计数 |
| --- | --- |
| 802.1Q VLAN（0x8100），IPv6（0x86DD），非 IPv4/非 ARP EtherType（如 0x88B5），三类分别注入 | `st_drop_vlan`、`st_drop_ipv6`、`st_drop_ethertype` |
| IPv4 广播、IPv4 组播、有效 IPv4 的未知目的 IP，三类分别注入 | `st_drop_broadcast`、`st_drop_multicast`、`st_drop_unknown_dst` |
| 声明 IP 总长 1501，保持可达 GE1 的帧长度。实际线上 jumbo 若需验，另从可发送的受控设备明确注入 | `st_drop_oversize` |
| 单独翻转 IPv4 头校验和。截断另测，构造合法校验和且声明长度大于实际可用字节，避开最小帧填充的影响 | `st_drop_bad_csum`、`st_drop_truncated` |
| 目的 MAC 改为非本板的单播，IPv4 地址仍符合转发条件 | `st_drop_mac` |
| 入口队列满或缓冲拒收，先通过离线 TB 验证边界，有观测后再在独立维护轮受控触发 | `st_rx_drop`，这是缓冲丢弃。Aurora 侧 `st_aur_drop / st_aur_bad_v4` 独立登记。 |

其他 L2 负例由现场可控注入器从正例修改单一字段，并保留实际输入包。修改 IPv4 字段时重算 IP 头校验和，校验和负例保留故意错误。VLAN/超长等若被主机 NIC 提前过滤，改用能够发出对应线上形态的夹具或将该实板项记 `BLOCKED`。预先用 [P2 仿真入口](../sim/p2/run_p2_sim.ps1) 检查单元和集成用例，不以仿真结果代签上板。

计数源以 [local_steer.v](../rtl/p2/local_steer.v) 的 10 个分类计数和 [p2_relay_top.v](../rtl/p2/p2_relay_top.v) 的缓冲/光段统计为准。上板前对每项登记实际探针、时钟域、位宽、清零条件；`st_rx_drop` 从 16 位计数扩展。D-fix 现有 ILA 有数据链路点，读取不到分类时保留阻塞项和对应观测构建需求。每类输入有后续正例，避免把停摆后的“零上线”记成正确丢弃。

### 8.3 结论：**`b2_fixed_tensor_demo.py` 不可用作 §5.4 正式取证入口**

2026-11-27 复审实测两处硬缺陷，均已在源码上核实：

| # | 缺陷 | 源码依据 | 后果 |
|---|---|---|---|
| 1 | **`--server-port` 只作用于 A 角色**；B 角色绑定 `(bind, 0)` 临时端口，A 角色 `peer=None` 从首包学习对端 | `b2_fixed_tensor_demo.py` **L47** `bind=(args.bind,args.server_port) if args.role=='A' else (args.bind,0)`；**L48** `peer=None if args.role=='A' else …` | 即使打印 `PASS`，**回程 DATA 与部分 ACK 走临时端口**，不是双端 47001；不能证明业务 ACK 走同一被测路径 |
