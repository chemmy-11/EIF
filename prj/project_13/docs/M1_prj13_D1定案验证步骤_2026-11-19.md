# D1 定案验证步骤（新位流上板后执行）

> 前置：B 版精简位流（ILA7 21bit + 已跳 ILA4）构建通过，**ltx = 5 核（ILA0/3/5/6/7，无 ILA4）**。

## 1. 交付与烧录

1. PC1 把位流放 HTTP：`http://10.194.22.147:8765/p13_B3/<sha>.bit` + `probes.ltx`
2. PC2 取件 → 核 SHA（PC1 给值）→ `scripts/burn_p13.ps1` 烧 → 串口 `d` → 回 `PC2-B3-READY`
3. 核对：Vivado 自报 **5 个 ILA 核**（不是 6 个）；`now=DMA`；LinkSpeed 1 Gbps

## 2. 抓取（决定性）

PC1 发帧，PC2 抓；或反之。关键是**帧正在通过时**抓：

```powershell
# 抓取（PC2 侧，用新 ltx）
set argv [list localhost:3121 210512180081 <out.csv> <new probes.ltx> dbg_stack_takeover none]
source D:/FPGA/prj/project_13/scripts/ila_capture_any.tcl
```

同时 PC1 发 3 帧（`--pair A --dst-ip 10.10.0.2 --dst-port 47001 --count 3 --len 100 --run-id 0x9`）。

> **注意**：ILA 深度 1024 @ gmii_rx_clk ≈ 6.8 µs 窗口，自由运行抓不到 ms 级稀疏帧。
> 必须**边沿触发**：`set_property TRIGGER_COMPARE_VALUE eq1'b1 [get_hw_probes dbg_pump_rev_en]`
> （正确写法是 `eq1'b1`；`eq1` / `1'b1` / `1'h1` 均被拒）。

## 3. 判读表

| `stack_takeover` | `pump_rev_en` | `rgmii_tx_en_o` | 结论 |
|---|---|---|---|
| **1（常高）** | 有脉冲 | 0（被压住） | **D1 定案 = mux 接管锁存卡死** → 修 `stack_takeover` 释放条件 |
| 0 | 有脉冲 | 有脉冲 | mux 正常 → 问题在更下游（RGMII/GMII 转换或 PHY） |
| 0 | **无脉冲** | 0 | 泵 B 读侧停摆 → 查 `prev_rd` 是否增长、pump 读复位 |

## 4. 修复方向（按结论）

- **锁存卡死**：`stack_takeover` 现只在 `stack_tx_en` 下降沿释放（`:1418`）。
  加固建议：加超时释放（例如 `stack_tx_en` 连续 N 拍为低则强制清 0），或用 `tx_idle_cnt` 做二次兜底。
- **mux 正常但无输出**：查 `gmii_to_rgmii` 的 TX 方向与 `gmii_tx_clk`。
- **泵 B 读侧停摆**：查 `frame_fifo_pump` 的 `rd_rst_n`（= `~aurora_rst`）与 `rd_clk`（= `gmii_rx_clk`）。
