## 0. 角色映射（本窗口专用，勿与物理标签混淆）

| 软角色 | 位流 | BOARD_IP / MAC | 部署到 | 对应 PC |
|---|---|---|---|---|
| **A** | `out/b_p2_A_3a8b6300_b30c3903/aurora_mem_bridge_p2_3a8b6300.bit` + `probes_p2_b30c3903.ltx` | `10.10.0.11` / `02-00-00-00-0a-01` | **PC1 侧那块板**（物理单元 B） | PC1 `10.10.0.1` |
| **B** | 今晚构建（`out/p13_B_<sha>/`） | `10.10.0.12` / `02-00-00-00-0b-01` | **PC2 侧那块板**（物理单元 A） | PC2 `10.10.0.2` |

**为什么换角色而不是改参数**：两板同型号同器件（`xcku060-ffva1156-2-i`，JTAG 序列号同为 `210512180081`），
可互换；换角色只换烧录件，零 RTL 改动、零重建。若按物理标签部署则 PC1 会得到
「local .1 + board .12」这种 preset 不存在的组合，且 `PC_IP/PEER_IP` 反向。

## 1. 前置（缺一项不开工）

| # | 项 | 判定 | 谁 |
|---|---|---|---|
| P1 | 两板网络 profile | PC1 `10.10.0.1/24`、PC2 `10.10.0.2/24` | 负责人（管理员） |
| P2 | 静态 ARP（**每侧两条**） | `Get-NetNeighbor -IPAddress 10.10.0.11`（PC2 侧查 .12）显示 `Permanent` | 负责人（管理员），用 `pc/static_arp.ps1` |
| P3 | 两板网口 1 Gbps | `Get-NetAdapter` LinkSpeed = `1 Gbps` | PC1/PC2 自查 |
| P4 | 位流成对 | A 版 bit+`probes_p2_b30c3903.ltx`；B 版 bit+`scripts/probes.ltx`；**禁止混用** | PC1 |
| P5 | 实现时序门 | `WNS>=0 && WHS>=0` 才允许写位流（`build_impl.tcl` 不满足 `exit 2`） | PC1 |
| P6 | 串口 | 两板 `d` 后 banner 末条 `DMAMODE now=DMA`（`d` 是**翻转**命令） | 各侧 |

静态 ARP 必须两条（`pc/README.md` §1）：
- PC1（pair A）：`10.10.0.11 → 0a:01`（板 mgmt）+ `10.10.0.2 → 0a:01`（对端 PC，代理 ARP 形态）
- PC2（pair B）：`10.10.0.12 → 0b:01` + `10.10.0.1 → 0b:01`

> 只绑板 mgmt 一条不够：PC1 发给 `10.10.0.2` 的帧，**以太网目的 MAC 必须是本侧板 MAC**，否则走 ARP 广播、板卡应答跨光回不来。

## 2. 执行步骤

| 步 | 动作 | 命令/判据 |
|---|---|---|
| T0 | 认板 | `scripts/list_targets.tcl`：只看到一条 `210512180081`；**禁 `-Board Both`** |
| T1 | 烧软角色 A → PC1 侧板 | 单板烧 bit + ELF；`BURN_OK`；串口 `d` → `now=DMA` |
| T2 | 烧软角色 B → PC2 侧板 | 同上（PC2 执行）；`BURN_OK`；`d` → `now=DMA` |
| T3 | 链路 | 两侧 ILA：`ch_up=1 lane_up=1 gt_pll_lock=1 link_ok=1 aurora_rst=0 hard/soft=0` |
| T4 | **两向 3 帧门** | PC1：`twin_send.py --dst-ip 10.10.0.2 --port 47001 --count 3 --len 100 --run-id 0x1`；PC2 反收 → `matched=3`。反向同理（PC2 发 `.1`，run-id `0x2`） |
| T5 | **判据 1：IP 包逐字节不变** | 两向；pcap 字节级 `cap == IP.len + 14`，payload 自校验 `fill[i]=(seq+12+i)&0xFF`；`twin_recv.py --expect-count/--expect-len/--expect-run-id --no-bcast` 全 matched |
| T6 | **判据 3：ARP 不跨板** | 对端 pcap 上 **零 ARP 帧**（`arp` 计数 = 0），且抓包过滤 `ether src <对端板 MAC>` 下 arp 为 0 |
| T7 | **判据 4：无乒乓** | 两侧发 `--dst-ip 8.8.8.8` ×3 → **线上零帧**、本侧 `dbg_pfwd_wr` 不动 |
| T8 | **连续 ≥180 s** | 单次连续窗口，**禁分块循环**；固定时钟槽：T0 两侧同时开抓，T0+30 s 发包，抓满 ≥180 s；两向各一轮 |
| T9 | 吞吐 | 见 §4 |

顺序要求：**先正向后负例**（T5 → T7），每类用独立 `run_id` 便于计数差分。

## 3. 判据与今晚范围（不得外推）

| # | 判据 | 今晚 | 说明 |
|---|---|---|---|
| 1 | IP 包逐字节不变 | ✅ 可测 | 字节级 `cap == IP.len + 14` + payload 自校验 |
| 2 | 各类 DROP 分别计数（VLAN/IPv6/广播/组播/未知 dst/超长/坏 csum/截断/MAC，11 类） | ❌ **NOT_TESTED** | A 版 `3a8b6300` 与 B 版今晚新建**均无 DROP 探针**；只能旁证"该丢的没上线路" |

| 4 | 无乒乓 | ✅ 可测 | `8.8.8.8` 零帧 + `pfwd_wr` 不动 |

**表述约束**：
- 今晚 V4 只能写「**功能三项通过 / DROP 计数未测（无探针）**」，**不得**写「V4 四项全过」或「V4 通过」。
- 未测写 `NOT_TESTED`；未闭环不写 `PASS`。

## 4. 吞吐（iperf 待验证）

1. **基线（必做）**：`twin_send.py --interval-ms 0` 按 `pc/README.md` §3 `--bench --bench-target board` 打板，
   记录「帧长 vs 帧率 vs 实际 Mbps」；这是 L2/L3 证据。
2. **10 MiB 批量**：`--count 7124 --len 1472 --interval-ms 0 --run-id 0x10`，pcap 字节级判 `cap == IP.len + 14`。
3. **真 iperf（尝试）**：`iperf3 -s` / `iperf3 -u -c 10.10.0.2 -b <rate> -t 10`。
   - 本设计是自定义 UDP 桥，**能否透传 iperf 任意 UDP 负载未实测**；
   - 跑通 → 补一列真 iperf 数字；跑不通 → 记 `NOT_TESTED` 并写明原因（帧格式/长度/端口）；
   - **禁止**用 iperf 数字反推桥的吞吐上界。

## 5. 风险与处置

| 风险 | 处置 |
|---|---|
| 板 B 无规律复位（#15）未闭环，180 s 窗口可能被打断 | 先做短窗口判据确认稳定；打断则该轮作废重跑，不降级为分块 |
| PC 网口自降 100 Mbps（本机 19:00 实测已是 100 Mbps） | 烧位流复位 PHY；仍 100M 则管理员钉 `*SpeedDuplex=6` |
| 实现时序不过 | 换 `P12_PLACE_DIRECTIVE=ExtraPostPlacementOpt` 重掷；先看 `out/rpt_impl_*.rpt` |
| 两板同 JTAG 序列号 | 一次只烧一块；靠网口/HW target 区分 |
| `d` 翻转导致"发送成功但不进板" | 每轮上电/重烧后必须 `serial_dma_mode.ps1` 确认 `now=DMA` |
