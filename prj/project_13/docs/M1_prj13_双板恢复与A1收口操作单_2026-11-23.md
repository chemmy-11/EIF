## 3. P0｜保留现场，确认双向通路

1. 双端串口用 `U` 读回目标固件 ID、状态和 `mode`。链路就绪后读取两轮，间隔约 5 秒。每轮两端 VIO `ui_rst_n/calib/armed=1`、`down=0`，ILA6 `dbg_ch_up/dbg_lane_up/dbg_link_ok=1`、`dbg_aurora_rst=0`，期间无新增 `dbg_hard_err_cnt/dbg_soft_err_cnt/dbg_ch_up_evt`，串口 `mode=1`。保留 sticky 初值及变化。当前已加载设计若丢失、链路未就绪或无目标串口，应留证后执行 §4。
2. 每个发送方向前两端各开业务口 pcap，接收端同时开绑定本机业务 IP:47001 的记录器。报 `PCAP_READY`、`UDP_READY`，再通知对端发包。每向先发 3×100 B 探针，再发独立的 20×100 B。限 20 ms 间隔，串行跑两个方向。可预留 PC1 `0xA25C`、PC2 `0xB255` 给第一次三帧，后续每个阶段另分配未使用的 run ID。事件后用新 ID、新时间窗。
3. 逐轮按 [A1 操作单 §3–4](M1_prj13_A1操作单_2026-11-22.md#3-正常传输操作) 抓包及字节对账。业务口见发送和接收原帧，接收端 3/3 或 20/20，源/目的 MAC 和 IP、序号、长度、全 payload、净 SHA 一致，未见旧 run 残留帧、截断或重复。对账窗口内检查全部从本板 MAC 到 47001 的业务帧，避免同轮过滤漏掉旧帧。板侧配对推进并同窗归档。三帧失败先留证，暂停该方向的 20 帧及后续测试。双方 20/20 达标即恢复基线，可进入 §6 的 W2 维护试验或先收证。

~~~powershell
$Vivado = 'D:\Xilinx\Vivado\2023.1\bin\vivado.bat'
& $Vivado -mode batch -source scripts/read_link_health.tcl -tclargs $HwUrl $Cable $Ltx $Role
# 先为 $IlaCsv 分配本板、本轮、采样前或采样后的唯一文件名。
& $Vivado -mode batch -source scripts/ila_capture_any.tcl -tclargs $HwUrl $Cable $IlaCsv $Ltx dbg_pfwd_wr

# 以下变量按发送端填写。$Count 先 3，后 20；$RunId 每次换新。
py -3 pc/twin_send.py --scheme handbook --pair $Role --src-ip $SelfIP --dst-ip $PeerIP `
  --dst-port 47001 --count $Count --len 100 --run-id $RunId --interval-ms 20
if ($LASTEXITCODE -ne 0) { throw "Send failed for $RunId" }
~~~

VIO 输出依次是 `ui_rst_n calib armed down sticky`。ILA6 的原始 `channel_up` 表示 IP 完成建链。通路最终就绪以双向有编号的实际收包和对账为准。当前位流使用 Vivado 2023.1、KU060、双工 Aurora 64B/66B v12.0。下节是本工程准备验证的恢复流程。[AMD PG074 状态端口](https://docs.amd.com/r/12.0-English/pg074-aurora-64b66b/Status-Control-and-Transceiver-Ports?contentId=_79KOuCmmqjMME3grEXDHQ)

## 4. P0 失败时｜断纤隔离后配对恢复

1. **先留原始断点。** 保存同轮双端 pcap、串口和 §5 的前/后读数、sticky 及最后一条命令，停止业务发送。若因 W2 复测从健康态进入此流程，先完成 §6 的事件记录。
2. **隔离。** 现场拔开对应 SFPA 光纤的双向路径，确认两端失去对端。目标设计还有响应时，记录 VIO `down=1`，并在可采样时记录 ILA6 `dbg_ch_up/dbg_link_ok=0`。配置丢失或 ILA 时钟停转的端记 `UNKNOWN`，记录实际断开的路径和对端可用读数。两端确认物理隔离才开始烧录。
3. **逐板烧录。** PC2 的软 B 先、PC1 的软 A 后，保持光纤隔离至双方都见 `BURN_OK`。两端分别使用自身 bit / JTAG / 同一 ELF，坏目标或缺 `BURN_OK` 立即停在本步。选用 [burn_one.tcl](../scripts/burn_one.tcl)，让串口 DMA 模式核对放在统一建链后。
4. **统一复链。** 两端都交接烧录完成后，仅复插一次。两端按 §3 读链路及 UART `U`。如确认 `mode=0`，相应端用终端在已验证的串口设置下发一次 `d`，见 `now=DMA` 后再用 `U` 确认 `mode=1`。已有 `mode=1` 就继续。达到两次可读的链路、校准、DMA 判据后，按 §3 用新 ID 重做双向 3 帧再双向 20 帧。
5. **当天裁决。** 一次通过记录 `need_reburn=Y` 和该顺序的人工恢复样本，另记是否发生过真实掉电。失败则停流，按下表保留证据并登记 `FAIL` 或因前置条件不足的 `BLOCKED`。本窗口最多做一次受控隔离恢复并收证，避免交替热烧改变待查状态。是否需要设计修改，由首断点、复现条件和 A1 的恢复要求共同决定。

~~~powershell
$Xsct = 'D:\Xilinx\Vitis\2023.1\bin\xsct.bat'
$BurnLog = Join-Path $RunRoot ("burn_isolated_{0}_{1}.log" -f $Role,(Get-Date -Format 'HHmmss'))
$BurnOutput = & $Xsct scripts/burn_one.tcl $HwUrl $Bit $Elf $Cable 2>&1
$BurnExit = $LASTEXITCODE
$BurnOutput | Tee-Object -FilePath $BurnLog
if ($BurnExit -ne 0 -or -not ($BurnOutput -match 'BURN_OK')) {
    throw "Isolated burn failed for $Role. Keep the fiber disconnected."
}
~~~

## 5. 首断点取证表

两侧先收 ILA6 完整前/后 CSV，使用相同 run ID。必要时在同一状态下开一个新的有编号小批补 ILA3/0/5/7。16 位计数只在同一未复位区间内做模差，前后读数夹住该批，确认无背景干扰或回卷歧义。

| 当前 run 的首个异常 | 下一读数与归因范围 |
| --- | --- |
| 发端 `pfwd_wr` 不增 | 先看发端 Npcap 业务帧、GE1、MAC/ARP 和板侧入口。业务帧真实到本板但无法区分入口分类时，再在独立窗口用对应角色的 ingress 计数。 |
| 发端 `pfwd_wr` 增、`pk_frames` 不增 | 发端 ILA3 `dbg_mem_wr_frm / dbg_mem_rd_frm`，ILA0 `dbg_mem_u_wr / dbg_mem_u_rd`，必要时 ILA5 `dbg_s2mm_state` 和 UART `U/W`。定位到忙卡住或写读缺失后，分别用 `dbg_pfwd_stuck_cnt` 或 `dbg_pk_ovf_cnt` 验证具体假设。 |
| 发端 `pk_frames` 增、收端 `up_frames` 不增 | 对齐两端 ILA6 链路和错误计数，查 Aurora TX 到 RX 解包边界。 |
| 收端 `up_frames` 增、`prev_wr` 不增 | 收端 ILA0 `dbg_mem2_u_wr / dbg_mem2_u_rd` 和 ILA3 `dbg_mem2_wr_frm / dbg_mem2_rd_frm` 区分 Aurora RX 到 mem2 写入、提交、读出及反向泵。 |
| 收端 `prev_wr` 增、`prev_rd` 或主机包缺失 | 收端 ILA7 `dbg_prev_rd`、RGMII TX、出口接管及主机 pcap/UDP 接收。 |

本项目 `link_ok` 来自 `channel_up`，`aurora_rst` 随之变化，UI 域另有同步复位副本。若复现，先对齐这些读数、MIG 和 FIFO/槽表状态。一次热重烧前后的两段异常足以划定取证范围，尚不足以确认共因。[顶层复位与桥实例](../rtl/aurora_mem_bridge.v#L248) · [帧存储接口](../rtl/frame_mem_if.v)

## 6. 后续窗口门槛与 A1-6 取证

- **A1-5 W2 优先。** P0 通过且仍有独立维护时间时，双端留正常对照，由现场执行约定的 PC1 受控掉电。记录事件时间、PC2 的掉链/sticky、PC1 上电后目标设计及固件读回，再用 §4 成对恢复并同一事件下复跑双向 20×100 B。双向 20/20 可签本次人工掉电恢复的小批证据，旧 W2 的 A→B 状态保留。短批通过后按验收指南 §4 和原 A1 操作单复跑 A1-1～A1-4，交接报告区分正常态与恢复后的结果。只做隔离重烧则记人工配置恢复。W1 的自主恢复失败继续列为已知边界。
- **入口缓冲溢满。** 本地现象为注入越过出口边界时 `st_rx_drop` 仍为 0。当前 ingress 下游 `m_ready(1'b1)`，拔纤会使 `eth_rst_n` 进入复位，备选的“断纤后洪泛”会改变被测对象。先在独立离线窗口运行 `powershell -NoProfile -File sim/p2/run_p2_sim.ps1 -Only framebuf`，要求 `P2_FRAMEBUF_TB: PASS≥5, FAIL=0`，保留双 bank 满时第三帧完整丢弃的结果。实板需要能证明帧真正到板和入口缓冲达到满条件的短用例，逐类读计数并恢复到一帧正常通过。现场无法达到该条件时保持 `BLOCKED`，之后可在独立诊断夹具对实际的消费端做受控短暂停顿。[入口连接](../rtl/p2/p2_relay_top.v#L143) · [测试平台](../sim/p2/tb_p2_frame_buf.v)
- **板侧等待超时。** 如在正常小批出现停摆，先保留 ILA5 状态、GO/ready、ILA0 `dbg_wr_fault` 和 UART `U/W`；PC socket 超时单独记。D-fix 未导出 `mem_stat_wr_timeout`。后备观测软 A 的规格是保留有效入口分类，在 `user_clk` 观测 `dbg_pk_ovf_cnt/dbg_pfwd_stuck_cnt`，在 `ui_clk` 观测 `u_mem` 的等待超时计数或事件及 `dbg_s2mm_state`。现行 A1 要求能区分超时和其他故障。聚合计数加同窗 FSM 取证即可判断用途，按阶段新增多个计数器留到有具体复现之后。[交付仓 A1 #14](https://github.com/chemmy-11/GSnFPipe-FPGA-PP/issues/14)
- **观测件的使用门槛。** 11 月 23 日 ILA8 把 `p2_st_aur_drop/p2_st_aur_bad_v4` 接到 `gmii_rx_clk` 核，源实际在 Aurora `user_clk` 域。沿用软 A 已取得的同域入口证据。新件先核每个探针的域、WNS/WHS、匹配 bit/ltx 与全哈希，再放独立诊断窗口，结束回到成对 D-fix 并复验。G5/V4 要按完整分类读数另核对双角色，复制旧 ILA8 无法覆盖全部分类。[AMD UG908 2023.1 ILA 时钟要求](https://docs.amd.com/r/2023.1-English/ug908-vivado-programming-debugging/ILA-Core-and-Timing-Considerations) · [A2 观测条件](M1_prj13_A2操作单_2026-11-22.md#1-放行与任务边界)
- **构建安排。** 软 A 诊断备件单独排在 11 月 24 日 02:00（北京时间）离线构建。结果和验收独立于本操作单的 P0。没有新件时直接执行 §2–5。

## 7. 回填与下一阶段

PC1 汇总，PC2 回填自己的原始记录并复核每个接收方向。预计先留 15 分钟做认件和小批，隔离恢复或 W2 的短批另留约 20–30 分钟，W2 后复跑完整矩阵需要另排时间。无两端协作或收窗提前时，优先交付已完成的 P0 或第一个实测断点。

每行记录 `用例、时间及事件、方向、run_id、bit/ltx/ELF SHA256、两端 UART/VIO/ILA/pcap、精确对账、PASS/FAIL/BLOCKED/NOT_TESTED、need_reburn`。归档沿原 A1 操作单的报告、CSV 和清单，旧资料按运行原样保留。A1-5/W2 未补齐、A1-6 未达到可区分错误的证据要求或受限运行范围未经交付签收时，A1 继续未签收。A1 签收后按 [A2 操作单](M1_prj13_A2操作单_2026-11-22.md) 核对 G4/G5 和 J0 用于本轮的协议冻结输入。D2-stack 随 V4，D3 的突发后停摆单独留账。A3 的真实吞吐上界另开窗口。
