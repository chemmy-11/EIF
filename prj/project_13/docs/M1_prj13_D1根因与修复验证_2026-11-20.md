## 一、D1 是什么

P2 双板透传的前向通路（PC1 → 板 A → Aurora → 板 B → PC2）在板间段是通的，但**转发帧到不了对端 PC**：

| 观测 | 值 |
|---|---|
| 板侧 `up_frames` / `prev_wr` | 与发送侧 `wr`/`rd` 三方对平（23=23=23；后 6639=6639） |
| `rgmii_tx_en_o` | 高 **142** 拍（发流瞬间实测） |
| 对端 pcap | **0 帧**来自板 MAC |
| 对端网卡 | `ReceivedUnicastPackets=0`、`PacketErrors=0`、`Discarded=0`（静默丢弃） |

---

## 二、根因（三条缺陷）

### 缺陷 1：缺前导码/SFD（8 B）

`rtl/p2/eth_rewrap.v` 输出从目的 MAC 起始，**不产生 `7×0x55 + 0xD5`**。

### 缺陷 2：缺 FCS（4 B）

`rtl/p2/eth_rewrap.v` 全文 216 行，**只有 1 处提到 FCS**（`MIN_FRAME_LEN` 的参数注释），**没有任何 CRC 生成**。

全 RTL 检索 `crc|fcs`：仅命中 `rtl/arp/crc32_d8.v` 与 `rtl/icmp/`（栈模块自用）⇒ 透传路径零 CRC 单元。

### 缺陷 3：出口 dst MAC 用错参数

`eth_rewrap.DST_MAC` 接的是 `PEER_MAC`（**对端** PC 的网卡）。
但出口帧是发给**本板直连 PC** 的 ⇒ 应为 `PC_MAC`（**本板**直连 PC 的网卡）。

### 为什么这三条能解释全部观测

- 无 FCS 的帧被接收端 NIC 按 **CRC 错误静默丢弃** —— 网卡不报错、不计数
- 数据内容本身正确（所以人工看波形"像对的"）
- 栈帧能上线（`arp`/`icmp` 走 `crc32_d8` 自己算 FCS）——**控制变量实验**：
  同板同时段，栈帧上线、转发帧不上线，唯一差别就是有没有 FCS

## 三、修复（commit `cbfd304`）

| # | 改动 | 文件 |
|---|---|---|
| 1 | 新增 `S_PRE` 状态，输出 `7×0x55 + 0xD5`（8 B），**不参与 CRC** | `rtl/p2/eth_rewrap.v` |
| 2 | 新增 `S_FCS` 状态，输出 4 B FCS；CRC **只覆盖 MAC 头 + IP + 填充** | 同上 |
| 3 | 新增 `parameter PC_MAC`，`eth_rewrap.DST_MAC` 改接它 | `rtl/p2/p2_relay_top.v`、`rtl/aurora_mem_bridge.v` |
| 4 | `u_ila_7` 新增 `rgmii_txd_o[7:0]`（21 → 29 bit） | `rtl/aurora_mem_bridge.v`、`scripts/build_synth_only.tcl` |

```verilog
assign m_frame_len = tot_len + 16'd12;                              // +8 前导 +4 FCS
wire crc_en_w = out_ace && (state != S_FCS) && (state != S_PRE);    // CRC 只覆盖 MAC+IP+填充
assign m_eop  = (state == S_FCS) && (fcs_idx == 2'd3);              // EOP 移到 FCS 末拍
```

### FCS 取字节配方（仿真验证，非猜测）

```
fcs_b0 = ~crc_data[24..31]   fcs_b1 = ~crc_data[16..23]
fcs_b2 = ~crc_data[8..15]    fcs_b3 = ~crc_data[0..7]
```

与板上已验证的 `rtl/arp/arp_tx.v:290-303` 同构（它用 `crc_next` 补偿一拍延迟）。

## 七、口径澄清（两层不可混）

| 层 | 长度 | 内容 |
|---|---|---|
| **pcap（Npcap）** | **142** | 14 以太头 + 20 IP + 8 UDP + 100 payload（**不含前导/FCS**） |
| **GMII / `tx_en`** | **154** | 142 + 8 前导 + 4 FCS |

判据应写「**pcap cap = IP.len + 14 = 142**」；`154` 属 GMII 口径。
