## 1. 当前结论与决策

**已确认停摆边界，具体卡点待测。** A 侧在链路恢复后仍出现 `pfwd_wr=3 / pk_frames=0`，首个失步点位于前向帧泵写入后、完成打包前。归档缺少同轮的 `u_ila_3` 和 `u_ila_0`，无法继续区分泵读出、DDR 提交、桥读出及 pack。23:08 在位重烧 A 后 `pk_frames` 恢复到 3，这只签收 A 侧打包计数。

恢复条件目前只有单次观测。光纤在位时重烧 A 曾恢复打包，断纤重烧再插回曾失败。可重复的恢复序列、是否必须整板重配置及端到端恢复均为 `NOT_TESTED`。 [任务书](../../../docs/任务书_prj13前向停摆根因定位_2026-11-20.md) · [V4 §11.3–11.4](M1_prj13_V4执行报告_2026-11-19.md:301)

### 窗口申请和分工

### 顺序与有效性

1. **预检。** 停两侧业务流量，按 V4 核对 NIC、静态 ARP 和软角色。B 若需重烧，在首个有效臂之前完成。记录 JTAG 序号和 COM。PC1 历史值为 `210512180081 / COM5`，PC2 现场确认。烧录前关闭 Vivado 抓取会话。
2. **E1/E2 各三次，交替执行。** 每次重新加载同一 A bit 和 ELF。E1 断纤加载，留存断纤态和插纤时刻；E2 保持光纤在位，记重新起链。两臂都用 `burn_one.tcl` 加载，再在 `ch_up=1 / aurora_rst=0` 后用 `serial_dma_mode.ps1` 确认 `now=DMA`。记录烧录、插纤、起链、校准、`d`、串口回执及首帧时间。历史两轮的 `d` 时机未知。若两臂都通，原失败未复现，优先核查历史 DMA 置位顺序。若任一臂无法置 DMA，则记控制面结果，不混入有效数据面对照。
3. **每次只发一组 3 帧。** 发前保存 A 的 `u_ila_0/3/6` 和 B 的 `u_ila_6`，发后停流并串行抓同组计数。PC2 在发送前确认 pcap 已开。用同一上电纪元的前后增量对账。发现二次掉链、混入业务帧、计数无法归属或漏抓，标记无效并补测。故障现场先收证，再用 `d`、软核下载或整板恢复干预。
4. **E3/E4 仅在 E1 稳定复现后执行，各至少一次。** E3 独立断纤启动，重连后不发帧等 10 s 再发，记录从链路回升到首帧的实测时间。若 E1 的取基线及置位也已超过 10 s，则在 E1 相同流程上额外等 10 s，并按这个增量报告。E4 在独立 E1 失败样本上先抓取，再做 `stop → dow 同一 ELF → con`，重新确认 `now=DMA` 并发 3 帧。XSCT 按线缆选 A，核对 MicroBlaze target，沿用 `burn_one.tcl` 的目标选择。E4 只重载软核。若出现首批滞留帧或重复，分别记录前向恢复与数据验收结果。
5. **收尾。** 若 3+3 未成组，优先补有效对照。若仍须区分历史运行中掉链与断纤冷启动，在 A 本地已验通的条件下，后续做一次只拔插、不重烧 A/B 的对照，抓掉链前、复插后、试探帧后三组。该项当前标 `NOT_TESTED`。

## 4. 实测判读与改动门槛

先核对 `dbg_calib=1`、链路稳定和本轮 `Δpfwd_wr=3`。未满足者分别记校准、链路或注入失败。满足后从第一处计数失步开始。

| 同轮读数 | 可确定的停点 | 后续取证 |
| --- | --- | --- |
| `Δmem_wr_frm=0`，`Δmem_u_wr=0` | 泵读出至 `frame_mem_if` 用户域接纳之间。 | `Δmem_u_drop>0` 时有桥侧丢弃。后续受控发帧时触发 `dbg_pfwd_en`，区分泵未送出和桥未接纳。静态 `dbg_pfwd_en=0` 不能排除早前读出。 |
| `Δmem_wr_frm=0`，`Δmem_u_wr=3` | `u_mem` 用户域接纳后至 S2MM 写提交之间。 | 用 `u_ila_3` 看写 FSM、`tvalid/tready`，用 `u_ila_5` 补 GO/ACK/中断和尾拍。`WD_WAITGO=1` 查 GO 和水位，`WD_WAITDONE=4` 查完成中断，`WD_HALT=6` 查进入 HALT 前的握手。拍到 HALT 可判定停泊状态，区分超时路径仍需波形。 |
| `Δmem_wr_frm=3`，`Δmem_rd_frm=0` | DDR 写已提交，停在桥读请求至读完成之间。 | 对账 UI outstanding、user 镜像和读输出。配套 LTX 缺少 `mem_rd_req`、命令 FIFO 状态和读 FSM 的直接探针。若现有读数仍有歧义，将缺失信号列为后续观测项。 |
| `Δmem_rd_frm>0`，`Δpk_frames=0` | 桥读完成到 pack 完成之间。 | 对比 `Δmem_u_rd`、`dbg_mem_rden_1` 和 `mem_rd_data`，区分返回路径与 pack 输入。 |
| A `Δmem_rd_frm=3 / Δpk_frames=3`，B `Δup_frames=0` | A pack 到 B 解包之间。 | 同轮核对两侧链路，再查 TX/RX 握手。若 B 已解包但 PC2 数据验收失败，另记 B 后段问题。 |
| `Δmem_len_err` 或 `Δmem_stall` 增长，或 `mem_ost` 接近 256 | 帧长异常、槽拒收或占用异常，可与上述任一停点并行出现。 | 分开记长度错和停顿，对账提交、清槽与 outstanding 镜像。读到高占用只说明压力。若要证明槽泄漏，须抓到与写入、读退休不相符的持续增量。 |

E2 的 A 侧通路通过要求本轮 `Δpfwd_wr / Δmem_wr_frm / Δmem_rd_frm / Δpk_frames` 均为 3。窗口结束时，按“原因 + 卡点”分别定级。直接拍到的单次卡点可写强证据，E1/E2 各 3 次分离可写启动条件关联可重复。触发到停点的状态演变有 RTL 与波形闭环后才写机制确定。A 内部恢复和端到端恢复分别记账。

**当前证据不足以支撑改动。** 若 E4 单独恢复，且现场波形或串口证实配置、S2MM 服务未就绪，下一轮先做固件初始化顺序对照。若实测锁到明确的 RTL 状态及触发，围绕该 FSM 或握手提出最小改动。若只定位到模块边界，下一轮只申请该边界缺失的证据。
