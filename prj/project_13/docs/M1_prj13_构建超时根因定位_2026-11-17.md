## 1. 结论摘要

| 问题 | 结论 |
|---|---|
| PC2 的时序数字（WNS −0.212 / TNS −3.819）是不是机器症状？ | **不是。** PC1 用**同一配方** `ExtraPostPlacementOpt` 复现出**完全相同的** −0.212 / −3.819（见 §3 Round B）。该数字是**配方决定的确定性输出**。 |
| 那 PC2 的 134 min 是什么？ | **环境**。同样的工作量在 PC1 上 `route_design` 只要 **13:05** 就走完 Phase 17→19，PC2 花 **>118 min** 仍停在 Phase 17.1.1 ⇒ **≥9 倍**。同源、同配方、同 Vivado 2023.1，唯一变量是机器。 |
| 配方本身有没有问题？ | **有。** `ExtraPostPlacementOpt` 对本设计是**更差的配方**：WNS −0.154、22 个失败端点，而 `ExtraTimingOpt` 是 −0.046、5 个失败端点。PC2 选的"重试配方"本身把路由器推进了难解区。 |
| 另外发现 | PC1 首次尝试即撞上 PITFALLS #61 的安装盘瞬时读失败（`unimacro_verilog.tcl` → `Mig 66-119`/`Opt 31-306`），**必须 TEMP 重定向 + 按日志文字重试**才能出片；`rc=0` 在此工程里对成功/失败都没有判据价值。 |

**判定**：`VERDICT = ENV`（墙钟差异）+ `TOOL/RECIPE`（配方向量选错）。**不是 DESIGN 收敛失败**——门限失败是配方/余量问题，不是"跑不完"。

## 3. 关键证据：PC2 的时序数字在 PC1 上逐字复现

PC2（#2 评论 `6944430015`）报告 17:10 停止时的中间时序：**WNS −0.212 / TNS −3.819 / WHS +0.004 / THS 0**，相位 `route Phase 17.1.1 Update Timing / Post Hold Fix`，配方 `ExtraPostPlacementOpt`。

PC1 Round B（同配方、同源、同器件）在 `Phase 18 Timing Verification` 打出的中间时序：

```
INFO: [Route 35-416] Intermediate Timing Summary | WNS=-0.212 | TNS=-3.819 | WHS=0.004  | THS=0.000  |
```

**四个数字全部逐字相同**。⇒ PC2 报的时序值是配方确定的确定性结果，**不能**作为"机器有问题"或"设计跑不完"的证据；它只能说明该配方把设计放在 −0.212 的位置起跑。

而同一份工作 PC1 只要 **13:05** 就完成整段 route（Phase 17→18→19），PC2 **>118 min** 未走完 ⇒ 差异在**墙钟/机器**，不在算法结果。

### 3.1 该机已有的同型前科（旁证，不是本轮定案）

`docs/M1_prj13_P2位流重建登记_2026-11-12.md:35-45`（`README.md:66` 标注为「组员机重建」）记录：

- 三次 run 中 **#1、#2 被主机睡眠打断**（`SetSuspendState` 19:46:46 / 01:17:38），**同样留 `rc=0` 而无完成标记**；
- **#3 的 `route_design` 跑 8h04m**，归因「同机并行负载（游戏占 8 GB / 5 核 → Vivado 压到 ~1 核）」。

本轮 PC2 的 `impl.log`（SHA256 `f5e5f1de…`）**未推送远端**，所以 11-17 当天究竟是负载、睡眠还是别的，**仍属未闭合**（见 §6）。

## 5. 门限失败的性质（不是"跑不完"，是余量薄）

A1（`ExtraTimingOpt`）的 5 个失败端点**全部是同一条路径族**：

| 项 | 值 |
|---|---|
| Slack | −0.046 ns |
| Source | `u_mem2/u_wr_bytes/wr_gray_s2_reg[10]/C` |
| Destination | `u_mem2/u_bridge/FSM_onehot_g_wr_hw.wst_reg[3]/CE`（及 wst[5]/[0]/[4]） |
| Path Group | `mmcm_clkout0`（300 MHz，period 3.333 ns） |
| Data Path Delay | 3.202 ns（logic 1.526 / route 1.676） |
| Logic Levels | **9**（CARRY8×3 + LUT2 + LUT4 + LUT6×4） |
| Clock Path Skew | −0.069 ns（DCD 3.946 / SCD 3.973 / CPR −0.041） |

⇒ 是**共享模块 `frame_mem_if` 的异步 FIFO 格雷码比较链**在 300 MHz 下的结构性临界路径，105 ps 余量（11-08 为 +0.015）被这版 RTL 吃掉了约 60 ps。**时钟偏斜只占 46 ps 中的 69 ps 量级，主因是 9 级逻辑**。

处置顺序按方案 §5.2（L186）：先换已验证的实现配方重跑（本次即 A1/B 对照），再考虑裁减非验收必需探针，最后才 DIAG_ONLY。**未改 RTL、未放宽任何约束或门限。**
