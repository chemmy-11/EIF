两端在 `D:\FPGA\prj\project_13` 下操作。把下列变量带到各自终端，PC2 换用上表本侧值。`$IfAlias` 填现场确认的别名，`$RunRoot` 用同一会话名、各自 PC 子目录。

~~~powershell
Set-Location D:\FPGA\prj\project_13
$env:PYTHONUTF8 = '1'
$Role = 'A'
$SelfIP = '10.10.0.1'
$PeerIP = '10.10.0.2'
$BoardMac = '02:00:00:00:0a:01'
$Nic = Get-NetAdapter -Name $IfAlias -ErrorAction Stop
$Guid = ([string]$Nic.InterfaceGuid).Trim('{}')
$NicMac = ($Nic.MacAddress -replace '-', ':').ToLower()
Get-NetIPAddress -InterfaceIndex $Nic.ifIndex -AddressFamily IPv4
Find-NetRoute -RemoteIPAddress $PeerIP -LocalIPAddress $SelfIP
py -3 pc/npcap_capture.py --list
powershell -NoProfile -File pc/static_arp.ps1 -Scheme handbook -BoardPcPair $Role -IfAlias $IfAlias -Apply
Get-NetNeighbor -InterfaceIndex $Nic.ifIndex -AddressFamily IPv4
New-Item -ItemType Directory -Path $RunRoot -ErrorAction Stop | Out-Null
~~~

确认本板管理 IP 和对端 PC IP 两条静态邻居都指向本板 MAC、状态 Permanent。放行 UDP 47001 时只改专用业务接口的实验规则。管理网络用于交换口令和证据。两端先停止占用业务口的测试程序。每轮接收端绑业务 IP:47001 并消费 UDP，避免系统为未监听端口回送 ICMP。可在单独终端执行以下接收记录器，设置相同的 `$SelfIP`、`$CaptureSeconds`、`$RunRoot`、`$Case` 和 `$RunId`。接收端也独立抓 pcap。

~~~powershell
@'
import socket
import sys
import time

host, seconds = sys.argv[1], float(sys.argv[2])
with socket.socket(socket.AF_INET, socket.SOCK_DGRAM) as sock:
    sock.bind((host, 47001))
    sock.settimeout(0.5)
    count = 0
    deadline = time.monotonic() + seconds
    print("UDP_READY", sock.getsockname(), flush=True)
    while time.monotonic() < deadline:
        try:
            sock.recvfrom(65535)
            count += 1
        except TimeoutError:
            continue
    print("UDP_RECEIVED", count)
'@ | py -3 - $SelfIP $CaptureSeconds | Tee-Object -FilePath (Join-Path $RunRoot ("socket_{0}_{1}.log" -f $Case,$RunId))
~~~

若已加载且能核对当前工件，先保留现场。需要加载时，先用 `Get-FileHash -LiteralPath $Bit,$Ltx,$Elf -Algorithm SHA256` 对齐全哈希，确认没有并行 Vivado 构建，再逐板执行 [burn_p13.ps1](../scripts/burn_p13.ps1)，显式传本机实测的 `-Bit -Elf -Cable -Com -Url`。保留 `BURN_OK` 和最后的 `now=DMA`。待两板均上线，再复核 DMA 状态。`d` 是翻转命令，按最后一条串口回显确认。

使用 Vivado 2023.1 和匹配 ltx，通过 [read_link_health.tcl](../scripts/read_link_health.tcl) 读取 `ui_rst_n/calib/armed/down/sticky`。下例中的 `$HwUrl/$Cable/$Com/$Bit/$Ltx/$Elf` 均用本端已核对的值。链路、MIG 校准和 DMA 就绪后，再做双向三帧。历史 sticky=1 时保留基线并对齐事件时间，新增掉链或计数复位即停止该轮。JTAG 访问和主动干扰按现场顺序逐板执行。

~~~powershell
# 仅需要重载时执行 burn_p13。
powershell -NoProfile -File scripts/burn_p13.ps1 -Bit $Bit -Elf $Elf -Cable $Cable -Com $Com -Url $HwUrl
vivado -mode batch -source scripts/read_link_health.tcl -tclargs $HwUrl $Cable $Ltx $Role
vivado -mode batch -source scripts/ila_capture_any.tcl -tclargs $HwUrl $Cable $IlaCsv $Ltx dbg_pk_frames
~~~

`$IlaCsv` 每次用新文件名。计数快照直接采样，省略可选触发探针。接收方查末级时用实际 ltx 中的 `dbg_prev_rd` 选 ILA7。

## 3. 正常传输操作

每个方向、尺寸、轮次用独立 `run_id`（TWIN uint32，可写十六进制）。PC1 发、PC2 收为 A→B，PC2 发、PC1 收为 B→A。两端各抓本机业务口，收到 `UDP_READY` 和两端 `PCAP_READY` 后发包。抓包进程使用 `py -3 -u`，日志打印 `linktype: 1` 并确认 pcap 文件已创建后报告就绪。PC1 汇总两端时间和文件名，抓包必须包含首尾包及排空时间。

~~~powershell
# 先在两端抓包终端设置本轮参数。短轮用 180 s，连续数据轮先留 360 s。
$Cap = Join-Path $RunRoot ("{0}_{1}_{2}.pcap" -f $Case,$RunId,$Role)
if (Test-Path -LiteralPath $Cap) { throw "Evidence already exists: $Cap" }
py -3 -u pc/npcap_capture.py --iface $Guid --seconds $CaptureSeconds --out $Cap

# 发送端在另一终端使用同一 run ID。例：先 $Count=3，$PayloadLen=100，$IntervalMs=20。
py -3 pc/twin_send.py --scheme handbook --pair $Role --src-ip $SelfIP --dst-ip $PeerIP `
  --dst-port 47001 --count $Count --len $PayloadLen --run-id $RunId --interval-ms $IntervalMs
if ($LASTEXITCODE -ne 0) { throw "twin_send failed in $RunId" }
~~~

保存发端原始输出和实际发包时间。若常规 socket 发送失败，先查源地址绑定、路由、静态邻居和防火墙。确需隔离软件路由时，使用 [p2_rawsend.py](../pc/p2_rawsend.py) 指定本卡 GUID、本卡源 MAC、本板目的 MAC、本侧与对端 IP，每次都显式传正的 `--interval-ms`，诊断结果注明 RAW L2。

| 用例 | 设置和通过条件 |
| --- | --- |
| 开工基线 | 双向各跑 3×100 B 再分别跑 20×100 B，按接收端 pcap 和双边计数核对目的单播 MAC、序号、长度与全 payload。 |
| A1-1 多帧长 | 26/64/100/512/1024/1472 B 均指 UDP payload，按尺寸分轮，每方向每档 ≥20 帧。1472 B 时无选项 IPv4 总长 1500 B。逐档核对最短和最大帧。 |
| A1-2 连续数据 | 每方向各一个连续 run。先按低速小批确认健康，再用 `$Count=8827`、`$PayloadLen=1200`、`$IntervalMs=20`。12 B TWIN 头不计，净字节为 `8827×1188=10,486,476 B`，高于 `10 MiB=10,485,760 B`。0 丢失、0 重复、记录乱序，逐字节校验并对账净数据 SHA256。 |
| A1-3 多轮 | 每方向至少 5 轮，每轮 ≥20 帧。每轮单独编号并保留全部结果。 |
| A1-4 同时双向 | 两端先预约实际重叠发送时段，每向从 20×100 B、20 ms 间隔开始，分别用不同 run ID。依据两侧发送时间和 pcap 验证流量重叠与双向字节正确。交错和同时负载的观察分别记入报告。 |

以每个 case 独立窗口为准。若准备时间接近捕获窗口末尾，重开新窗口和新 ID。短轮中出现丢帧、CRC/字节异常或计数停滞，先收证和定位，暂停进入长轮。连续轮按实际发包跨度计时。

## 4. 接收对账

接收端先运行 [p1_judge.py](../scripts/p1_judge.py)，它按本侧板源 MAC、端口检查精确帧数、序号集合、TWIN 填充和长度。再检查真实目的 MAC、源/目的 IP、到达顺序和净数据 SHA256。下面的补充对账读取同一份 classic pcap，并生成逐帧 CSV。`$RecvCsv` 指向本轮新路径。脚本的 `span_s` 是接收首尾帧间隔，也可用于 A2 T8。

~~~powershell
py -3 scripts/p1_judge.py --from-pcap $Cap --board-mac $BoardMac --port 47001 --port-direction dport `
  --expect-count $Count --count-mode exact --expect-len $PayloadLen --expect-run-id $RunId --allow-dup 0 `
  --json-out (Join-Path $RunRoot ("{0}_{1}_judge.json" -f $Case,$RunId))
if ($LASTEXITCODE -ne 0) { throw "PCAP judge failed in $RunId" }

@'
import csv
import hashlib
import sys

sys.path.insert(0, "scripts")
sys.path.insert(0, "pc")
from p1_judge import check_twin, parse_frame, read_pcap
from twin_send import build_payload

pcap, csv_path, rid, count, length, local_ip, peer_ip, board_mac, pc_mac = sys.argv[1:]
rid, count, length = int(rid, 0), int(count), int(length)
frames, _ = read_pcap(pcap)
rows, sequences = [], []
received_hash, expected_hash = hashlib.sha256(), hashlib.sha256()
for stamp, raw in frames:
    frame = parse_frame(raw)
    ip, udp = frame["ip"], frame["udp"]
    if frame["src_mac"] != board_mac.lower() or not udp or udp["dport"] != 47001:
        continue
    payload = udp["payload"]
    twin = check_twin(payload)
    if not twin or twin["run_id"] != rid:
        continue
    seq = twin["seq"]
    valid = (twin["total"] == count and twin["fill_ok"] and len(payload) == length
             and not frame["vlan"] and not frame["frag"] and not ip["mflag"]
             and ip["ihl"] == 20 and ip["tot"] == length + 28 and udp["ulen"] == length + 8
             and len(raw) - frame["fcs"] == 14 + ip["tot"] and not udp["truncated"]
             and frame["dst_mac"] == pc_mac.lower() and ip["src"] == peer_ip and ip["dst"] == local_ip)
    rows.append((stamp, seq, frame["src_mac"], frame["dst_mac"], ip["tot"], len(raw), length - 12, valid))
    sequences.append(seq)
    received_hash.update(payload[12:])
for seq in range(count):
    expected_hash.update(build_payload(seq, count, rid, length)[12:])
with open(csv_path, "x", newline="", encoding="utf-8") as out:
    writer = csv.writer(out)
    writer.writerow(("time_s", "seq", "eth_src", "eth_dst", "ip_bytes", "cap_bytes", "application_bytes", "valid"))
    writer.writerows(rows)
missing = len(set(range(count)) - set(sequences))
duplicate = len(sequences) - len(set(sequences))
span = rows[-1][0] - rows[0][0] if len(rows) > 1 else 0
print(f"rx={len(rows)} missing={missing} duplicate={duplicate} span_s={span:.6f}")
print("rx_sha256", received_hash.hexdigest(), "expected_sha256", expected_hash.hexdigest())
ok = sequences == list(range(count)) and all(row[-1] for row in rows) and received_hash.digest() == expected_hash.digest()
sys.exit(0 if ok else 1)
'@ | py -3 - $Cap $RecvCsv $RunId $Count $PayloadLen $SelfIP $PeerIP $BoardMac $NicMac
if ($LASTEXITCODE -ne 0) { throw "Byte/order audit failed in $RunId" }
~~~

采集发送侧 `pfwd_wr → mem1 写读 → pk_frames`，接收侧 `up_frames → mem2 写读 → prev_wr/prev_rd`，使用匹配 ltx 的 ILA 实际探针。记录 before/after 及复位次数。在同一未复位的计数区间且可证明增量小于 65536 时，16 位计数差可按模 65536 计算。计数推进、到达数量与字节检查全部放在该 run 对账。报告同时记录发包 stdout、两端网卡丢弃和抓包异常。

## 5. 恢复与错误上报

| 用例 | 执行与判定 |
| --- | --- |
| A1-5 重启/闪断 | 正常测试结束后另开维护窗口。先保存基线和关键探针，由现场负责人按约定做受控重启或光链路闪断。先留掉链、复起、校准、DMA 和 sticky 原始值，保留重烧之前的数据探针证据。若仅重烧后恢复，明确记录 `need_reburn=Y`。完成既定重启/断电后的 Bit+ELF+DMA 恢复流程，按指南复跑完整数据用例，至少先验证双向各 20×100 B。在限定运行范围内未安排的故障条件保留 `NOT_TESTED`，遇到前置禁止时写 `BLOCKED`。 |
| A1-6 错误报告 | 按 [A2 的单类负例表](M1_prj13_A2操作单_2026-11-22.md#6-v4-连续性与负例) 借用已校验的有限输入。分开记录坏校验/非法帧、应用序号缺失、缓冲丢弃、配置丢失、等待超时的证据。每类保留触发前后计数、首个失步点和正常探针复验。D-fix 缺分类读数时保留 `BLOCKED`，可先跑同 RTL 仿真并准备观测版。出现停摆、校准失效或新 sticky 事件，先停发留 pcap、ILA、串口再按恢复策略处置。 |

D3 的历史洪泛用于复盘。本单按有间隔、有限帧数执行。现场恢复动作与试验数据各用独立编号，掉链后的证据按实际事件类型签收。板卡自恢复、人工重烧恢复、历史告警锁存各有独立判据。
