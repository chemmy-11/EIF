## 1. 前置（一次性，约 15 min）

```powershell
# 1) 认板（只插一条 JTAG 线；确认序列号与板号标签对应）
vivado -mode batch -source scripts\list_targets.tcl

# 2) 两 PC 改成 10.10.0.x（管理员）
Get-NetAdapter                                            # 记下数据网卡 Name / IfIndex
New-NetIPAddress -InterfaceAlias "<PC1 网卡>" -IPAddress 10.10.0.1 -PrefixLength 24
#   PC2: 10.10.0.2
netsh interface ipv4 delete neighbors "<PC1 网卡>" 10.10.0.2 2>$null
netsh interface ipv4 add neighbors "<PC1 网卡>" 10.10.0.2 02-00-00-00-0A-01

# 3) 网口必须 GE2、必须 Up/1 Gbps
Get-NetAdapter | ? Name -eq '<PC1 网卡>' | ft Status,LinkSpeed

# 4) 烧 BitElf（位流 + ELF 一起；注意用 prj13 的 Root 与 config）
powershell -NoProfile -ExecutionPolicy Bypass -File D:\FPGA\prj\project_12\out\twin_burn.ps1 `
    -Board A -Mode BitElf -Run `
    -Root D:\FPGA\prj\project_13 -Config D:\FPGA\prj\project_13\out\twin_config_13.json
#   期望：BURN_OK / BURN_ELF_DONE；哈希不符会拒绝烧（除非 -Force）

# 5) 串口进 DMA 写模式（每次上电/重烧后必做）
powershell -File scripts\serial_dma_mode.ps1 -Com COM6   # 串口号以实测为准：PC1=COM6 / PC2=COM5
#   期望：SERIAL_RESULT: PASS / now=DMA
```

> **易失性**：位流在 JTAG SRAM、ELF 在软核 RAM、`d` 在固件 RAM —— 断电/复位三者全丢，**每次上电都要重烧 BitElf + `d`**。
> `twin_burn.ps1` 只在 prj12 有（prj13 尚未复制），上面的 `-Root`/`-Config` 两个参数就是让它烧 **prj13 的 P2 位流**而不是 prj12 的 P1 基线对。**不传这两个参数就会烧到 P1 基线（`C856BA83`）** —— 这是最容易犯的错。

## 2. 档 1：**不接光纤** —— 本地栈出板通路（最先做，最便宜）

### 2.1 这一档在验什么

验的是 2026-11-08 集成里新增的 `stack_takeover`（契约 §7.3 记录的缺口）：**本地应答必须从本板 GE2 出去**。P1 位流下这两件事根本做不到（栈 TX 只进 Aurora → 应答跑到对端网口去了），所以这是 P2 相对 P1 的**结构性改进**，且**不需要对端板、不需要光纤**。

### 2.2 关键前提（别误判成故障）

无光纤/无对端时 `channel_up=0` → `aurora_rst=1` → **P2 的转发侧（extract/buf/steer/rewrap）处于复位**，这是设计使然。所以本档：

> 行号可核：`rtl/aurora_mem_bridge.v:234` `wire aurora_rst = ~sys_rst_n | ~link_ok;`（P2 两个域的 `rst_n` 都接 `~aurora_rst`），
> 而本地栈/`stack_takeover` 走的是 `rtl/aurora_mem_bridge.v:183` `assign eth_rst_n = sys_rst_n;` —— **不受链路状态门控**，所以档 1 在无光纤时仍然成立。

- ✅ 只看 **PC 侧**现象（ARP/ping）；**不看任何 Aurora 计数**（`pfwd_wr/pk_frames/up_frames/prev_wr` 全 0 是预期）。
- ✅ ILA6 里 `ch_up=0 / aurora_rst=1` **不是失败**。
- ❌ 不要在这一档发"转发包"（`dst=10.10.0.2`）—— 链路没起来，必然没有结果。

### 2.3 判据

| # | 操作 | 期望 | 不通过说明 |
|---|---|---|---|
| L1 | `arp -d 10.10.0.11` 后 `ping 10.10.0.11`，再 `arp -a` | 学到 `10.10.0.11 → 02-00-00-00-0a-01` | 没学到 → ARP 应答没出本板 GE2（`stack_takeover` 或 mux 没生效） |
| L2 | `ping 10.10.0.11 -n 20` | **0% 丢包，全 <1 ms** | 全丢 → 检查串口 `d` 是否 PASS（`d` 不影响本档，但排除法先排除）；检查 PC 子网/掩码 |
| L3 | 同上，但把 PC 静态 ARP 先清掉、只用 `ping` | 首次 ping 可能首包丢（ARP 解析），其后 0 丢 | 持续全丢 → L1 失败同因 |
| L4 | `ping 10.10.0.2 -n 3`（对端 PC，本档不通） | **100% 丢** | 若居然通了 → 说明转发逻辑在链路未起时仍在转发（异常，立即报） |

> L4 是**反向判据**：本档没有链路，跨板一定不通。它顺便证明"没链路时不会乱转发"。

## 3. 档 2：**光纤自环** —— 转发通路（单板跑完整条 P2 链路）

### 3.1 物理接法

用一根光纤跳线把 **SFPA（X1Y11）的 TX 接到 RX**（同一模块自环）。这是 prj8 用过的成熟配置。

自环后数据流是：

```
PC1 ─GE2─► 板A 提取 ─► 判决(RELAY) ─► 泵A ─► mem1 ─► Aurora TX ─┐
                                                                │（自环跳线）
PC1 ◄─GE2─ 泵B ◄─ mem2 ◄─ rewrap ◄─ unpack ◄─ Aurora RX ◄───────┘
```

### 3.2 判据

| # | 操作 | 期望 |
|---|---|---|
| S0 | ILA6 单帧（`ila_capture_any.tcl ... dbg_pk_frames none`） | `ch_up=1 lane_up=1 gt_pll_lock=1 link_ok=1 aurora_rst=0 hard/soft=0` |
| S1 | 发 1 帧 `dst=PEER_IP`：`twin_send.py --scheme handbook --dst-ip 10.10.0.2 --count 1 --len 100 --run-id 0x11 --interval-ms 0` | **六点差分链各 +1**（见 §3.4）；pcap 抓到 1 帧 |
| S2 | 同上的 pcap 逐字节比对 | 回来的帧 = **dst=`A8:2B:DD:76:DF:A2`、src=`02:00:00:00:0A:01`、type=`0x0800`**，IP 包**逐字节相同**（含 IP/UDP checksum、TTL、DSCP、端口） |
| S3 | 小包：`--len 12`（IP 总长 40） | 回来的**帧长 60**（补零到最小帧），后 20 B 全 `0x00`，前 40 B 原样 |
| S4 | 分片：用 `pc/make_test_pcap.py` 造 MF=1 的包后 `twin_send.py --from-pcap`（若脚本无此参数则用 PC1 手工组包工具） | 回来逐字节相同，**不被重组** |
| S5 | 反向判据：发 1 帧 `--dst-ip 10.10.0.11`（BOARD_IP） | **自环上零帧**（走本地通路，`pfwd_wr` 不动），PC1 侧表现为 ping/应答正常 |
| S6 | 反向判据：发 `--dst-ip 8.8.8.8` ×3 | **自环上零帧**，`pfwd_wr` 不动（防乒乓：不允许"非本板 IP 都转发"） |
| S7 | 链路稳定：`ila_poll_stable.tcl ... <ltx> 300 5` | 300 s 内 `ch_up` 恒 1（自环应非常稳） |

### 3.3 **必须知道的坑：MAC 过滤**

自环回来的帧 `dst = PEER_MAC = A8:2B:DD:76:DF:A2`（PC2 的网卡），发到 **PC1** → PC1 网卡会按 MAC 过滤丢弃，**OS 应用收不到**。

- ✅ **判据一律走 pcap**（npcap promiscuous 模式能抓到非本机 MAC 的帧），这也是本档判定"逐字节不变"的唯一可靠手段：
  ```powershell
  py pc\npcap_capture.py --iface "<PC1 网卡>" --seconds 30 --out out\tier2_rx.pcap   # 先起抓
  py pc\twin_send.py --scheme handbook --dst-ip 10.10.0.2 --count 1 --len 100 --run-id 0x11 --interval-ms 0
  py pc\twin_recv.py --from-pcap out\tier2_rx.pcap --scheme handbook --no-bcast `
      --expect-count 1 --expect-len 100 --expect-run-id 0x11
  ```
- 若想做到**应用层收包**（UDP socket 真收到），需另出一版"自环专用位流"，把 `PEER_MAC` 改成 **PC1 自己的 MAC**（改 1 个参数、约 40 min 构建）。**建议先按 pcap 判据跑通，再决定要不要这一版。**

### 3.4 六点差分链（定位丢在哪一段，全用**现有探针**，不需要新位流）

> **先确认一件事：`d` 之后 mem1 会不会自动读出？——会，行号可核：**
> - `d` 命令不只是切标志：它设 `R_ENGINE=1` **并** 把 `R_MODE` 置成 `MODE_SEQ`（`sw/src_j3/main.c:638-660`）；
> - RTL 里 `mem_rd_req` 的生成是：**`cfg_mode_eff==0` 时自动读**（有 outstanding 就读），只有 `cfg_mode_eff==1`（RND）才要求 `cmd_rd_req_pulse | lite_rd_req_pulse`（`rtl/aurora_mem_bridge.v:384-386`）；
> - 固件在提示符空闲循环里每圈调 `serve_any()`（`sw/src_j3/main.c:611-616`）——软核在等命令时也在服务读请求。
>
> ⇒ 所以 **T2 的 `now=DMA` 成立之后，发一帧就应在下面六点各 +1**。若 `pfwd_wr+1` 而 `pk_frames` 不动，**先怀疑 `d` 没真正生效**（banner 是上一轮残留的）或 mem1 写被整帧拒收，而不是先查 Aurora。


| 观察点 | 探针（ILA） | 含义 | 期望（发 1 帧） |
|---|---|---|---|
| ① 转发判决通过 | ILA6 `dbg_pfwd_wr` | 泵A 写入帧数 = **RELAY 包数**（P2 起语义变了） | +1 |
| ② 进内存桥① | ILA3 `dbg_mem_wr_frm` | mem1 写帧数 | +1 |
| ③ 出内存桥① | ILA3 `dbg_mem_rd_frm` | mem1 读帧数 | +1 |
| ④ 上 Aurora TX | ILA6 `dbg_pk_frames` | pack 出帧数 | +1 |
| ⑤ 从 Aurora RX 解出 | ILA6 `dbg_up_frames` | unpack 帧数（自环应等于④） | +1 |
| ⑥ 进/出内存桥② | ILA3 `dbg_mem2_wr_frm` / `dbg_mem2_rd_frm` | mem2 写/读 | 各 +1 |
| ⑦ 到 RGMII | ILA6 `dbg_prev_wr` | 泵B 写帧数（=发往 PC 的帧） | +1 |

**另外**：ILA0 的 `dbg_pfwd_data[7:0] + dbg_pfwd_en` 是**转发流的原始字节**——抓一次就能直接看到 IP 包头的 `45 00 …`，用它核对"送进 Aurora 的就是 IP 包、没有以太头"。这是当前唯一能"眼看字节"的探针。

| **板 B 版 P2 位流未构建** | 双板 V4 无对端 | 同源码换参数（`BOARD_IP=.12 / BOARD_MAC=0b:01 / PEER_IP=.1 / PC_IP=.2 / PEER_MAC=PC1 网卡 MAC`）再跑一次 synth+impl（约 40 min，**我可以直接做**） |
| **P2 计数器无探针** | #10 的「各类 DROP 分别计数」判据抓不到 | 给 11 个计数器加 `mark_debug`（32–48 bit）后重出位流（可与上一条合并成一轮构建） |
| **板 B 无规律复位（#15）未闭环** | 180 s 连续抓包会被打断 | 先做短窗口判据；或按 §6 的 QSPI 固化 + 看护脚本兜底 |

### 4.2 双板标准顺序（手册 §9，别改顺序）

1. 先确认**对端** `get_hw_ilas=4` 且 `ch_up=1`；
2. 再**整板重烧本板 + 串口 `d`**；
3. **3 帧探针**确认 `pk_frames +3`（探针不过就打不开窗口）；
4. 才开**单次连续 ≥180 s** 的抓包窗口（禁分块循环）；
5. V4 四项判据：#10 §6.8 —— IP 包逐字节不变 / 各类 DROP 计数 / ARP 不跨板 / 无乒乓。

### 4.3 V3（反向对称性，用旧位流即可，不需要 P2）

B→A 方向：B 侧闪断后 `mem2_wr_frm / mem2_ost` 冻结而 `up_frames / prev_wr` 照涨 → 证明缺陷对称。**这一步与 P2 位流无关**，用 prj12 的 P1/B1 位流即可，可在板 B 测试间隙做。

## 7. 失败分诊（症状 → 判别 → 处置）

| 症状 | 判别 | 处置 |
|---|---|---|
| 发包成功但 pcap 零帧、板侧计数不动 | **scheme 配错**（对 P2 位流用了 `p1`） | 一律 `--scheme handbook`；看脚本打印的 `BITSTREAM:` 行 |
| `pfwd_wr` 涨但 `pk_frames` 恒 0 | **没进 DMA 模式**（只烧了位流，漏 `d`），或 mem1 写被整帧拒收 | 串口 `d` → `SERIAL_RESULT: PASS`；再看 ILA3 `dbg_mem_stall/len_err` |
| `pk_frames` 涨、`up_frames` 不涨 | 自环线没连/没插好；或 `ch_up=0` | 先抓 ILA6 确认 `ch_up=1`；重插自环跳线 |
| `up_frames` 涨、`prev_wr` 不涨 | mem2 写/读异常 | 看 ILA3 `dbg_mem2_wr_frm/rd_frm/len_err` |
| pcap 抓到但内容不对（IP 被改） | 不该发生 | **立即停**：报 bug（P2 红线是 IP 逐字节不变），附 pcap + ILA0 字节流 |
| 抓 ILA 报 "no ILA in device" | 位流不带 ILA / 抓到别的板 | 用 `probes_p2_B30C3903.ltx`；认板靠 cable 选择（两板同序列号） |
| 串口无回显 | CH340 被占 | 拔插 CH340；`d` 是**翻转**命令，只看最后一条 banner |
| `get_hw_ilas=0` | 位流丢了（复位/断电/被重烧） | 重烧 BitElf + `d`；**网口 Up 不代表位流在跑** |
| 自环下 ping 板卡不通 | `stack_takeover` 或 mux 没生效 | 退回档 1 复测（L1/L2）；档 1 都不通则是集成 bug |

## 8. 与板 B 并行测试的约定

1. **不要同时烧两块**：同一台机器上两板 JTAG 序列号相同，`-Board Both` 会选错；一次只烧一块，烧另一块前先确认前一块已 `d` 完成。
2. **证据各归各**：板 A 证据进 `prj13/out/evidence_2026-11-10_p2_onboard/`，板 B 的测试证据按它自己的目录走；两边都在 README 里写清**当时烧的是哪片位流**（哈希），否则事后无法对账。
3. **板 B 若要做 P2 对端**：等板 B 版位流（§4.1），在此之前板 B 只能跑 P1/B1 类判据（`--scheme p1`）。
4. **共享判据工具**：`pc/twin_send.py` / `twin_recv.py` / `npcap_capture.py` 是两板共用的，改默认值前先通知（当前默认 `handbook`）。
5. **时间槽**：若两板都要抓 180 s 窗口，按 prj12 手册 §4 的固定时钟槽（T0 起两边同时抓，T0+30 s 发包），不要互相等。
