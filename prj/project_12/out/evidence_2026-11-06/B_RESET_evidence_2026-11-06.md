# 板 B 无规律复位 · 证据与结论（2026-11-06）

> 结论先行：**这是硬件供电/接触类问题，不是位流、不是 RTL、不是脚本**。
> 影响：会反复清掉 P1 位流（JTAG SRAM 易失），每次都要「重烧 B + 重烧 A（A 的 pack 会卡死）」；
> P1 的判据本身不受影响（每次都在复位前的窗口内取得并留档），但长跑类实验无法稳定进行。
> 建议：下轮先换**电源适配器 / DC 头 / 供电排插**；软件侧的根治方案是把 P1 位流写进 QSPI（复位后自动加载，见 §4）。

## 2. 排除项（为什么不是软件/位流问题）

| 排除项 | 依据 |
|---|---|
| 位流本身 | 全程同一份 `C856BA83`（SHA256 `C856BA83…7401`）；复位与「烧了哪份位流」无关，烧完 P1 后同样会掉 |
| RTL / 固件 | 复位发生在**空闲期**（无发送、无 ILA 抓取、无串口交互）也发生；`ch_up` 与计数是干净清零，不是逻辑乱 |
| 脚本 / Vivado 会话 | 复位与「是否开 Vivado 会话」无关：17:40:50 关会话后 17:41:42 仍是 4；19:01–19:05 单会话轮询 17 次全 4 后照样掉 |
| 重插接线 | 19:29:22 全部接线重插后稳定 15 min，又在 19:44–19:46 掉 → **重插无效，指向供电/接触本身** |
| FPGA 温度/负载 | 复位时 DUT 空闲（`pk/up/pfwd/prev=0`），不是高负载过热 |

## 3. 复位间隔统计

- 间隔范围：**2 – 38 分钟**，无固定周期；
- 最长稳定段：**≥38 min**（18:05:37 → 18:43:35）；另有 32/32 样本（19:33:56–19:41:55）稳定；
- 重插接线后：15 min（19:29:22 → 19:44:10）；
- 复位后板子回落到 **QSPI flash 旧位流**（无 Aurora、无 ILA），`以太网` 仍可能 Up（flash 设计也驱动 GE2）——
  **所以「网口 Up」不能当作「P1 在跑」的判据，唯一判据是 `get_hw_ilas` 数量（P1=4 / flash=0）**。

## 4. 软件侧根治方案（下轮可选项）

| 方案 | 说明 | 成本/风险 |
|---|---|---|
| **把 P1 位流写进 QSPI flash** | 复位后自动加载 P1，复位不再致命；板子变「上电即 P1」 | 需 `write_cfgmem` + `program_hw_cfgmem`；注意 N25Q128=16MB 与 .bit 10.3MB（压缩后）容量关系；写错会覆盖出厂固件，需先备份 |
| 外部看门狗/自动重烧脚本 | 由 PC 侧轮询 `get_hw_ilas`，掉 0 就自动 `twin_burn -Board B -Mode BitElf` | 已有 poller 原型；但重烧 B 会再打 A 的 pack，需配套重烧 A |
| 只做短窗口实验 | 每轮实验前 `ilas=4`+3 帧探针，窗口 ≤10 min | 最省事，但长跑/稳定性结论受限 |

## 5. 对 P1 结论的影响

- **不影响**：P1-01/02（10 min 稳定曾在 15 min 稳定段内取得，119 样本 `drops=0 resets=0`）/03/04/05 的判据均已在复位前的干净窗口内取得并留档；
- **影响**：任意「长于复位间隔」的连续实验（P2 吞吐/长跑）会被打断；每打断一次需要「重烧 B + 重烧 A」约 3 分钟；
- **代码/文档未做任何规避性 hack**（没有改判据、没有掩盖复位）。
