# prj12 · P2 候选设计：PC1 ↔ PC2 经 FPGA 的 UDP 透明转发（仅设计，不合并）

> **状态**：候选设计 v0.1（2026-10-24）。**不并入 P1 位流**，不触碰 `prj/project_12/rtl/` 的顶层集成。
> **依据**：`操作文档/阶段三_prj12_双板互联开工草案_2026-10-24.md` §3.2/§4.3；对齐包 `06` 的 A3/M1 口径。
> **前置**：P1 绿（链路 + 数据面可见）；`Q-05`（任务粒度/缓存）与 `protocol_v1` 未冻结前，**不做带语义的头**（本设计只做无状态 payload relay）。
> **代码**：`prj/project_12/p2_candidate/rtl/`（3 个单元件）、`p2_candidate/sim/`（3 个 TB）。它们**不在 Vivado 工程的 fileset 里**，P1 位流不含它们。

---

## 1. 要解决的问题（一句话）

P1 的链路只做到"PC1 发的帧能在 PC2 网口被**看到**"：prj11/12 的以太网栈是**终止+回显**（`assign des_mac = src_mac; assign des_ip = src_ip;`），
回显帧出了对端板的 RGMII 之后 **目的 MAC/IP 仍是 PC1**，PC2 的 OS 不会交付给应用。P2 要把它变成 PC1↔PC2 可用的数据通道，同时**不把本地控制面带跑**。

---

## 2. 目标架构（每块板同一份源码，A/B 两套参数）

```
PC1 ─GE1─► [eth stack: ARP/ICMP/UDP 解析]
                 │
                 ├─ local_steer ── LOCAL(ARP/ICMP/命令/本板服务) ──► 既有栈处理（本地直出）
                 │
                 └─ RELAY(数据 UDP) ─► udp_payload_extract ─► 帧写 mem1(DDR)
                                                              │
                                            pack(8→64) ─► Aurora A TX ═══ 光纤 ═══► 板 B A RX
                                                                                        │
                                                                              unpack ─► mem2(DDR)
                                                                                        │
                                         relay_tx（按**本板 PC** 的 MAC/IP 重建 ETH/IP/UDP）
                                                                                        │
                                                                              RGMII TX ─► PC2
```

反向同构：PC2 → 板 B → Aurora → 板 A → relay_tx → PC1。

**关键语义**：
- 一个 **UDP payload = 一个内部帧**（`mem` 的 `len` 字段携带长度），上限沿用 prj11 的 **1538 B/帧** ⇒ payload ≤ **1496 B**（1538 − 42 头）。
- 两板**同源不同参数**：`BOARD_MAC/IP`（本板）、`PC_MAC/IP`（本板 PC）、`DATA_PORT`；P2 先出 A/B 两套位流，后续再合并为运行时配置。
- 不做：ACK/重传/序号/分片重组（属 `protocol_v1` 冻结后的可靠层）；不做 M3 门控/时窗；不做多路径。

---

## 3. 三个候选单元件（已写 + 已带 TB）

| 件 | 文件 | 接口要点 | 单元判据（TB） |
|---|---|---|---|
| ① payload 提取 | `p2_candidate/rtl/udp_payload_extract.v` | 入：从 **UDP 头首字节**开始的 8bit 流 + `sop/last`；出：payload 流 + `m_len` | 26/100… 逐字节；零长/超长/长度不符/头截断四类错误标志 |
| ② 整帧重建 | `p2_candidate/rtl/relay_tx.v` | 入：payload 流 + `start/payload_len` + `dst_mac/dst_ip/dst_port`；出：整帧流 | 42B 头逐字节 + IP 校验和自校验（累加=0xFFFF）+ 长度字段 + 1497 超限不发 + 背压 |
| ③ 本地/转发分流 | `p2_candidate/rtl/local_steer.v` | 入：ethertype/ip_proto/dst_ip/dst_port；出：`cls`/`is_local`/`is_relay`/`is_drop` | 8 类判决全表（ARP/ICMP/命令/数据/本板其它/陌生/TCP/非 IP） |

> 为什么把 ① 收窄成"吃 UDP 头"而不是"吃整帧"：IP 解析已在既有栈里做过（且要处理 IHL/分片），再写一遍只会引入第二套解析口径；单元件边界放在 UDP 段，TB 更干净、集成点更明确（栈的 UDP RX 出口直接接它）。

### 3.1 `relay_tx` 的头部字段（逐字节约定）

| 偏移 | 长度 | 值 |
|---|---|---|
| 0–5 | 6 | `dst_mac`（本板 PC） |
| 6–11 | 6 | `SRC_MAC`（本板，参数） |
| 12–13 | 2 | `0x0800` |
| 14 | 1 | `0x45`（IPv4, IHL=5） |
| 15 | 1 | `0x00`（DSCP/ECN） |
| 16–17 | 2 | `total_len = 28 + payload_len` |
| 18–19 | 2 | `0x0000`（identification） |
| 20–21 | 2 | `0x4000`（DF） |
| 22 | 1 | `64`（TTL） |
| 23 | 1 | `17`（UDP） |
| 24–25 | 2 | IP 头校验和（硬件算） |
| 26–29 | 4 | `SRC_IP`（本板，参数） |
| 30–33 | 4 | `dst_ip`（本板 PC） |
| 34–35 | 2 | `SRC_PORT`（参数，默认 1234） |
| 36–37 | 2 | `dst_port`（本板 PC 的应用端口） |
| 38–39 | 2 | `udp_len = 8 + payload_len` |
| 40–41 | 2 | UDP 校验和 = `0x0000`（IPv4 合法：未计算；要真校验和需伪头累加，属后续增量） |

## 4. 集成点（P2 真正改顶层时落这里，本阶段**不动**）

| # | 落点（prj11/12 顶层） | 改动 | 风险 |
|---|---|---|---|
| 1 | `stack_txd/stack_tx_en`（eth→泵A）之前 | 插入 `local_steer` + `udp_payload_extract`，RELAY 帧改走 mem1 | 与既有 UDP 回显语义冲突：必须先关掉 `des_mac=src_mac` 的回显路径（否则同一帧走两条） |
| 2 | `mem2` 读出口 → `pumpB` | 插入 `relay_tx`，用本板 PC 的地址重建帧 | 与栈自发的 ARP/ICMP 应答**共用 RGMII TX**，需要优先级 mux（沿用 W5 `cmd_takeover` 的空闲拍注入法） |
| 3 | 顶层参数 | 新增 `BOARD_MAC/IP`、`PC_MAC/IP`、`DATA_PORT` 参数化 + A/B 两套位流 | 两板同 IP/MAC 时必须靠直连/独立 L2 隔离（P1 已如此） |
| 4 | `xdc` | 不改（P2 不新增引脚） | — |

---

## 5. 判据

**单元（本阶段已具备）**：`p2_candidate/sim/run_p2_tb.cmd` → 三个 TB 全 PASS。
**上板（P1 绿后）**：
- PC1 发 → PC2 应用收到（不是"抓到"）：字节数/内容/SHA 一致；
- 本地 ARP/ICMP 仍正常（`ping` 板卡 IP 通）——证明控制面没被带跑；
- 反向同理；断电重启后自动恢复；
- 有界窗口/低速率先跑 1 MB，再谈 10 MB（可靠层未冻结前不承诺）。

---

## 6. 未决与边界

| 项 | 影响 | 本设计的态度 |
|---|---|---|
| `Q-05` 任务粒度/缓存 | 一帧要不要带 `transfer_id/segment_*` | **不带**，payload 即帧；等 `protocol_v1` |
| `Q-15` 时窗语义 | M3 才需要 | 不涉及 |
| UDP 校验和 | 端到端完整性 | 先写 0；硬件伪头累加留增量 |
| 两板 MAC/IP 冲突 | 同交换域会冲突 | P2 用 A/B 唯一参数；测试期 PC 直连 |
| 1538 B 帧上限 | 大消息要分片 | 分片属 `protocol_v1`；本设计一帧一 payload |

---

## 7. 与 prj11 的关系（不重复造轮子）

- mem1/mem2、pack/unpack、帧泵、AXI 桥、软核控制面**全部复用 prj11 已验证件**；
- 本设计只新增 3 个纯组合/简单 FSM 单元件 + 一处 TX mux 插入；
- 因此 P2 的回归风险主要在"回显路径与转发路径的互斥"，不在数据搬运本身。
