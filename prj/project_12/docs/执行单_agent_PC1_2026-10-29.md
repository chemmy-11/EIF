# 执行单 · Agent（PC1 / 本机）· prj12 P1 双板联调

> **给谁看**：在 **PC1（本机）** 上执行联调的 agent。**本单是机械可执行的步骤表**；背景与证据口径看
> `docs/P1_双板上板执行单_2026-10-24.md`（人读版），冲突时以本单的命令/判据为准。
> **拓扑假设**（不成立就停）：两块板都在本机旁边，**两板 USB-JTAG 与串口都插在本机**；
> 本机网口接**板 A 的 GE1**；PC2 的网口接**板 B 的 GE1**。两板 GE1 不接同一交换机。
> **本单只验 P1** = 链路 + 数据面"可见"。**不要**给出 PC↔PC 可用收发的结论（那是 P2）。

## 3. 本机静态 ARP（**必须**，否则 PC1 一条都发不出去）

原因：板卡的 ARP 应答也会跨光从**对端板**出去（`rtl/eth_ctrl.v:163-177` → `stack_txd` → 泵A），
PC1 永远收不到 → ARP 解析失败 → `sendto()` 在 OS 层就失败。

```powershell
# 先把 config 里的 pc_nic 改成 §1.2 查到的真实名字（可能是中文"以太网"）
powershell -NoProfile -ExecutionPolicy Bypass -File D:\FPGA\prj\project_12\pc\static_arp.ps1 -DryRun
powershell -NoProfile -ExecutionPolicy Bypass -File D:\FPGA\prj\project_12\pc\static_arp.ps1 -Apply -InterfaceAlias "<PC1 网卡名>"
# 校验（必须出现 00-11-22-33-44-55 / Permanent）
Get-NetNeighbor -InterfaceAlias "<PC1 网卡名>" -IPAddress 192.168.1.10 | Format-Table InterfaceAlias,IPAddress,LinkLayerAddress,State
```

**通过**：邻居项存在且 `State=Permanent`。
**停**：非管理员导致写入失败 → 回报，不要跳过（跳过必然 0 帧）。

## 5. 链路判据（P1 核心）

```powershell
# 板 A（cable 用 A 的序列号）
vivado -mode batch -source D:\FPGA\prj\project_12\scripts\ila_capture.tcl `
  -tclargs localhost:3121 <A线缆序列号> D:\FPGA\prj\project_12\out\ila6_A.csv
# 板 B
vivado -mode batch -source D:\FPGA\prj\project_12\scripts\ila_capture.tcl `
  -tclargs localhost:3121 <B线缆序列号> D:\FPGA\prj\project_12\out\ila6_B.csv
```

**通过**（两块板各自都要满足）：

| 观测 | 判据 |
|---|---|
| CSV 里 `probe0` 的 bit1（channel_up） | =1 |
| bit0（link_ok） | =1，且与 bit1 同相（同相 = 补丁生效） |
| bit2（lane_up） | =1 |
| bit3（gt_pll_lock） | =1 |
| `probe1` bit0/bit1（hard_err/soft_err） | 全 0 |
| `probe9`（aurora_rst） | =0 |
| 板载 LED T23 | 常亮 |
| 10 min 后重抓一次 `probe3/probe4`（hard/soft 计数） | 不增长 |

**CSV 怎么读**：先 `Get-Content <csv> -TotalCount 3` 看表头（列出 probe 名与位宽），
再按上表的 **probe 位序**取第一行数据的值（十六进制按位拆）。
若表头/格式与上表对不上：**停**，把前 3 行原文贴进回报，人工判——不要猜。

**停**：`channel_up=0` → 按人读版 §7 的 5 分钟判别树（T23 → 模块 → `gt_pll_lock` → `lane_up`）；回报每一步观测。
**停**：`channel_up` 起来又掉 / `hard_err` 增长 → 记录两板模块型号，回报，不要继续数据面。

## 7. A→B 方向（PC1 发，PC2 抓）

1. 通知 PC2（或用户）**开始抓包**（PC2 侧命令见 `执行单_agent_PC2_2026-10-29.md` §3）。
2. 本机发送（`--run-id 0x1` 用于方向判别）：

```powershell
py D:\FPGA\prj\project_12\pc\twin_send.py --dst-ip 192.168.1.10 --dst-port 1234 `
   --count 20 --len 100 --run-id 0x1 --interval-ms 20
```

**通过（本机侧）**：`SEND_OK: 20/20`。
**停**：`FAIL: send error` → 回 §3（ARP 没绑）；**不要**用 ping 试。

3. 等 PC2 回报 `twin_recv: PASS`（判据在 PC2 单里）。**PC1 本机不应收到回包**——这是 P1 预期，不是故障。
4. （可选佐证）重抓一次 ILA6，`probe5`（进 A 核 TX 帧数）应比发送前**增加约 20**。

## 8. B→A 方向（PC2 发，PC1 抓）

1. 本机起抓（`ifIndex` 用 §1.2 的；过滤条件只收板卡发的帧）：

```powershell
dumpcap -i <ifIndex> -f "ether src 00:11:22:33:44:55" -a duration:30 -w D:\FPGA\prj\project_12\out\pc1.pcap
```
2. 通知 PC2 发送 20 帧（`--run-id 0x2`）。
3. 判据：

```powershell
py D:\FPGA\prj\project_12\pc\twin_recv.py --from-pcap D:\FPGA\prj\project_12\out\pc1.pcap `
   --board-mac 00:11:22:33:44:55 --port 1234 --expect-count 20 --expect-len 100 --expect-run-id 0x2
```

**通过**：`twin_recv: PASS`（`matched ≥ 20`、`unique=20`、`dup=0`、`fill=ok`、`run_id 0x2 OK`）。
**预期语义**：抓到的帧 `eth.dst = PC2 的 MAC`（不是 PC1 的）——这是 P1 正常现象。

## 11. 停止条件与不做清单

**立即停并回报**：认板只 1 条线缆；`channel_up` 10 min 未起；`hard_err` 持续增长；
`twin_recv` matched=0 且 `probe5` 不动；板卡/模块发烫、异响、电源异常；

**不做**：不用 ping/单帧截图当判据；不宣称 PC↔PC 可用收发（P2）；
不跳过静态 ARP；不改 `expect_bit_sha256` 绕过哈希；不并行起多个 Vivado；
