# 执行单 · Agent（PC2）· prj12 P1 双板联调

> **给谁看**：在 **PC2**（另一台 PC，接**板 B** 的 GE1）上执行联调的 agent。
> **本机没有 Vivado / JTAG / 板卡**——PC2 只做三件事：**配网 + 抓包判定 + 反向发送**。
> 背景口径见 `M1_prj12_执行单_agent_PC1_2026-10-29.md`（PC1 侧）与人读版执行单；冲突时以本单命令为准。
> **本单只验 P1** = 链路 + 数据面"可见"。**不要**给出 PC↔PC 可用收发的结论（那是 P2）。

---

## 0. 角色与拓扑（不成立就停）

```
PC1 ──GE1── 板A ══光纤(SFPA↔SFPA)══ 板B ──GE1── PC2
      （本机，Vivado/JTAG 都在那边）              （就是你这台）
```

- 你这台只连**板 B** 的 GE1；**两板 GE1 不得接进同一台交换机**（两板同 MAC/IP）。
- 板卡地址：`192.168.1.10 / 00:11:22:33:44:55`（**两板相同**，各自独立 L2）。
- 你这台的地址：`192.168.1.102/24`（与板卡同网段）。
- **绝对不要**把 `192.168.1.10` 配到本机网卡上（那是板卡的地址，配了会直接冲突）。

## 1. 前置（10 分钟，全部只读）

```powershell
# 1.1 Python（脚本只用标准库）
py -V
$env:PYTHONUTF8 = '1'          # 建议设；GBK 控制台打中文会崩
# 1.2 抓包工具（Wireshark 自带 dumpcap+Npcap）
dumpcap -D
# 1.3 网卡（记下接板 B 的那块的名字与 ifIndex）
Get-NetAdapter | Format-Table Name,MacAddress,Status,ifIndex -AutoSize
# 1.4 当前 IP（确认是 192.168.1.102/24；不是就配，别配 .10）
Get-NetIPAddress -AddressFamily IPv4 | Format-Table InterfaceAlias,IPAddress,PrefixLength -AutoSize
```

**通过**：`py -V` 有版本；`dumpcap -D` 能列出网卡；接板 B 的网卡存在且 IP 为 `192.168.1.102/24`。

> 网卡显示"未识别的网络"是直连的正常现象，**不要**用 ICS/网络桥接去"修"它。

## 4. 静态 ARP（**必须**）

原因：板卡的 ARP 应答会跨光从**对端板**出去，PC2 永远收不到应答 → 不绑就发不出包。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\twin\pc\static_arp.ps1 -DryRun
powershell -NoProfile -ExecutionPolicy Bypass -File C:\twin\pc\static_arp.ps1 -Apply -InterfaceAlias "<接板B的网卡名>"
Get-NetNeighbor -InterfaceAlias "<接板B的网卡名>" -IPAddress 192.168.1.10 |
    Format-Table InterfaceAlias,IPAddress,LinkLayerAddress,State
```

**通过**：`192.168.1.10 → 00-11-22-33-44-55`，`State=Permanent`。
**停**：非管理员 → 回报（不要跳过，跳过必然 0 帧）。

## 5. 抓 A→B 方向（PC1 发、你抓）

**时机**：PC1 那边说"开始抓"后，先起抓包（30 s 窗口），再让 PC1 发 20 帧。

```powershell
dumpcap -i <ifIndex> -f "ether src 00:11:22:33:44:55" -a duration:30 -w C:\twin\out\pc2.pcap
```

**注意**：
- 过滤条件只能是 `ether src`（板卡发出的）；**不要**加 `ether dst` —— 这批帧的目的 MAC 是 **PC1**，不是你。
- 混杂模式由 dumpcap 自动开，不要额外设置。

抓完立刻判：

```powershell
py C:\twin\pc\twin_recv.py --from-pcap C:\twin\out\pc2.pcap `
   --board-mac 00:11:22:33:44:55 --port 1234 --expect-count 20 --expect-len 100 --expect-run-id 0x1
```

**通过（0 丢包口径，机械判据）**：
`twin_recv: PASS` 且同时满足 `matched ≥ 20`、`unique=20`、`dup=0`、每帧 `fill=ok`、`run_id: 0x1 OK`、`payload len(s) [100]`。

**预期语义（不是故障）**：抓到的帧 `eth.dst` = **PC1 的 MAC**；PC2 的 OS 不会把帧交给应用。这是 P1 的定义。

| 现象 | 先判 | 回报内容 |
|---|---|---|
| `matched: 0`、`other` 也 0 | 抓包没抓到任何东西 | 网卡名/ifIndex 是否选错；`dumpcap -D` 输出 |
| `matched: 0`、`other > 0` | 抓到了但不是板卡发的 | 前 5 行 `twin_recv` 输出（看 src_mac/dport） |
| `matched` 少于 20 | 真丢帧 | 完整 `twin_recv` 输出 + `dup`/`unique` 数 |
| `fill BAD@n` | 内容被破坏 | 首帧 `seq/len/fill_bad_at` |

## 6. 发 B→A 方向（你发、PC1 抓）

**时机**：PC1 说"我起抓了"之后再发（`--run-id 0x2` 用于方向判别）。

```powershell
py C:\twin\pc\twin_send.py --dst-ip 192.168.1.10 --dst-port 1234 `
   --count 20 --len 100 --run-id 0x2 --interval-ms 20
```

**通过（本机侧）**：`SEND_OK: 20/20`。
**停**：`FAIL: send error` → 回 §4（ARP）；**不要**用 ping 试（P1 下 ping 必不通）。
**注意**：你**不应该**收到回包（回显帧会从板 A 出去给 PC1），这是预期。

## 7. 回报格式（照抄填空，别只写"通过"）

```
[PC2] 环境：py=<版本> dumpcap=<路径> 网卡=<name>/<ifIndex> IP=<x>/<前缀>
[PC2] 自检：good=PASS badfill=FAIL（两条都符合预期）
[PC2] ARP：192.168.1.10 -> <LLADDR> state=Permanent
[PC2] A→B：pcap=<文件名> 帧数=? matched=? unique=? dup=? fill=? run_id=? → PASS/FAIL
[PC2] B→A：SEND_OK 20/20（发送端）；PC1 判据结果=<PC1 回报>
[PC2] 异常/停点：<无 或 逐条现象+原始输出片段>
[PC2] 证据：pcap 路径 + twin_recv 输出全文（贴回）
```

## 8. 停止条件与不做清单

**立即停并回报**：板卡一个包都抓不到（`other` 也为 0）；`matched` 明显少于发送数；
`fill BAD`；静态 ARP 绑不上；网卡/驱动异常；需要装软件或改系统设置才能继续。

**不做**：不用 ping 当判据；不宣称 PC↔PC 可用收发（P2）；不把 `192.168.1.10` 配到本机；
不桥接/ICS；不改脚本逻辑（发现脚本问题 → 停并回报，让 PC1 侧修）；
不删 `out\*.pcap`（这是证据）。
