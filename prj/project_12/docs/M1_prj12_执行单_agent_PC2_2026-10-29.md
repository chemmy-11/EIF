# 执行单 · Agent（PC2）· prj12 P1 双板联调

> **给谁看**：在 **PC2**（接**板 B** 的 GE2）上执行联调的 agent。**本单是机械可执行的步骤表**；背景口径看
> `M1_prj12_执行单_agent_PC1_2026-10-29.md`（PC1 侧）与人读版执行单；冲突时以本单命令为准。
> **本单只验 P1** = 链路 + 数据面"可见"。**不要**给出 PC↔PC 可用收发的结论（那是 P2）。
>
> ### ★ 2026-11-06 上板实测修订（先读这五条）
> 1. **网口是板卡 GE2，不是 GE1**。工程 XDC 的 eth 引脚与官方 `KU_IO.xdc` 的 `#GE2` 段逐脚一致
>    （AC31/Y33/W33/W34/V33/AC32/Y32/AE32/Y31/AF32/AF30/AG30/AA33）。PC1 实测：插 GE1 → 网卡一直
>    `Disconnected`（两端重插无效）；换 GE2 → **立即 Up / 1 Gbps**。**本机网口不亮时先换 GE2**。
> 2. **环境已变**：本机现在接**板 B 的 GE2 + 板 B 的 USB-JTAG**，且有 Vivado 2023.1。
>    旧版本文"PC2 没有 Vivado/JTAG/板卡"已作废；若某台机器确实没有，退化为"只做配网 + 抓包判定 + 反向发送"。
> 3. **B→A 方向需要板 B 也烧 ELF 并发串口 `d`**（DMA 写模式）：板 B 的桥①（eth→Aurora）的 DDR 写走
>    AXI DMA S2MM，固件按帧服务，只在 `g_dma_mode=1` 时工作。只烧位流时：`pfwd_wr` 涨、
>    `mem_wr_frm/mem_rd_frm/pk_frames` 恒 0（**A→B 方向不受影响**，板 B 只走接收硬件通路）。
> 4. **dumpcap 是硬前置**：无 dumpcap = A→B 判据做不了。需管理员装 Wireshark/Npcap，或改用内置
>    `pktmon`（同样要管理员）。非管理员环境请先回报，不要伪造判据。
> 5. **板卡身份**：本机只挂一条 JTAG 线；**不要用 `-Board Both`**（会重复烧同一块板），用
>    `-Board B -Cable <本机实测序列号>`；板子以**丝印 + 物理标签**（A/PC1、B/PC2）区分，
>    序列号不作为全局唯一标识（PC1/PC2 报回的序列号可能同值，见 EIF issue #1）。

## 0. 角色与拓扑（不成立就停）

```
PC1 ──GE2── 板A ══光纤(SFPA↔SFPA)══ 板B ──GE2── PC2
```

- 你这台只连**板 B 的 GE2**；**两板 GE2 不得接进同一台交换机**（两板同 MAC/IP）。
- 板卡地址：`192.168.1.10 / 00:11:22:33:44:55`（**两板相同**，各自独立 L2）。
- 你这台的地址：`192.168.1.102/24`（与板卡同网段）。
- **绝对不要**把 `192.168.1.10` 配到本机网卡上（那是板卡的地址，配了会冲突）。

## 1. 前置（全部只读）

```powershell
py -V
$env:PYTHONUTF8 = '1'
dumpcap -D                                   # 必须；没有就停（见修订 ④）
Get-NetAdapter | Format-Table Name,InterfaceDescription,Status,LinkSpeed,ifIndex,MacAddress -AutoSize
Get-NetIPAddress -AddressFamily IPv4 | Format-Table InterfaceAlias,IPAddress,PrefixLength -AutoSize
Get-PnpDevice -PresentOnly | Where-Object InstanceId -match 'VID_0403|VID_1A86' |
    Select-Object Status,FriendlyName,InstanceId      # 认 JTAG(0403) 与 CH340 串口(1A86)
```

**通过**：`py -V` 有版本；`dumpcap -D` 能列出网卡；接板 B 的网卡存在且 IP 为 `192.168.1.102/24`。
**网卡显示"未识别的网络"是直连的正常现象，不要用 ICS/网络桥接去"修"它。**
**网卡 Disconnected**：先查 GE2 口（修订 ①）→ 换线 → 再查速率/双工是否"自动侦测"。

## 3. 烧板 B（同一份 P1 位流）

### 3.1 A→B 方向：只烧位流即可

```powershell
# dry-run（不烧）
powershell -NoProfile -ExecutionPolicy Bypass -File out\twin_burn.ps1 -Board B
# 真烧
powershell -NoProfile -ExecutionPolicy Bypass -File out\twin_burn.ps1 -Board B -Run
```

**通过**：`BURN_BIT_OK` + `End of startup status: HIGH` + `4 ILA core(s)` + `1 MIG core(s)`。

### 3.2 B→A 方向：必须再烧 ELF 并进 DMA 模式（修订 ③）

```powershell
# 位流 + ELF 一起烧（xsct 通道；本机需 Vitis 2023.1）
powershell -NoProfile -ExecutionPolicy Bypass -File out\twin_burn.ps1 -Board B -Mode BitElf -Run
# 串口 d：进 DMA 写模式（脚本会自动处理 d 是"翻转"这件事）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\serial_dma_mode.ps1 -Com <板B的CH340 COM>
```

**判据**：日志 `BURN_OK` + `BURN_ELF_DONE`；串口 `SERIAL_RESULT: PASS` 且 banner 含 `[B2] DMAMODE now=DMA`。
**停**：本机没有 `xsct`/Vitis → **B→A 暂缓**，先只做 A→B（板 B 只走接收硬件通路，不需要 ELF）。
**停**：`-Mode BitElf` 报 `Invalid transport name` → xsct 的 URL 需要 `tcp:` 前缀（`burn_one.tcl` 已自动补齐）。

## 4. 板 B 的 ILA6（链路判据）

```powershell
$env:TEMP='C:\tmp_vivado'; $env:TMP='C:\tmp_vivado'     # 纯 ASCII
vivado -mode batch -source scripts\ila_capture.tcl -tclargs localhost:3121 <本机实测序列号> out\ila6_B.csv
py out\handoff_pc2_2026-11-06\judge_ila6.py out\ila6_B.csv --board B
# 10 分钟后再抓一次：... -Out 换 out\ila6_B_10min.csv，再 judge --prev out\ila6_B.csv
```

判据（P1-02，全要）：`dbg_ch_up=1`、`dbg_link_ok=1` 且与 ch_up 同相、`dbg_lane_up=1`、`dbg_gt_pll_lock=1`、
`dbg_aurora_rst=0`、`dbg_hard_err/dbg_soft_err=0`；10 分钟后 `ch_up_evt/hard_err_cnt/soft_err_cnt` 不增长。
未接光纤/对端没光时 `ch_up=0 / lane_up=0` 属正常，不是故障。

## 5. 静态 ARP（**必须**）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File pc\static_arp.ps1 -Apply -InterfaceAlias "<接板B的网卡名>"
Get-NetNeighbor -InterfaceAlias "<接板B的网卡名>" -IPAddress 192.168.1.10   # 必须 00-11-22-33-44-55 / Permanent
```

原因：板卡的 ARP 应答会跨光从**对端板**出去，PC2 永远收不到应答。

## 6. 抓 A→B 方向（PC1 发、你抓）

**前置**：dumpcap 可用（修订 ④）、网卡 Up、§5 ARP 已绑。

**时机**：PC1 说"开始抓"后，先起抓包（30 s 窗口），再让 PC1 发 20 帧。

```powershell
dumpcap -i <ifIndex> -f "ether src 00:11:22:33:44:55" -a duration:30 -w C:\twin\out\pc2.pcap
py C:\twin\pc\twin_recv.py --from-pcap C:\twin\out\pc2.pcap --board-mac 00:11:22:33:44:55 `
   --port 1234 --expect-count 20 --expect-len 100 --expect-run-id 0x1
```

**通过**：`twin_recv: PASS` 且 `matched ≥ 20`、`unique=20`、`dup=0`、每帧 `fill=ok`、`run_id 0x1 OK`。
**预期语义（不是故障）**：抓到的帧 `eth.dst` = **PC1 的 MAC**；PC2 的 OS 不会把帧交给应用。

| 现象 | 先判 | 回报内容 |
|---|---|---|
| `matched: 0`、`other` 也 0 | 抓包没抓到任何东西 | 网卡名/ifIndex、`dumpcap -D` 输出 |
| `matched: 0`、`other > 0` | 抓到但不是板卡发的 | 前 5 行 `twin_recv` 输出（看 src_mac/dport） |
| `matched` 少于 20 | 真丢帧 | 完整输出 + `dup`/`unique` |
| `fill BAD@n` | 内容被破坏 | 首帧 `seq/len/fill_bad_at` |

## 9. 停止条件与不做清单

**立即停并回报**：网口 Disconnected 且换 GE2/换线后仍不 Up；`dumpcap` 缺失；`channel_up` 10 min 未起；
`hard_err` 持续增长；`matched=0` 且对端 `pk_frames` 不动；板卡/模块发烫、异响、电源异常；
任何需要**改 RTL / 改位流 / 改 prj11 / 改顶层参数**才能继续的情况。

**不做**：不用 ping/单帧截图当判据；不宣称 PC↔PC 可用收发（P2）；不把 `192.168.1.10` 配到本机；
不桥接/ICS；不用 `-Board Both`（单机只有一条线）；不改脚本逻辑（发现脚本问题 → 停并回报，让 PC1 侧修）。
