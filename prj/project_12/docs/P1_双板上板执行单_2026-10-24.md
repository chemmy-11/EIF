# prj12 · P1 双板上板执行单（板卡归位后照着做）

> 对应草案 §4.2 的 P1-01～P1-06。**本单所有判据都必须上板取得**；离线脚本只保证"参数/哈希/命令正确"。
> 每步给：动作 → 命令/脚本 → 通过判据 → 失败分支。执行完把证据收进 `out/evidence_<日期>/`。

---

## 0. 前置检查（P1-00）

| 项 | 怎么查 | 通过标准 |
|---|---|---|
| 位流/ELF 就位 | `out\aurora_mem_bridge.bit`、`out\j3_soft_r2_BA3C0220.elf` | 存在；SHA256 与 `out\twin_config.json` 的 `expect_*` 一致 |
| 两板 JTAG | `out\twin_config.json` 的 `cable_serial`；Vivado Hardware Manager 的 `get_hw_targets` | 两条线缆都出现，序列号能对上 A/B |
| 两板串口 | 设备管理器 / `[System.IO.Ports.SerialPort]::GetPortNames()` | A=COM5（实测记录）、B=待填；9600 8N1 |
| 两板网口 | 各自直连 PC（不经交换机） | PC1/PC2 均为 `192.168.1.102/24` |
| 参数自洽 | `powershell -File out\twin_link_test.ps1 -Step 1 -Run` | `TWIN_LINK_RESULT: PASS`（或只剩 MANUAL） |

> `-Step 1` 会检查：位流哈希、COM 是否存在、hw_server 端口是否可达、配置占位符是否填完。

## 1. 物理连线（P1-01，MANUAL）

- 两板 **SFPA（X1Y11）↔ SFPA（X1Y11）**，LC duplex 光纤 **TX/RX 交叉**（A 的 TX 进 B 的 RX）；
- 光模块必须是 **10G SFP+**（Aurora 线速率 10G；RS0=RS1=1 高速档、tx_disable=0 已在 RTL 固定）；
- 两板各自 156.25 MHz refclk（板载晶振，不同源——P1 的重点就是看它稳不稳）；
- 两板 GE1 各接自己那台 PC；两板 USB-JTAG 与串口都插上。

**通过判据**：两板均能被 Vivado 识别到 `xc7a100t`(JTAG 调试器) 与 `xcku060`；串口能收到板卡复位后的打印。
**失败分支**：模块灯不亮 → 查 tx_disable/供电；Vivado 只看到一个 target → 查 USB 线/驱动（Digilent）。

## 2. 烧录（P1-02 前半）

```powershell
# 先 dry-run 看计划（不烧）
powershell -NoProfile -ExecutionPolicy Bypass -File out\twin_burn.ps1 -Board Both
# 真烧（P1 只需要位流；ELF 用于串口控制台）
powershell -NoProfile -ExecutionPolicy Bypass -File out\twin_burn.ps1 -Board Both -Run
# 需要软核控制台时：
powershell -NoProfile -ExecutionPolicy Bypass -File out\twin_burn.ps1 -Board Both -Mode BitElf -Run
```

**通过判据**：每块板日志里出现 `BURN_BIT_OK`（Vivado 通道）或 `BURN_OK`（xsct 通道）；Vivado 显示 `End of startup status: HIGH`。
**失败分支**：`cable selection ambiguous` → `cable_serial` 填错/两块板序列号没填；`program_hw_devices` 失败 → 查 JTAG 频率/电源。

> 两板烧**同一份位流**（P1 设计如此：同 IP/MAC，各自独立 L2）。

## 3. 链路判据（P1-02，核心）

```powershell
# 立即抓一帧 ILA6（单核链路健康）
vivado -mode batch -source scripts\ila_capture.tcl -tclargs localhost:3121 210512180081 out\ila6_A.csv
# 若要等 hard_err 再抓
vivado -mode batch -source scripts\ila_capture.tcl -tclargs localhost:3121 210512180081 out\ila6_A_err.csv probe1[0]
```

| 观测 | 通过标准 | 说明 |
|---|---|---|
| `u_ila_6.probe0[1]` channel_up | **=1** | P1 硬前提 |
| `u_ila_6.probe0[0]` link_ok | =1，且与 channel_up 同相 | 同相 = P0-02 补丁生效 |
| `u_ila_6.probe0[2]` lane_up | =1 | 4 lane 全 up |
| `u_ila_6.probe0[3]` gt_pll_lock | =1 | 不锁 → 先查 refclk/模块 |
| `u_ila_6.probe9` aurora_rst | =0 | 链路起来后数据通路必须已出复位 |
| `u_ila_6.probe1` hard_err/soft_err | 不出现 | — |
| `u_ila_6.probe3/probe4` 计数 | 10 min 不增长 | 两板独立晶振的稳定性判据 |
| LED T23 | 常亮 | 旁证（= link_ok） |

**失败分支**：`channel_up=0` → 模块/光纤/极性/refclk；`channel_up=1 但 link_ok=0` → **漏打 P0-02**（本工程位流不该出现）；`hard_err` 增长 → 换模块/板，记录两板模块型号。

## 4. 数据面可见（P1-03 / P1-04）

**PC1 发**：
```powershell
py pc\twin_send.py --dst-ip 192.168.1.10 --dst-port 1234 --count 20 --len 100
```
**PC2 抓 + 判**：
```powershell
dumpcap -i <ifIndex> -f "ether src 00:11:22:33:44:55" -a duration:30 -w out\pc2.pcap
py pc\twin_recv.py --from-pcap out\pc2.pcap --board-mac 00:11:22:33:44:55 --port 1234 --expect-count 20
```

**通过判据**：`matched ≥ 20`、`seq 0..19 唯一`、`fill` 全 ok；同时 ILA6 `probe5`（进 A 核 TX 帧数）按帧数递增。
**预期语义（不是故障）**：PC2 抓到的帧 **eth.dst = PC1 的 MAC**，PC1 本机收不到回包；`eth.dst != PC2 MAC` 属正常。

| 现象 | 先看哪 | 结论 |
|---|---|---|
| PC2 一帧没有 | `probe5` 动不动 | 不动 → 本板没往 Aurora 发（栈/泵/桥）；动 → 对端 RX→mem2→eth 段 |
| 帧数对但内容错 | `twin_recv` 的 `fill BAD@n` | 定位到第几个字节开始错（打包/解包/搬运） |
| 只收到部分 | `probe5` vs `probe6` 差值 | 差值 = 丢在链路或对端 |

**反向（P1-04）**：角色对调，`--run-id` 换值，PC1 抓。判据同上。

## 5. 断电/复位恢复（P1-05，MANUAL）

两板断电 10 s → 上电 → 30 s 内重跑第 3 步。
**通过判据**：`channel_up=1` 自动恢复；`probe2/probe3/probe4` 清零后不增长；无永久卡死。

## 7. 失败即停的边界

- 任何一步判据没过，**不要**继续下一步（尤其不要用 PC 侧"抓到一帧"替代 `channel_up`）；
- 不要用仿真替代链路判据；
- 板上现象与本文冲突时，先记原始日志/波形，再改文档。
