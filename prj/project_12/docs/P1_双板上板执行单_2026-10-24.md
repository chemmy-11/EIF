# prj12 · P1 双板上板执行单（板卡归位后照着做）

> 对应草案 §4.2 的 P1-01～P1-06。**本单所有判据都必须上板取得**；离线脚本只保证"参数/哈希/命令正确"。
> 每步给：动作 → 命令/脚本 → 通过判据 → 失败分支。执行完把证据收进 `out/evidence_<日期>/`。
> **口径提醒**：本单验的是 P1 = **链路 + 数据面"可见"**。"PC2 应用收到包"属 P2，本单不做承诺。

## 0. 前置检查（P1-00）

| 项 | 怎么查 | 通过标准 |
|---|---|---|

## 1. 物理连线（P1-01，MANUAL）

- 两板 **SFPA（X1Y11）↔ SFPA（X1Y11）**，LC duplex 光纤 **TX/RX 交叉**（A 的 TX 进 B 的 RX）；
- 光模块必须是 **10G SFP+**（Aurora 线速率 10G；`sfp_tx_disable=0`、`rs0=rs1=1` 已在 RTL 固定）；
- 两板各自 156.25 MHz refclk（板载晶振，不同源——P1 的重点就是看它稳不稳）；
- 两板 GE1 各接自己那台 PC；两板 USB-JTAG 与串口都插上；**两板不得接进同一台交换机**（同 MAC/IP）。

**通过判据**：两板都能被识别（§0.1）；串口能收到板卡复位后的打印。
**失败分支**：模块灯不亮 → 查 tx_disable/供电；只识别一块 → 查 USB 线/驱动。

## 3. 链路判据（P1-02，核心）

```powershell
# 立即抓一帧 ILA6（单核链路健康）
vivado -mode batch -source scripts\ila_capture.tcl -tclargs localhost:3121 210512180081 out\ila6_A.csv
# 等 hard_err 上升再抓
vivado -mode batch -source scripts\ila_capture.tcl -tclargs localhost:3121 210512180081 out\ila6_A_err.csv probe1[0]
```

| 观测 | 通过标准 | 说明 |
|---|---|---|
| `u_ila_6.probe0[1]` channel_up | **=1** | P1 硬前提 |
| `u_ila_6.probe0[0]` link_ok | =1，且与 channel_up 同相 | 同相 = P0-02 补丁生效 |
| `u_ila_6.probe0[2]` lane_up | =1 | 4 lane 全 up |
| `u_ila_6.probe0[3]` gt_pll_lock | =1 | 不锁 → 查 refclk/模块；**也见下方共享 QPLL 分支** |
| `u_ila_6.probe9` aurora_rst | =0 | 链路起来后数据通路必须已出复位 |
| `u_ila_6.probe1` hard_err/soft_err | 不出现 | — |
| `u_ila_6.probe3/probe4` 计数 | 10 min 不增长 | 两板独立晶振的稳定性判据 |
| LED T23 | 常亮 | 旁证（= link_ok） |

**失败分支**（按顺序，别跳）：

1. `gt_pll_lock=0` 且 `channel_up=0` → 查两板 refclk/模块；**另注意 `u_aurora_b` 是 `_support_shared`，与 A 核共享同一 QPLL**
   （`rtl/aurora_mem_bridge.v:489`），B 核复位链异常也会拖住 QPLL → 看 `gt_pll_lock` 是否一直为 0。
2. `gt_pll_lock=1` 但 `lane_up=0` → 光纤/极性（TX↔RX）/模块速率档（RS0=RS1=1）。
3. `channel_up=1` 但 `link_ok=0` → **漏打 P0-02 或烧了旧位流**（本工程位流不该出现）。
4. `hard_err` 增长 → 换模块/板，记录两板模块型号与 SN（进 `hardware_inventory`）。
5. 以上都对但 `aurora_rst` 一直为 1 → 查 `sys_rst_n`（复位按键/AC34）。

### 3.1 串口快照（可选，需要 ELF）

## 4. 数据面可见（P1-03 / P1-04）

```powershell
# PC1：先确认邻居表已绑（§4.1），再发
py pc\twin_send.py --dst-ip 192.168.1.10 --dst-port 1234 --count 20 --len 100
# PC2：抓 → 判
dumpcap -i <ifIndex> -f "ether src 00:11:22:33:44:55" -a duration:30 -w out\pc2.pcap
py pc\twin_recv.py --from-pcap out\pc2.pcap --board-mac 00:11:22:33:44:55 --port 1234 --expect-count 20
```

**通过判据**：`matched ≥ 20`、`seq 0..19 唯一`、`fill` 全 ok；同时 ILA6 `probe5`（进 A 核 TX 帧数）按帧数递增。
**预期语义（不是故障）**：PC2 抓到的帧 **eth.dst = PC1 的 MAC**，PC1 本机收不到回包；`eth.dst != PC2 MAC` 属正常。

| 现象 | 先看哪 | 结论 |
|---|---|---|
| PC1 的 `sendto` 直接报错/`FAIL: send error` | 邻居表 | 没绑静态 ARP（见 §4.1） |
| PC2 一帧没有 | `probe5` 动不动 | 不动 → 本板没往 Aurora 发（栈/泵/桥）；动 → 对端 RX→mem2→eth 段 |
| 帧数对但内容错 | `twin_recv` 的 `fill BAD@n` | 定位到第几个字节开始错（打包/解包/搬运） |
| 只收到部分 | `probe5` vs `probe6` 差值 | 差值 = 丢在链路或对端 |

**反向（P1-04）**：角色对调，`--run-id` 换值，PC1 抓。判据同上。

### 4.1 为什么静态 ARP 是**必须**的（不是"推荐"）

- `eth_ctrl` 把 **ARP / ICMP / UDP 的 TX 全汇成一路** `gmii_txd` → `stack_txd`（`rtl/eth_ctrl.v:163-177`），
  而 `stack_txd` 直接进泵A（`rtl/aurora_mem_bridge.v:657` 端口连接、`:808` `.wr_data`），
  也就是**板卡的 ARP 应答也跨光去了对端板**。
- 结果：PC1 发 ARP 请求 → 板 A 的应答从**板 B** 的网口出去（目的=PC1）→ **PC1 收不到** → ARP 解析失败 →
  `sendto()` 在 OS 层就发不出去（"目的主机不可达"）。
- 同理：**`ping 192.168.1.10` 在 P1 一定不通**（ICMP 应答走同一条路）。**不要把 ping 当健康检查**，
  链路用 ILA `channel_up` + LED T23。
- 唯一本地直出的是 **W5 命令通道应答**（端口 1235，泵B末级 `cmd_takeover` 注入，`:1303-1305`），
  它需要"发往广播 IP + magic"的专用格式，不在本单判据内。

## 7. 失败判别树（channel_up=0 的 5 分钟）

| 顺序 | 看什么 | 若是 | 下一步 |
|---|---|---|---|
| 1 | LED T23 灭？ | 是 | 继续 2 |
| 2 | 模块灯/模块是否插到位 | 否 | 换模块/重插，回 2 |
| 3 | `gt_pll_lock` | 0 | 查两板 refclk/晶振；注意 B 核共享 QPLL（§3 分支 1） |
| 4 | `lane_up` | 0 | 光纤 TX/RX 交叉、极性、模块速率档 |
| 5 | `channel_up` | 1 而 `link_ok` 0 | 漏打 P0-02 / 旧位流 |
| 6 | `hard_err` 增长 | 是 | 换模块/板，记录 SN；稳定后复测 10 min |

## 8. 边界

- 任何一步判据没过，**不要**继续下一步（尤其不要用 PC 侧"抓到一帧"替代 `channel_up`）；
- **不要用 ping / 单帧截图当判据**（P1 语义下 ping 必不通；单帧不构成 0 丢证据）；
- 不要用仿真替代链路判据；
- 板上现象与本文冲突时，先记原始日志/波形，再改文档。
