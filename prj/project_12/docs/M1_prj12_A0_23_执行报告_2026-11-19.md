## 2. 基线臂实测记录

### 2.1 第 1 次：空闲时拔插 ~5–10 s

- 闪断前：`wr=0 rd=0 drop=0`（刚烧完的干净零点），链路全绿。
- 闪断后（17:53:11 ILA）：`ch_up/lane_up/pll=1`、`aurora_rst=0`；**用户域计数全 0**（被 aurora_rst 清零）。
- 不重烧发 3 帧（`run 0x3A0`，17:53:26）：
  - 串口 `wr=3 rd=3 drop=0`
  - ILA：`pfwd_wr=3 / pk_frames=3 / mem_wr_frm=3 / mem_rd_frm=3`，`mem_stall=0`、`mem_len_err=0`
- **判定：恢复 → INCONCLUSIVE**（空闲 FIFO 指针本就对齐，复位只是清一遍）。
- 备注：`dbg_ch_up_evt` 在 `aurora_rst` 期间被清零，**=0 不能证明未发生闪断**；闪断时刻以负责人确认为准。

### 2.2 第 2 次：**持续流量中**拔插 ~10 s（触发条件更正）

- 触发条件更正：闪断必须发生在**有帧穿越**时，FIFO 指针才可能错位。
- 流量：`run 0x3B0`，len=100 @75 ms，2400 帧（A→B，PC1 侧板持续转发）。
- 现象：闪断期间串口**无响应**（固件 `serve_any()` 饱和），停流后恢复 → 非死锁。
- 闪断后（17:55:11 ILA）：`ch_up/lane_up/pll=1`、`aurora_rst=0`；`pfwd_wr=0x00F5=245`、`pk_frames=0x00F7=247`
  ⇒ **用户域计数被清零后重新累积，说明板子在闪断后自行恢复转发**。
- 不重烧发 3 帧（`run 0x3A1`，17:55:37）：串口 `wr 434→437`、`rd 436→439` = **+3**。
- ILA（17:56:11）：`pfwd_wr=437 / pk_frames=439 / mem_wr_frm=695 / mem_rd_frm=695`、`mem_stall=0`、
  **`mem_len_err = 0007`（非零！）**。
- **判定：恢复 → INCONCLUSIVE**。
- **新发现**：`mem_len_err=7` 是今日首次出现的非零长度错误计数 ⇒ 闪断确实在数据面留下 7 帧长度异常，
  但**未导致死锁**。此项应纳入"闪断后数据完整性"的后续观测。

### 2.3 第 3 次：持续流量中拔插 ~30 s（加长重做）

- 流量：`run 0x3B1`，len=100 @60 ms，4000 帧（A→B）。
- 闪断发生判据：用户域计数被清零后重新累积 —— `pfwd_wr` 从 17:56:11 的 **437** 降到 17:57:53 的 **183**（清零后重新计入），链路回到 `ch_up/lane_up/pll=1`、`aurora_rst=0`。
- 串口在 17:56:48–17:57:33 连续 6 次无响应（闪断 + 恢复瞬间 `serve_any()` 饱和），停流后恢复。
- 停流、**等 30 s**、**不重烧**、发 3 帧（`run 0x3A2`，17:58:37）：串口 `wr 354 → 357` = **+3**。
- ILA（17:59:06）：`pfwd_wr=357 / pk_frames=354`；`mem_wr_frm=mem_rd_frm=0x537=1335`；`mem_stall=0`；**`mem_len_err = 0007`（保持）**；链路全绿。
- **判定：恢复 → INCONCLUSIVE**（第三次）。
