## 2. 基线臂实测记录

### 2.2 第 2 次：**持续流量中**拔插 ~10 s（触发条件更正）

- 触发条件更正：闪断必须发生在**有帧穿越**时，FIFO 指针才可能错位。
- 流量：`run 0x3B0`，len=100 @75 ms，2400 帧（A→B，PC1 侧板持续转发）。
- 现象：闪断期间串口**无响应**（固件 `serve_any()` 饱和），停流后恢复 → 非死锁。
- 闪断后（17:55:11 ILA）：`ch_up/lane_up/pll=1`、`aurora_rst=0`；`pfwd_wr=0x00F5=245`、`pk_frames=0x00F7=247`
  ⇒ **用户域计数被清零后重新累积，说明板子在闪断后自行恢复转发**。
- 不重烧发 3 帧（`run 0x3A1`，17:55:37）：串口 `wr 434→437`、`rd 436→439` = **+3**。
- ILA（17:56:11）：`pfwd_wr=437 / pk_frames=439 / mem_wr_frm=695 / mem_rd_frm=695`、`mem_stall=0`、
  **`mem_len_err = 0007`（非零！）**。
- **判定：恢复 → INCONCLUSIVE**。
- **新发现**：`mem_len_err=7` 是今日首次出现的非零长度错误计数 ⇒ 闪断确实在数据面留下 7 帧长度异常，
  但**未导致死锁**。此项应纳入"闪断后数据完整性"的后续观测。

### 2.3 第 3 次：持续流量中拔插 ~30 s（加长重做）

- **判定：恢复 → INCONCLUSIVE**（第三次）。

### 2.6 **触发条件更正：饱和流量下基线死锁复现（决定性）**

**前三节（2.1–2.3）的"未复现"是测试条件错误，不是缺陷不存在。**

依据 `evidence_2026-11-07_dma_stall/README.md`：
- `frame_mem_if.v:305` `byte_room_ok = (wr_level <= 2558)`，闪断后 **Q∈[1,5633]（≈69%）→ 硬死锁**；**Q=0 则无事**。
- 原文："本设计一旦成功传过几千字节，之后任何一次 Aurora 闪断都会把它推进'硬死锁或静默错位'二选一，都不可能自愈。"

前三次用的是 `len=100 @75/60 ms`，每帧只占 FIFO ≈1 µs，占空比 ≈0.002% ⇒ **闪断几乎必然落在空 FIFO（Q=0）**，因此"安然无恙"。

**改正后（第 4 次）**：背靠背饱和流量 `len=100 @0 ms`、4×40000 帧，使 FIFO 持续非空，再拔光纤 ~10 s：

| 计数 | 闪断前（稀疏流量） | **饱和流量闪断后（18:01:45 / 18:03:16）** |
|---|---|---|
| `dbg_pfwd_wr` | 3 | **3**（帧进了泵） |
| `dbg_pk_frames` | 3 | **0**（未打包、未上 Aurora） |
| `dbg_mem_wr_frm` | 3 | **0x1771 = 6001 停住不动** |
| `dbg_mem_u_drop` | 0 | **3**（全被写引擎丢弃） |
| 链路 | 全绿 | **全绿（ch_up/lane_up/pll=1、aurora_rst=0）** |

- 串口：`wr=0 rd=0 drop=3`（3 帧全部丢弃，`wr` 不增长）。
- **结论：基线硬死锁复现** —— 帧进得去、出不来；链路健康但数据面不恢复。
  指纹与 DSR 的 `wr_hold` 粘滞一致。

### 2.7 恢复阶梯（在死锁态上实测，PC1 侧板）

| 阶梯 | 操作 | 结果 |
|---|---|---|
| 1 | `d` 翻转 | **无效**：`pk_frames` 仍 0、`mem_wr_frm` 仍 6001、`mem_u_drop` 保持 3 |
| 2 | `rst -processor` + `dow` + `con` + `d` | **无效**：发 3 帧后 `drop` 3→6，`wr` 仍 0 |

- 与 DSR 结论一致：**`d` 无效、只有整板重配置能清 ui 域指针**。
- 重烧耗时实测 **16 s**（DSR 记 60–90 s，本机更快）。

### 2.8 基线臂判定

**基线臂 = 缺陷复现成立（baseline deadlocks）**。这与执行卡"基线预期卡死"一致，因此后续 **B1 臂的对照才有意义**：
