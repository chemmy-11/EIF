## 二、证据一：现有归档**没有任何** AXI 握手探针（⇒ 无法离线量取）

### 2.1 全仓库探针归档扫描（不区分大小写）

```bash
rg -i '(awvalid|bvalid|arvalid|rvalid|awready|arready|bready|rready)' D:/FPGA/prj -g '*.ltx'
→ 0 命中
```

范围内含 prj10 的全部 6 份归档探针（`w5_cursor_fixed_2026-10-08` / `w5_runt_fixed_2026-10-08` / `w5_timing_ok_2026-10-08_WNS+0.001` / `w6_l1_pingpong_2026-10-09` / `w6_l2_pipeline_2026-10-09` / `scripts/probes.ltx`），以及 prj4 的 MIG 位流探针、prj8 / prj9 的判决位流探针。**一个握手信号都没有。**

### 2.2 ui_clk 域 ILA3 的探针全表（`build_debug.tcl` L192–218）

实测 **14 项 / 179 bit**（算式 1 + 16×9 + 9 + 8 + 8 + 9 = 179）：

| 探针 | 宽度 | 语义 |
|---|---|---|
| `dbg_calib` | 1 | MIG 校准完成 |
| `dbg_mem_wm` / `dbg_mem_wr_frm` / `dbg_mem_rd_frm` | 16×3 | 帧级计数 |
| `dbg_mem_stall` / `dbg_mem_len_err` / `dbg_mem_bresp` | 16×3 | 错误 / 停等计数 |
| `dbg_mem_ost` | 9 | **帧级**在途（已提交未读出的帧数），**不是 AXI outstanding** |
| `dbg_mem_wslot` / `dbg_mem_rslot` | 8×2 | 槽指针 |
| `dbg_mem2_wm` / `dbg_mem2_wr_frm` / `dbg_mem2_rd_frm` / `dbg_mem2_ost` | 16×3+9 | 桥②同族 |

**全部是计数器与状态量，没有一条 `m_axi_*valid` / `*ready`。**

### 2.3 为什么当时没挂（原始注释为证，`build_debug.tcl` L203–211）

```tcl
# ---- W5: 非法读/无帧计数 + 读写突发数（J5 对账与可观测性）----
# ⚠️ 2026-10-07 实测: 这 96 bit 加在 300MHz 的 ILA3 上会把 ui 域推向拥塞
#    （WNS -0.041 → -1.142, 4040 端点失败, 平均缺口仅 0.27ns = 典型拥塞特征）。
# foreach n [bus_nets dbg_mem_ill     16] { lappend nets3 $n }
# foreach n [bus_nets dbg_mem_nofrm   16] { lappend nets3 $n }
# foreach n [bus_nets dbg_mem_wbeats  32] { lappend nets3 $n }
# foreach n [bus_nets dbg_mem_rbeats  32] { lappend nets3 $n }
```

即：当时**连「每帧突发数」这种纯计数器都不敢挂在 ui_clk 域**（挂 96 bit 即 WNS −1.142），更不必说握手信号。
桥 RTL 侧端口是齐的（`axi4_master_bridge.v` L112 / L120 / L126 / L131：`m_axi_awvalid` / `m_axi_bvalid` / `m_axi_arvalid` / `m_axi_rvalid`），**只是从未引出到探针**。

> ⇒ **「现有 ILA 波形可离线量取 Lw/Lr」不成立。**

## 四、能回填什么：三档可靠度，按需取用

> 说明：本节的区分很关键 —— **只有 4.1 / 4.2 是无条件成立的**；4.3 有未证实的前提；4.4 是已作废的路径；4.5 只是相容性旁证。

### 4.1 【可靠】Lr 无实测；读路径在 1466 B 工况下不是瓶颈（定性）

- RND 判别（10-09 上板）：关掉整条读路径与二级桥后速率几乎不变（**26,365 vs 26,500 fps**，差 0.5%）⇒ 该工况下**瓶颈不在读路径**；
- 但这只说明「Lr 不构成约束」，**不能给 Lr 定值**；
- ⇒ 体检报告 §3.2 的 **Lw=200 / Lr=250 仍然只是假设**，引用时必须带「假设」二字，不得写成实测。

### 4.2 【可靠但松】无条件粗上界：Lw < 37.7 µs ≈ 11,300 拍

- 预 L2 的闸门饱和实测：1466 B 时 **26,500 fps = 37.7 µs/帧**；该点报价 pace=20 µs（= 50k fps）**高于**实测值 ⇒ 是**板卡限制**，不是 PC 限速；
- 该时期桥写 FSM **每帧串行等一次 BVALID**（10-09 记录 §二⑤ 原文：`W_PUSH→W_B(等bvalid)→提交→W_IDLE`），且 RND 判别把范围锁定在写路径；
- ⇒ 写路径每帧总耗时 37.7 µs **必然包含** Lw ⇒ **Lw < 37.7 µs ≈ 11,300 拍**；
- 用途：**只用于废掉更大的数**（松到 30× 量级，不能当设计输入）。

### 4.3 【条件性·前提未证实】Lw ≤ 7.0 µs ≈ 2100 拍

- 若那个「写路径每帧固定项 ≈7.0 µs」确实测于**每帧串行等 BVALID** 的时期，则可推出 Lw ≤ 7.0 µs；
- **但记录无法证实该前提**：10-09 的 L2 已把写路径流水化（4 深提交队列、同 ID 多笔 outstanding），而给出「7/24 µs」的 §三·补 正是 **L2 评估语境**下写的 —— 那个 7.0 µs 里 Lw 是否仍逐帧暴露，**记录没有交代**；
- 反证方向同样存在：若 Lw 真达 6000 拍（20 µs），L2 把它藏进流水线后 1466 B 应当大涨，但实测 **26,500 → 25,900 fps（噪声内）** ⇒ 两种读法互相矛盾；
- ⇒ **标为条件性上界**：可用于量级判断，**不得当设计输入**；解开它只能靠 §六 的实测。

### 4.4 【已作废】用「帧率上限」反推 Lw

- L2 之后写路径有 **4 深提交队列**，Lw 被主动藏进流水线 —— 这正是 L2 的目的；
- 副作用：仿真里 933→931 拍几乎不动（TB 的 Lw≈2），**帧率上限里再也挤不出 Lw**；
- ⇒ 在 L2 版位流（终版 `DBE35734…017F`）上用吞吐反推 Lw/Lr 的方法**失效**，必须直接探握手。

### 4.5 【旁证，非测量】帧周期预算与实测零丢帧相容

- 帧周期预算 3690 拍（12.30 µs）；1466 B 的两级桥数据 / 节拍项 T_w+T_r = 3055 拍（Lw=Lr=0 时：写 1466+3×23+4、读 1466+2×23+4）；
- 实测 1466 B **82.67k fps 零丢帧** = 12.10 µs/帧 = 3630 拍，且该点已是**线速口径**（千兆 1466 B 理论上限 81.27k fps）⇒ 板卡至少这么快；
- ⇒ 若 09-29 的「每帧串行」模型成立，可得 **Lw+Lr ≤ 575 拍 ≈ 1.92 µs**（按 12.30 µs 口径为 ≤635 拍，与体检报告 §3.2 的「636 拍即破坏节拍」同源）；
- ⚠️ 该式**只在「不流水、每帧串行」模型下成立**，而 L2 版已不满足 ⇒ **只能当「假设与实测不矛盾」的旁证，不得当测量结果**。

## 五、结论

1. **② 的「离线回填」路径不存在**：全仓库 0 个握手探针，且当时连纯计数器都挂不上 ui_clk 域（`build_debug.tcl` 注释为证）。
2. **现阶段没有任何可当设计输入的 Lw / Lr 数值**：可用的只有 4.2 的无条件粗上界（Lw < 37.7 µs）、4.3 的条件性上界（Lw ≤ 7.0 µs，前提未证实）与 4.1 的「Lr 无实测」。设计点（单桥 5.80 µs / 两级串行 11.68 µs / 裕量 1.05×）**继续挂「假设」标签**。
3. **引用「真机 Lw≈6000 拍」的写法必须废止**（该数 = 已作废的 20.3 µs 假象）。
4. ② 是 **B3（数据面换 AXI DMA）的硬阻断**（W5 验证单原文），而 **prj10 已冻结只读** ⇒ 只能在 **prj11** 侧排期，且**属上板动作**，不是文档工。

方案甲落地（prj11 B3-0：桥内 `lat_w/lat_r` 计数器 + UDP `GET_LATENCY(0x05)` 回读；

| 量 | min | 中位 | max | 换算（中位 / max，×3.332 ns）|
|---|---|---|---|---|
| **Lw**（AW→B 出队）| 97 拍 | **97 拍** | 246 拍 | **0.32 µs / 0.82 µs** |
| **Lr**（AR→首个 R）| 19 拍 | **23 拍** | 160 拍 | **0.08 µs / 0.53 µs** |

**核对 §四 的两条上界**：Lw max = 246 拍 **同时**满足 ① 粗上界 < 11,300 拍 与

## 六、下次上板的低开销测法（二选一，推荐甲）

### 方案甲（推荐）· 寄存器回读，不占 ILA 位

| 项 | 内容 |
|---|---|
| 落点 | `axi4_master_bridge.v` 内加两个 16 bit 计数器：`lat_w`（`awvalid&&awready` → 首个 `bvalid` 的拍数）、`lat_r`（`arvalid&&arready` → 首个 `rvalid`）；可选再加 min / max / 累加+次数 |
| 回读 | 走 W5 命令通道扩一条 **`GET_LATENCY`**（`0x01–0x04` 已占用，**`0x05` 空闲**），PC 侧脚本直接打印，不需要 ILA 会话 |
| 为什么这么选 | ui_clk 域**加 96 bit 纯计数器都会 WNS −1.142**（有实测），寄存器路径只增极浅逻辑；构建脚本已有 **WNS≥0 门限**自动把关（不达标不写位流）|
| 判据 | 连续 N≥100 帧，Lw / Lr 拍数分布稳定（min / 中位 / max），换算 **µs = 拍 × 3.332 ns**；再与 4.2 的粗上界（<11,300 拍）与 4.3 的条件性上界（≤2100 拍）做一致性核对 —— 这同时能判定 4.3 的前提是否成立 |
| 工时 | RTL 约 80 行 + 单元 TB（正负对照）+ 回读脚本 ≈ 0.5 天；上板 1 场 |

### 方案乙 · 新建 ILA 探针（仅在 prj11 内做）

- 挂 `m_axi_awvalid/awready/bvalid` 与 `arvalid/arready/rvalid`（6 bit），触发条件 `awvalid&&awready`，深度 2048；
- 必须先加 `C_INPUT_PIPE_STAGES 1`（10-09 用此法把 WNS −0.235 救回，属常规手段）；
- 代价：多一次构建 + 一次 ILA 会话；收益：能看到单笔事务波形，W/B 与 AR/R 两条路径可同时量。

### 排期约束

- prj10 冻结只读 ⇒ 改动只能落在 **prj11**；
- **prj11 的 B0 首次构建此刻仍在跑**（2026-10-10 14:40 四个 ILA 的 OOC 综合在动），**B1 依赖其全绿**；本项**不得与 B1 抢 Vivado**（会话与综合 / 实现 / 仿真全局串行）；
- 建议排 **B1 场次之后、B3 之前**（② 本来就是 B3 的硬阻断）。
