## 命名规范（2026-10-26 终案）

文件名 `[阶段]_prj标识_概要_YYYY-MM-DD.md`；跨目录引用加 `cross` 前缀；日期取文件头 `created` 字段；重命名文件 frontmatter 加 `alias` 保旧链接可达（**alias 一律写 YAML 列表**，如 `alias: [旧名A, 旧名B]`，注记放正文不塞字段）。豁免：`README.md`、`agent.md`、导师原件（`GSnFPipe_*_v1.0` 等保持原样）、非 Markdown 数据文件。

**阶段段两轴**（2026-10-26 定案）：
- **历史轴**（单板时代，封存）：`阶段一` / `阶段二之N` / `阶段二前置` / `阶段三`——`阶段三` 封存为 prj10/11 历史专属；
- **M 轴**（GSnFPipe 双板时代，prj12 起新文档一律用此轴；唯一例外 = 已存在的 `阶段三_prj12_双板互联开工草案_2026-10-24.md` 不改名，以 frontmatter `里程碑: M1` 标注）：`M<N>_<prj标识>_概要_YYYY-MM-DD.md`，N=导师方案里程碑 1–4；prj标识 ∈ `prj12`（工程件）/ `GSnFPipe`（联合件）。M1–M4 不进无里程碑文档的文件名（对齐/工具链/横切类不挂 M 前缀）。

**无阶段类型（12 种）**：`前置` · `参考` · `里程碑` · `汇报` · `规划` · `追踪` · `结论` · `架构` · `导览` · `复现`（复现指南 → `复现/`）· `任务书`（照着做类 → `操作文档/`）· `对齐`（面向导师的对齐包，目录级约定 `对齐_<对象>_日期/00~06_编号.md`）。其中 `任务书`/`对齐` 为 2026-10-26 登记的实际在用类型，`导览` 为 2026-10-01 新增。

**存放规则（两类分开放）**：

| 判据 | 放哪 | 典型文件名关键词 |
|---|---|---|
| **读它是为了"照着做"**（步骤/规格/判据设计/清单/工具用法） | `操作文档/` | 实操单 · 实施单 · 开工草案 · 验证单 · 作战卡 · **任务书** · **参考** |
| **读它是为了"看结果/看证据"**（做完之后的记录与结论） | `调试记录/` | 调试记录 · 执行记录 · 测试报告 · 复现记录 · **结论** |

混合型以主导内容归类。**根目录只放入口与现行件**（README / agent / 规划 / 退役追踪）；完结的类型化文档按上表归位（2026-10-26 已执行首轮归位）。
跨目录引用按新路径写；移动文件时**必须同步修正全库引用**（坑 #46）；基名式 `[[wikilink]]` 移动后仍可解析，路径式引用才是修改对象。
**先定仓再定名**：B 组或导师要看的（协同/验收/实验结果/论文图）→ 交付仓 `D:\GSnFPipe-FPGA-PP`（守其 `CONTRIBUTING.md`）；只有工程侧看的 → 本库。
