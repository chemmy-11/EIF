## 4. 光链路：载板、GT、Aurora

| ID | 陈述 | 证据 | 来源/复核动作 |
|---|---|---|---|
| `F-22` | **光口载板**：实验室板的 4 个 SFP+ 口在 **FMC 四光口子卡**上（SFPA~SFPD，非底板板载）；子卡曾经历改版（改动内容与版本号未记录）；**两板配置相同已确认（`F-02`），子卡改版号仍以实物照片核对** | `[手册]` + `[工程]` | 板卡手册第 56 章笔记（明记"实验室板为 FMC 四光口子卡版"）；`U-03` |
| `F-23` | **GT 资源**：KU060 共 32 个 GTH（8 Quad × 4 通道）；本板四个 SFP 口**共用同一个 Quad**：Bank 226 = Quad X1Y2 | `[手册]` + `[工程]` | 板卡手册第 56 章；Vivado IBERT 实测（选 QUAD_226 后通道落位 X1Y8~Y11） |
| `F-24` | **SFP → GT 通道映射**：SFPA = `GTHE3_CHANNEL_X1Y11`；SFPB = `X1Y9`；SFPC = `X1Y10`；SFPD = `X1Y8`。引脚表另注通道号：SFPD=TX0、SFPB=TX1、SFPC=TX2、SFPA=TX3 | `[工程]` | 板卡引脚表 + Vivado 器件数据库反查 |
| `F-25` | **GT 参考时钟**：工程 XDC/注释记录为 **MGTREFCLK1_226 = `T6/T5`、156.25 MHz**（prj7–11 一致，注释称"IBERT 实测定版"）；早期引脚表（`KU引脚表.xlsx` 工作表 + Vivado 器件数据库反查）记录为 **`P6/P5`**（该 Quad 的另一路 refclk 选 `M5/M6`）。**两项来源冲突，尚未在板②复核**；频率 156.25 MHz 两处一致 | `[工程]` | `D:\FPGA\prj\project_11\xdc\aurora_mem_bridge.xdc` 注释；`参考_cross_FMC_4SFP_GTH引脚表`；关闭方式见 `U-04` |
| `F-26` | **SFP 控制脚**：`TX_DIS` 低电平使能；`RS0/RS1` 高电平选择 >4.25 Gbps 速率（10G 时两脚均高）；电平 LVCMOS33。引脚表存在**两个版本**（工作表1 vs 副本），当前 XDC 使用"VERSION A"；子卡改版后映射可能变化 | `[工程]` + `[手册]` | 操作文档中 VERSION A XDC；`D-05` |
| `F-27` | **Aurora IP 实例参数**：`aurora_64b66b_v12_0_13`（Vivado 2023.1），`c_aurora_lanes=1`、`c_line_rate=10.0`（Gbps）、`c_gt_type=GTHE3`、`interface_mode=Framing`、`dataflow_config=Duplex`；用户接口 64-bit AXIS | `[工程]` | IP 生成文件头部；`R-07` |
| `F-28` | **时钟换算**：64B/66B 下 `user_clk = line_rate / 66`，10.0 Gbps → **≈151.5 MHz**；参考时钟 156.25 MHz（×64 = 10.0 Gbps 线速率） | `[推断]` + `[工程]` | 与工程注释一致；官方时钟架构见 `R-01` |
| `F-29` | **RX 方向无 `tready`**：Aurora 64B/66B 用户接口的 `m_axi_rx_*` 没有反压信号，消费者必须每拍都能接；否则静默丢数。**这是方向性硬约束** | `[工程]` | IP 端口表 + IP 源码（`ll_to_axi`/`_core` 内部接 0）逐行核对；**官方 PG074 正文未给出该语义**（SPA 渲染），见 `R-07` |
| `F-30` | **`tkeep` 语义**：本 IP 的 `tkeep` 在末拍为 **MSB 对齐**（有效字节在高位 lane，`tkeep = ~(0xFF >> N)`），与多数 Xilinx AXIS IP（低位对齐）相反；中间拍恒 `0xFF`；`tlast` 每帧恰好一次；帧长任意（官方 `R-06`/`R-07` 确认帧长任意与 `tlast` 语义） | `[工程]` | 本项目 2026-09-10 结论（IP 源码级证据，置信度 0.95）；官方未给出 `tkeep` 原文，见 `R-07` |
| `F-31` | **错误语义**：`soft_err` = 无效 sync header / BTF，**不触发复位**；`hard_err` = TX/RX 弹性缓冲溢出/下溢等，**自动复位并重新初始化**；官方明确"两端时钟源频率差 >100 ppm"可导致 RX overflow/underflow 型 hard_err | `[官方]` | `R-02` |
| `F-32` | **无重传**：Aurora 协议不提供重传/确认；PG074 的 CRC32 是**每 lane、IP 自用**（`crc_pass_fail_n`/`crc_valid`），"does not map to any higher layer protocol requirements" | `[官方]` | `R-05` |
| `F-33` | **流控可选**：Aurora 64B/66B 支持 NFC（收端请求发端插 idle）与 UFC（1–256 字节控制消息），默认不启用；streaming 接口只支持 NFC immediate，framing 接口支持 immediate/completion | `[官方]` | `R-03`；本工程是否启用见 `U-12` |
| `F-34` | **共享逻辑**：同 Quad 多核必须共享 refclk/GT COMMON；UltraScale GTH 的共享资源为 `IBUFDS_GTE3/4`、`GTHE3/4_COMMON`、`BUFG_GT`；IP 有"Shared Logic in Core / in Example Design"选项 | `[官方]` | `R-04`；本项目双核回环已按此实现 |
| `F-35` | **速率差**：Aurora 有效载荷 ≈10.0 × 64/66 ≈ **9.7 Gbps**（约 1212 MB/s）；GE1 有效 ≈953 Mbps（约 119 MB/s）；**约 10× 差值**。F-29 的无反压 + 该差值 ⇒ 接收侧必须整帧缓存、限速或丢弃 | `[推断]` | `R-06`；`D-11` |

| `F-39` | **路线 A 性能**：1466 B 帧、纯硬件数据面 **82.67k 帧/秒 ≈ 969 Mbps**（约千兆线速），10 MB 全量 100% + SHA256 一致 | `[实测]` | 导览 §2.2/§1.7 |
| `F-40` | **路线 B 性能**：软核逐帧服务，1466 B 帧可持续 **≈2000 帧/秒（≈23 Mbps）**，临界 ≈2500 fps，服务上限 ≈2560 fps；定位为"可编程、可观测"，不追求线速 | `[实测]` | 导览 §2.3 |
| `F-41` | **缓存容量的算术后果**：方案自己的算例为 65,536 B/activation × M=8 × 正反双向 = **1,048,576 B = 恰好 1 MiB**，与 F-37 的队列容量相等，**无 hold/门控余量** | `[推断]` | `D-10`；`A-08`、`Q-05` |
| `F-42` | **帧数与任务数**：65,536 B / 1200 B ≈ **55 片/张量**；一个 PP Step（M=8、双向）≈880 片。256 槽只够约 **4.6 个张量**（按帧计） | `[推断]` | 同 `D-10` |
