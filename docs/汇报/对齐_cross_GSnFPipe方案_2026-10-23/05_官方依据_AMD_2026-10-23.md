## 1. Aurora 64B/66B（IP v12.0，本工程 `aurora_64b66b_v12_0_13`）

### `R-01` 参考时钟与时钟架构

- **原文要点**：参考时钟频率从"按线速率给出的列表"中选择，默认 **156.25 MHz**；核心使用 `user_clk`、`sync_clk`、`tx_out_clk` 三个相位锁定的并行时钟；`user_clk` 同步核心与用户逻辑、必须由 BUFG 驱动；核心用稳定的 `init_clk` 做 MMCM 同步，**`pma_init` 需保持到 MMCM 锁定**。
- **URL**：
  - https://docs.amd.com/r/en-US/pg074-aurora-64b66b/GT-Reference-Clock-Frequency
  - https://docs.amd.com/r/en-US/pg074-aurora-64b66b/Aurora-64B/66B-Clocking-Architecture
- **本工程落点**：Vivado 2023.1、`aurora_64b66b_v12_0_13`、`c_line_rate=10.0`、单 lane、refclk 156.25 MHz（T6/T5）、`user_clk ≈151.5 MHz`。A1 上板流程需按"MMCM 锁定 → 释放 `pma_init`"的顺序实现与验证。
- **影响**：`D-14`、`A1` 验收；上电/复位序列写入 `hardware_inventory` 的上板流程。

### `R-02` 错误信号：hard_err / soft_err

- **原文要点**：`soft_err` 表示检测到位错误（无效 sync header / 无效 BTF 等），**不触发复位**；`hard_err` 表示硬件级错误（TX 弹性缓冲溢出/下溢、RX 时钟校正/通道绑定 FIFO 溢出/下溢等），**核心自动复位并重新初始化**；**"两个 channel partner 的时钟源频率不在 100 ppm 以内"可导致 RX overflow/underflow**。
- **URL**：https://docs.amd.com/r/en-US/pg074-aurora-64b66b/Error-Signals-in-Aurora-64B/66B-Cores
- **本工程落点**：A1 必须把 `hard_err/soft_err` 计数纳入验收；两板参考时钟源需核对是否同源/同频（KU060 同款板通常满足，但必须实测/记录）。
- **影响**：`F-31`、`D-14`；M1 验收证据清单。

### `R-03` 流控是可选特性（NFC / UFC）

- **原文要点**：流控接口有三种配置：native flow control（NFC，收端请求发端发 idle）、user flow control（UFC，1–256 octets 高优先级控制消息）、USER-K；NFC 的 immediate/completion 模式；**streaming 接口只支持 immediate，framing 接口两者都支持**；默认 `None`。
- **URL**：
  - https://docs.amd.com/r/en-US/pg074-aurora-64b66b/Flow-Control
  - https://docs.amd.com/v/u/en-US/aurora_64b66b_protocol_spec_sp011（SP011 流控概述）
- **本工程落点**：当前 IP 是否启用 NFC 未知（`U-12`）；若 `Q-12` 选择"开 NFC"，需改 IP 配置并重新验证 framing 模式下的模式选择。
- **影响**：`D-11`、`Q-12`。

### `R-04` 共享逻辑（同 Quad 多核）

- **原文要点**：`Shared Logic in Core` 与 `Include Shared Logic in Example Design` 两种方式；UltraScale/UltraScale+ GTH 的共享资源包括 `IBUFDS_GTE3/4`（参考时钟）、`GTHE3/4_COMMON`（Quad 时钟）、`BUFG_GT`（时钟）；同一 Quad 多核需共享这些资源。
- **URL**：https://docs.amd.com/r/en-US/pg074-aurora-64b66b/Shared-Logic
- **本工程落点**：现有"单板双核回环"已按共享逻辑实现（`F-34`）；跨板若做双链路，仍需每板两核共享同一 Quad 资源（`R-04`），第三/第四核须复用共享逻辑版本。
- **影响**：`A-15`、未来多路径扩展。

### `R-05` 无重传；CRC 为 IP 自用

- **原文要点**：
  - SP011：Aurora 定义 hard/soft error；hard error 触发复位；**协议不提供重传/确认**。
  - PG074：`CRC32` 按 lane 计算，**"for consumption of the Aurora IP alone, and it does not map to any higher layer protocol requirements"**；收端用 `crc_valid` / `crc_pass_fail_n` 报告。
- **URL**：
  - https://docs.amd.com/v/u/en-US/aurora_64b66b_protocol_spec_sp011
  - https://docs.amd.com/r/en-US/pg074-aurora-64b66b/CRC-Functionality-for-a-GTY-Transceiver-Based-Core
- **本工程落点**：可靠性必须端到端实现（与方案 §4.3 一致，`A-13`）；FPGA 不能把 Aurora CRC 当作业务 CRC，也不能靠 Aurora 重传。
- **影响**：`F-32`、`Q-08`、`D-11`。

### `R-06` 帧接口/流接口与初始化

- **原文要点**：
  - **Framing** 接口是完整 AXI4-Stream，**可封装任意长度的数据帧**；**Streaming** 接口无帧边界。
  - `lane_up` 表示单 lane 完成初始化；`channel_up` 仅在完整初始化流程结束后拉高；数据可能在 `channel_up` 之前到达，**只能用 `m_axi_rx_tvalid` 限定有效数据**；`channel_up` 可反相用于复位 TX 侧模块。
- **URL**：
  - https://docs.amd.com/r/en-US/pg074-aurora-64b66b/Interface
  - https://docs.amd.com/r/en-US/pg074-aurora-64b66b/Initialization
- **本工程落点**：`F-27`（Framing）、`F-04`（回环拓扑）；A1 验收记录 `lane_up→channel_up` 时序与复位行为（`D-14`）。
- **影响**：`A-05`、`D-14`。

### `R-07` 用户接口语义的边界说明（重要）

- **官方正文能确认的**：Framing 接口 = 完整 AXI4-Stream、帧长任意；`tlast` 每帧一次（AXI4-Stream 语义）；RX 侧端口表中**没有 `tready`**（IP 不提供反压）。
- **官方正文未检索到的**：`tkeep` 在末拍的**MSB 对齐**规则、`REM` 的具体编码、`SEP/SEP7` 控制块细节。原因：PG074 官网正文为 JS 渲染 SPA，检索服务与直接抓取均只返回片段；本项目的 `tkeep` 结论来自**IP 生成源码逐行核对**（`axi_to_ll.v` / `ll_to_axi.v` / `sym_gen.v` / `sym_dec.v`，置信度高，见内部文档 `笔记和开发指南/结论_cross_Aurora64B66B_AXIS接口约定_2026-09-10.md`）。
- **本包处理**：`F-29`/`F-30` 已按 `[工程]`（IP 源码级）标注，**不标 `[官方]`**；若需官方书面依据，需另行取得 PG074 PDF 或 UG508/SP011 全文（SP011 已取得，含控制块编码表）。
- **影响**：`D-13` 的"接口不变式"按工程源码级证据执行；论文引用时注明"依据 IP 源码与 SP011，非 PG074 正文"。

## 2. AXI DMA（PG021）

### `R-11` 散射聚集描述符与用户应用字段

- **原文要点**：SG 描述符 = **8 个 32-bit 基础字 + 0 或 5 个 User Application 字（`APP0`–`APP4`）**；**APP 字只有在包含 Control/Status Streams（`C_SG_INCLUDE_STSCNTRL_STRM=1`）时才会被读取/回写**；描述符按 **16 个 32-bit 字对齐**（0x00/0x40/0x80…）；单描述符 buffer 长度上限 **67,108,863 B**（旧版 DS 记 8 MB）；支持 64 位地址。
- **Cyclic 模式**：BD 环 + `Cyclic_BD_Enable` + Tail 写非链内值；引擎循环取同一组 BD 直至停止/复位。
- **URL**：
  - https://docs.amd.com/r/en-US/pg021_axi_dma/Scatter-Gather-Descriptor
  - https://docs.amd.com/r/en-US/pg021_axi_dma/Cyclic-DMA-Mode
- **本工程落点**：prj11 使用 AXI DMA **512-bit**、当前为 direct-register 逐帧模式；若 `Q-13` 选"SG 描述符 + APP 字段"，必须先加 C/S stream 逻辑，且字段只有 5×32-bit。
- **影响**：`Q-13`、`A-09`。

## 3. AXI DataMover（PG022）

### `R-12` 命令流与 TAG

- **原文要点**：DataMover 的 MM2S/S2MM 各有一个命令接口（AXI4-Stream）；一条命令 = 一个 command word；32 位地址系统 **72-bit**，64 位地址 **104-bit**；单命令传输 **1 B–8,388,607 B**，自动拆成合规 burst；命令含 **`TAG`**（任意值），随执行流进入对应状态字。
- **URL**：https://docs.amd.com/r/en-US/pg022_axi_datamover/Command-Interface
- **本工程落点**：`Q-14` 的建议方案（命令流 + 硬件定时器 + TAG 回读）以此为依据；不要求 Vivado 版本差异（2023.1 自带 DataMover）。
- **影响**：`Q-14`、`A5` 架构。

## 4. AXI UART Lite（PG142/DS741）

### `R-09` FIFO 深度、最大波特率与误差

- **原文要点**：**16 字符** 发送/接收 FIFO；最大波特率 = **AXI 时钟 / 16**（例：128 MHz → 8 MBaud）；波特率误差需在约 **5%** 内（旧版 DS 口径）；读写空/满 FIFO 会产生总线错误/未定义行为。
- **URL**：
  - https://docs.amd.com/v/u/en-US/axi_uartlite_ds741
  - https://adaptivesupport.amd.com/s/article/14760?language=en_US
  - https://xilinx-wiki.atlassian.net/wiki/spaces/A/pages/18842359/AXI+UART+Lite+standalone+driver
- **本工程落点**：AXI 时钟 100 MHz → 最大 6.25 MBaud；当前 9600 B/s 仅够调命令；事件日志必须走 GE1/UDP（`D-08`）。
- **影响**：`F-13`、`F-52`、`Q-10`。

## 5. 以太网与时间戳

### `R-10` PG138 的 1588 选项要求 1000BASE-X/SGMII

- **原文要点**：配置 1588 硬件时间戳的步骤："From the Physical Interface tab, select the **1000BASE-X or SGMII** option. From the Network Timing tab, select the Enable 1588 option."；支持 1-step/2-step、ToD 或 Correction Field、80-bit ToD、可选 64-bit 随帧时间戳。
- **URL**：https://docs.amd.com/r/en-US/pg138-axi-ethernet/Generating-the-Subsystem-for-1588-Operation
- **本工程落点**：本板为 **RGMII**（GMII-to-RGMII，125 MHz，`R-14`）⇒ **不能依赖 PG138 的 1588 做跨板对表**；方案 §6.1 "不许直接相减"与之一致（`F-51`）。
- **影响**：`A-12`、`Q-16`、M3 时间口径。

### `R-14` GMII-to-RGMII 参考

- **原文要点**：GMII to RGMII 核工作在 **125 MHz**，支持 10/100/1000 Mb/s 全速率；RX 路径延迟 = 一个 `rgmii_rx_clk` 周期 + IDELAY 固定延时。
- **URL**：https://docs.amd.com/r/en-US/pg160-gmii-to-rgmii/Performance
- **本工程落点**：`F-16` 的 125 MHz 与 `F-18` 的 IDELAY 相位修复均有对应机制；但板级最优相位需实测（`D-06`）。
- **影响**：`F-18`、`D-06`。

## 6. AXI4-Stream FIFO（PG080）

### `R-13` store-and-forward / cut-through 与短包已知问题

- **原文要点**：PG080 支持 store-and-forward 与 cut-through 两种发包/收包模式；store-and-forward 要求 FIFO 能装下整包；**异步 + packet mode 下，2 beat 短包可能被拆拍**（Answer 000034731），与需要连续整包的 IP（如 100G CMAC）配合会损坏包。
- **URL**：
  - https://docs.amd.com/r/en-US/pg080-axi-fifo-mm-s/Protocol-Description
  - https://adaptivesupport.amd.com/s/article/000034731?language=en_US
- **本工程落点**：A3 的"整帧转发"可用 store-and-forward；但 ARP/ICMP 等短帧（2 beat）跨时钟路径需单独测试；**Aurora 的 `tkeep` 语义与多数 AXIS IP 不同**（`D-13`），若插入 PG080/AXI DMA 需确认语义不被改写。
- **影响**：`D-13`、A2/A3 测试用例。

## 8. 官方依据对结论的影响（汇总）

|---|---|
| 可靠性必须端到端（Aurora 无重传/CRC 自用） | `R-05` |
