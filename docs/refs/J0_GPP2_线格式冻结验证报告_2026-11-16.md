## 3. 逐项检查

| 检查 | 方法 | 结果 |
|---|---|---|
| 头部/长度 | 逐包 `decode()` 校验 magic/version/kind/direction/flags、`payload_len`、datagram ≤1200 B | 380/380 通过 |
| CRC32 | 覆盖“头前 48 B + payload”，逐包重算比对 | 380/380 通过 |
| META | JSON 解析、`nbytes=prod(shape)×dtype_size`、整张量 SHA256 | 10/10 通过 |
| 重组 | 按 `segment_index` 重组，校验无缺片/无重复、片数 = `segment_count` | 10/10 通过 |
| 整张量摘要 | 重组 SHA256 == META.sha256 == `expected_payload.bin` SHA256 | 10/10 全等 |
| ACK | 每片一个 ACK、索引 0..count−1 完整；META ACK 索引 `0xFFFFFFFF` | 10/10 通过 |
| 重编码 | `encode(decode(blob)) == blob`（逐字节） | 380/380 字节一致 |
| 与 B 组实现互操作 | 逐包字段比对 + B 组 codec 重编码字节一致 | 380/380 通过 |
| 边界/负例 | 坏 CRC、坏 magic、超长 datagram、`payload_len` 不符、run_id 空/超长/含 NUL、dtype 不支持、nbytes 不符、缺片/重复/片数不一致 | 负例全部按预期拒绝 |
| 回归 | `pytest tests -q`（含 `tests/test_gpp2_codec.py`） | **245 passed / 6 skipped / 1098 subtests**（19.75 s） |

## 5. 未覆盖与限制（不改变冻结结论）

1. **A 侧实机承载未测**：1228 B IP 包经 P2 双向、丢包/速率上限、ACK 同路径返回——待 A2/P2 上板与 A3 吞吐；本报告只证明**线格式与软件实现**。
2. **B 侧传输行为未复测**：本报告不验证 RTO/窗口/重传性能，只验证报文格式与 META/ACK 语义；B 组 M1/M2 报告仍待双机实证。
3. **labels 端到端未测**：约定已写入冻结文件 §4，实际 activation+labels 配对在 J1 固定 Tensor 上验证。
4. **8 MiB 上限未做压力测试**：只验证 32/64 KiB 与 1148 B 边界；大 Tensor 分段行为由 codec 单元测试覆盖，未上机。

## 6. 结论

A 侧独立实现与 B 组交付的 GPP2/v1 实现**字节级一致**，10 用例 380 报文全过，负例按预期拒绝；线格式冻结条件满足。
**J0 剩余**：A 侧能力/网络实测回填（A2/A3）+ 实机承载复验 + 双方签字；在此之前 J0 整体仍为 **BLOCKED**（线格式已完成冻结，见 #6）。
