## 0. 一页摘要

**基本面好于直觉，病灶高度集中。** 命名规范 0 违规、frontmatter 覆盖 99.5%、镜像门禁 CI 化、多义文件名 0 个——这套体系的"死文档"（事实记录）层质量很高，1557 处 wikilink 使历史结论的交叉检索相当可靠（实验 D 第 6 题：0 回显根因一击命中且多处口径一致）。

**真正的病在"活文档"层：5 个"当前状态"载体（agent.md 当前状态节 / vault README 状态表 / AGENTS §十 / 追踪 / 规划）没有一个是最新的事实源**——而最新事实（prj12 P0 完成、双仓定案、B 组 v1.1）只存在于 10-24~26 新写的结论文档里。实验 D 实录：新会话问"路线 B 收口了吗"，README 当前状态表的末行会给出 **"R1 未收口"的错误答案**（实际 10-19 已全量收口并发了 Release）。

**根因不是"没维护"，而是机制缺口**：①活文档无唯一权威、无更新触发器（5 载体并行，没有任何流程强制谁更新）；②"当前状态"与"历史事实"混在同一张表里（README 状态表 30 行 = 30 笔未来维护债）；③类型化文档 2/3 无归属目录（结论/任务书/参考落根目录，4 个目录不在任何地图）；④链接写作无校验（wikilink 无 CI、alias 字段写法不符合 YAML 规范）。

**治理方案核心一招 = 状态唯一化**：一个唯一"现在"文件、状态与历史分离、里程碑提交触发更新、CI 拦死链。三阶段合计 ≈1 天。**Obsidian 裁决：保留 vault 不为它重构**（7 周未开、tags 近零、wikilink 是纯文本资产不依赖它；上 tags/bases 是第二套索引，治不了时效病）。

## 一、第一性原理：这套体系为什么存在

### 1.1 目的函数

文档体系存在的唯一理由：**降低四类消费者完成四类任务的成本**。

| 消费者 | 核心任务 | 对体系的要求 |
|---|---|---|
| AI 会话（ZCode/DSH，最主要） | 冷启动后接手工作 | 入口文件**新鲜且指向唯一权威**；按名可检索 |
| AI 会话 | 查历史证据/结论（判据、位流哈希、根因） | 交叉链接密集、口径一致、不可篡改感 |
| AI 会话 | 防重蹈覆辙 | 坑账本可检索、编号可引用 |
| 人（用户/导师/B 组/同门） | 验收、对齐、装环境 | 交付物按对方仓库的格式就位 |

由此得到体系的核心指标：**新会话首答正确率与时延**（活文档层决定）、**历史证据可达性**（死文档层决定）、**防重复踩坑率**（坑账本决定）。

### 1.2 公理：文档只有两类，腐化只发生在其中一类

- **活文档**（状态/入口/索引/路由）：价值 = 与事实的同步度。**每次事实变化都必须跟着变**，不变就是负资产（比没有更糟——它给出错误答案）。
- **死文档**（调试记录/结论/验证单）：写完即冻结，**越老越有价值**，永不腐化。

本审计的全部 P0 问题都发生在活文档层；死文档层的 30 条断链只是链接写法问题，不影响其内容正确性。**推论：治理的优先级应该是"先修活文档机制"，而不是"整理目录"。**

### 4.1 命名规则终案

**第一层｜先定仓，再定名**：一句话判据——"B 组或导师要看吗？看 → 交付仓（守其 CONTRIBUTING：英文命名+版本号+issue 前缀）；只有工程侧看 → vault（守下述格式）"。

**第二层｜vault 格式（主格式不动 + 两处扩展）**：

1. **M 轴（新）**：GSnFPipe 时期新文档用 `M<N>_<prj标识>_概要_YYYY-MM-DD.md`——M 段替换阶段段。prj标识 ∈ `prj12`（工程件）/ `GSnFPipe`（联合件）；如 `M1_prj12_双板链路上板验证单_2026-10-28.md`。
2. **轴切换点**：`阶段三` 封存为 prj10/11 历史专属；prj12 起新文档一律 M 轴。已存在的 `阶段三_prj12_双板互联开工草案_2026-10-24.md` 不改名，frontmatter 补 `里程碑: M1`。
3. **无里程碑文档**（对齐/工具链/CI/横切）继续用无阶段类型，不硬挂 M 前缀。
4. **类型表补全（9→11 类，修计数错）**：现有 `前置·参考·里程碑·汇报·规划·追踪·结论·架构·导览` 之外，登记实际在用的 **`任务书`**（照着做类 → `操作文档/`）与 **`对齐`**（面向导师的对齐包，目录级约定 `对齐_<对象>_日期/00~06_编号.md`）。
5. **不动项**：`[阶段]_prj标识_概要_日期` 主体格式、日期段、alias 机制、docs/ 脱敏镜像规则、交付仓内部命名（其自治）。
