## 二、设计决策（为什么这样做）

1. **UART 两段协议**（`'M'`→SEQOK→PC 预热→`'M'`→READY）：RND 模式下桥①不自动读 ⇒ 板卡
   发不出 **ARP 应答** ⇒ PC 邻居表老化 ⇒ 单播数据帧被 PC 自己丢弃（prj10 2026-10-08 实证）。
   B2 模式切换权在 C，故预热窗做成协议第一段：C 先切 SEQ，PC 在窗口内发 UDP 探测刷 ARP，
   再 GO 切 RND。
2. **基线在 SET_MODE 之后取**：板上实征 SET_MODE 使 `u_wr_frame` +1（B1 会话三轮 T3 各 +1），
   契约 §4.1 步 0 的顺序（先切模式后取基线）天然吸收；轮末恢复 SEQ 在 DONE 打印之后，不污染对账。
3. **C 侧读节拍 = wm_rd 增量等待**（rd_reg 轮询 ~1ms 粒度）：等价于 j3 脚本"每发一条等对应
   数据帧回来"，且对 Lr（<37.7µs 粗上界）有 300ms 超时兜底；负向 B 重读槽单独 120ms 观察窗。
4. **判据全部 PC 侧独立推导**：不采信 C 的自评行（C 只报计数），逆序对按**实收序**计量，
   集合级判决对着**全集**量（负向 A 的"缺"才能被看见）。

## 四、过程坑（候选坑账本 #42/#43）

1. **Vitis `app build` TCF 通道 reset 静默空转**：`ERROR : xsct server communication channel
   has closed unexpectedly`（IDE.log）后 `app build` 返回"成功"、`J3_DONE` 照打，但 Debug/
   下**没有 ELF**。判别法：构建后 `ls *.elf` 必须非空。修法：`make all` 直跑（PATH 补
   `gnu/microblaze/nt/bin` + `gnuwin/bin`），秒级且无 TCF 依赖 → 坑账本 **#42**。
2. **C 一处 if 多语句未加花括号**：`if (x) uputs(...); uputd(...); else` 直接语法错——
   mb-gcc -fsyntax-only 单独检查比整套 Vitis 构建快两个数量级，写完先查再进构建。
3. **Mock 三个判据侧 bug（负向对照矩阵抓出）**：① 预热回显落 OS socket 缓冲、start_rx
   后才被读入 → 每轮多 1 帧零载荷（修：start_rx 后 sleep 0.3 再清 frames）；② 上一轮
   `SEQRESTORED` 残留行被下一轮当 SEQOK 判（修：轮首发前清行 + SEQOK 等待循环跳杂行）；
   ③ 负向 A 的缺帧判定原先对着"期望实收集"，跳过的帧两边同时消失恒空（修：对着全集判）。
4. **负向对照反向抓出自己注入缺陷写反**：`fresh[s] = defect != "noretire"` 把正常模式
   变成"永不退休"、缺陷模式反而正常——首轮 byte/order 的 B 轮 FAIL 是被这个反逻辑误伤，
   noretire 根本没生效。**教训：负向对照不仅要"注入后期望 FAIL"，还要核对"FAIL 的原因
   是注入的缺陷本身"**（看失败行/错误类别，不只看红绿）→ 坑账本 **#43**。

### 板上三段缺陷链（全部板上实证，J_B2 首跑 → 收口之间）

1. **PC 侧 read_line 遗留缓冲 bug（最大干扰源）**：行解析只在"有新字节到达"时检查缓冲——
   上一次调用返回一行后**留在缓冲里的完整行**，在下一次超时时被当"残包"整体丢弃
   （resync 转储里赫然是带 `\r\n` 的完整 READY/WRWAIT 行 = 自我暴露）。**修：进入 read_line
   先解析遗留缓冲再等新字节**。修后串口残包归零。
2. **幽灵 RX 字节 → 补码对协议**：与打印突发相关的单字节幻影会进 RX FIFO（抓到实锤
   `RXGHOST 53`='S'）。单字节命令协议会被幻影误触发 → **轮命令改补码对（c,~c）**：
   幻影单发凑不齐对，'S'/'I' 单字节命令在命令间消费不受影响。
3. **I 行打印中穿插 AXI 读 → TX 行中后段字节损坏（真物理层现象）**：`uputs…uputd(rd_reg())`
   夹在字符之间的行**必挂**（`drop=` 后必丢、`wr=799` 显示成 `wr=01`——4/4 稳定复现）；
   而 READY/DONE 等纯打印行（值已在局部变量里）完好。根因同 PDRC-203：UART 引脚与
   DDR 校准 bitslice 同组，AXI 读突发把 UARTLite TX 拖进校准窗。**修：先读完 4 寄存器再
   一次性纯打印** → I 行 5 次重试全干净。→ 坑账本 **#44**。

### 对账口径备注（勿误判）

轮后 'I' 快照的 `wr+16142` 这类大数 = **跨轮累积的回显迟到提交**（桥② 回显写回 + 预热探测
+ 重试残余都在快照窗内），prj10 先例口径：**wr+ 增量判定只看 DONE 行**（轮内闭环、与基线同
窗），轮后快照仅作 rd 侧旁证。本轮判定全部基于 DONE 行（0 残包全收到），证据链干净。
