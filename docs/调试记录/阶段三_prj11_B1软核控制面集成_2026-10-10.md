## 三、过程中的坑（候选坑账本 #35-#44，均为本轮实证）

1. **测试激励的 AXI BFM 两个经典竞态**（TB 侧，两版各踩一次）：①"单拍 valid 脉冲"在 DUT 恰好未 ready 的那个时钟沿把事务整个丢掉；②"等 ready 再撤销 valid"在 ready 波形与采样沿错位时活锁。**修法 = negedge 驱动 + 在 negedge 上观察到 ready=1 后才让 valid 覆盖下一个 posedge**。
2. **AXI 从机 ready 的"接受边同拍拉低"陷阱**（RTL 真教训）：accept 分支里 `arready<=1` 后又 `<=0`（末次赋值胜出）→ ready 只在"无请求"时为高 → 电平轮询的主机永远等不到 → 无限受理。**修法 = 受理后进入忙碌态时才撤 ready，与写通道 AWREADY 的做法对齐**。
3. **读通道未串行化的旧数据**：pending rvalid 期间受理下一笔 AR，朴素主机会采到旧 rdata——接受门加 `!rvalid` 强制串行。
4. **user 域执行 FSM 缺"等请求撤销"关闭态** → 请求电平在 2FF 往返窗口内每拍重复执行同一命令（脉宽监视器抓到 9 次脉冲）——**cmd_channel 的 U_WREQL/U_WBACKL 关闭态必须原样复刻**（新增 U_CLOSE 态修复）。
5. **"同拍写 cfg + 发脉冲"类缺陷在寄存器边界不可观测**：下游按寄存器采样，脉冲沿必然同时看到新值——负向对照改为**脉宽 2 拍**缺陷（可观测、真违约）。
6. **多驱动自查**：bvalid/rvalid 曾被两个 always 块赋值（坑 #25 模式），编写期自查拦截，未流到 DRC。
7. **SmartConnect M01 AXI4-Lite 写转换 × 自研 Lite 从机在真硬件上交互楔死**（本轮最大坑）：TB 三种 AW/W 到达次序全绿、真网表确认入流、未映射地址写返回正常、UARTLite(M00) 写正常——**唯独写 M01 从机挂死总线**；板下无法复现（问题在真硬件的转换器行为）。处置 = 换 axi_interconnect（M1 本板验证过）。**教训：跨 IP 边界的协议组合，仿真过了不算过，必须有真硬件上的独立取证通道（本轮是 JTAG mwr/mrd + 未映射地址差分）**。
8. **BD 模块引用的 OOC 综合 DCP 缓存不随 RTL 变更失效**：`reset_run synth_1` 不级联 `mb_ctrl_*` OOC runs——RTL 修了、烧的仍是旧网表（板上现象不变才暴露）。修法：build 脚本显式 reset 全部 `mb_ctrl_*` runs。**判别法：改了 RTL 重建后板上行为不变，先查 OOC DCP 时间戳**。
9. **xsct targets 里 "MicroBlaze Debug Module"(MDM) 与 "MicroBlaze #0"(CPU) 都会被名字匹配命中**——选错 `dow` 报 Invalid context；按 `MicroBlaze #` 精确匹配。
10. xsct/vivado 抢 JTAG：切换前 `close_hw_target` + `disconnect_hw_server` + 杀 hw_server/cs_server 最干净；TCF "Channel closed" 即残留态。
11. **`apply_bd_automation` 的 debug_module 合法值 2023.1 变更且不可枚举** → 方法论：从已验证工程（project_1）`write_bd_tcl` 导出重建脚本当配方基底。
12. proc_sys_reset 极性参数 `C_EXT_RESET_HIGH` 2023.1 只读——极性由所连端口的 POLARITY 决定；模块引用地址段命名是 `cell/s_axi/reg0`（小写）——分配前先探测。
13. bash 内联 python 双引号内 `$` 被展开导致补丁锚失配（第 N 次踩）——**RTL/脚本补丁一律走 Write 工具脚本文件**。

## 四、B1 集成构建（✅ 2026-10-10 17:57 全绿收官）

- **实现全过：WNS +0.021 / WHS +0.004**（比 B0 基线 +0.019 还略好——软核域独立 100MHz 隔离的策略兑现，未碰 W5 已收敛的 cfg 锥）；ILA0 追加 42 bit lite 探针无碍收敛（`C_INPUT_PIPE_STAGES 1` 在位）。

### ②中发现的真缺陷链（三段递进，全部板上实证）

**第一段：写通道挂死总线的定位（隔离实验链，干净总线 ×4 轮）**
- 现象：ELF 下载后 CPU 卡在 PC=0x74c（uputc 内、TX 写前）；JTAG `mrd` 读全通（ID/水位/槽映射算术全对——读通道与邮箱完全正常）；**任何对 0x44A00000 的 `mwr` 立即挂死总线**。
- 隔离：写未映射地址 ✅ 返回正常（DECERR 通路完好）→ 写 UARTLite(M00) ✅ 通 → 写 axi_lite_regs(M01) ❌ 挂 → **楔点精确锁定在 SmartConnect M01 Lite 写转换 ↔ 本从机的交互**。
- 第一版修复（AW/W 分拍独立锁存 + TB P4b 回归用例）：TB 全绿但板上**仍挂**——因为还有第二段。

**第二段：BD 模块引用的 OOC DCP 缓存坑（修复根本没进位流）**
- 修复版重烧后现象不变；查 `mb_ctrl_axi_lite_regs_0_0_synth_1` 的 DCP 时间戳**停在修复前的旧综合**——`reset_run synth_1` **不级联** BD 内模块引用/内部 IP 的 OOC runs，旧网表被复用。
- 修法：build_debug.tcl 增加 `foreach mr [get_runs -quiet -filter {NAME =~ mb_ctrl_*}] { reset_run $mr }`；重建后 DCP 刷新（15:30）。
- 重烧后：**读 T1/T2 PASS 打印到串口（COM5 上首次看到软核输出！）但 T3 写仍挂**——TB 全绿 + 真网表确认入流，SmartConnect 交互楔死坐实为工具级问题。

**第三段：换互联（SmartConnect → axi_interconnect，M1 本板验证过的组件）**
- 工程决策：把唯一未经验证的组合（SmartConnect M01 Lite 写转换 × 自研从机）换成 project_1 M1 在本板验证过的 axi_interconnect（NUM_SI=1/NUM_MI=2，project_1 导出配方同款接线）。
- create_bd_b.tcl 已改 + BD 重生成验证通过；全量重建首掷 **WNS −0.193**（W5 已知关键锥 full_bit_q→FSM CE，换互联后布局拥挤重现；同指令续跑同结果=确定性）；**换 place 指令（ExtraTimingOpt→Explore）重掷收敛：WNS_GATE +0.004 / WHS_GATE +0.004，位流+ltx+XSA 齐出**（`W5_BUILD_OK`，18:35）。四件产物归档 `out/archive/b1_ic_v2_2026-10-11/`（bit `D14425F2…A114` / ltx `CF1FFCFA…3199` / xsa `53B747AF…EDD2`）。
- **板上会话因板卡断电暂停（2026-10-11）**——下一场次的完整清单见 §六。

### 板上已拿到的硬结论（不会因后续工作失效）

1. **J_B1① A 基线复现全过**（B1 集成不破坏数据面——fork + 控制面叠加的硬证明）；
2. **读通道全链通**：软核经 AXI-Lite 读 ID/水位/槽映射（COM5 串口 T1/T2 PASS + JTAG mrd 双源印证）；
