## 2. G0：B1D 诊断轮（下午只做这个）

### 2.1 准备

- 两板各自有同一套：`prj/project_12/out/b1d_D550FD6B/aurora_mem_bridge_b1d.bit`、`probes_b1d.ltx`；ELF `prj/project_12/out/j3_soft_r2_BA3C0220.elf`（`ba3c0220…bb3559`）；配置 `out/twin_config_b1d.json`。
- 现场回填 `twin_config_b1d.json` 的 cable/COM/NIC（不同机器不同 COM）；烧录前校验 bit/ltx/ELF 全哈希；**B1D 与 B1 都 5 核，不能按核数识别，必须核 ltx SHA**。
- 串口按实测（历史 PC1 COM6/COM7、PC2 COM5，不得照抄）。

### 2.2 执行

1. 先确认无其他 Vivado 会话；两板逐块烧 bit+ELF，串口 `d` 进 DMA；链路 S0：`ch_up/lane_up/pll/link_ok=1`、`aurora_rst=0`、hard/soft=0。
2. 静默背景，每方向发 **1 帧 `len=100`**（线上 142 B），抓 pcap + 计数前后快照；读 `dbg_up_bytes`、`dbg_up_stall`、`dbg_pfwd_drop`、`dbg_prev_drop`、`up_frames`、mem2 计数；16 位计数做模 65536 差分。
3. 同 run 补 `len=1200/1472` 长度交叉；反向 B→A 做方向对照。
4. 若要归因 B1 补丁，另做基线 `C856BA83` / B1 `E9BE2B14` 同拓扑对照；**不能只靠 B1D 单侧**。

### 2.3 判读（只做分诊）

| 观测 | 允许结论 | 禁止结论 |
|---|---|---|
| `up_bytes +142` 且输入确认 142 B | 计数点已吐预期字节；查 `len_tab`/`wr_commit_len`/mem2/pack 边界 | “唯一根因就是 mem2” |
| `up_bytes +78` 且输入确认 142 B | 到该计数点已有缺口；查 TX keep/last、输入、unpack 计量 | “unpack 根因已定” |
| stall/drop/overflow 有增量 | 按语义查背压/丢弃；保留同 run 前后证据 | 不区分原因写硬件坏 |
| 恒零/复位/背景流干扰 | 判据未取得；最多重做两次受控 run 后归档阻塞 | 把恒零当通过，硬套 +142/+78 |

B1D 是**诊断分叉**，不是 L4 定案；修复与正反对照闭环后才可写根因等级。

### 4.2 正式 A/B 构建（D8）

- 共 **3 次正式完整构建**：P12 修复候选 1 次 + P13 A/B 各 1 次；另留 **1 次实现重试 40–50 min**。
- P13 A/B **首轮即合并 11 类 DROP/统计观测**；先列真实位宽/时钟域/语义，映射审查后插 ILA；跨域合法同步，不把不同域总线塞一核。
- 时序不收敛：留报告→合法 directive/布局重试→必要时出 **DIAG_ONLY 版**分诊；**V4 保持 BLOCKED**，不放宽时钟、不删必要计数。

### 4.3 G5 双板 V4

- 入口：G3、S0–S6、A/B 配套新版、完整计数映射、管理员网络、双向 3 帧门、两侧原始证据。
- 顺序：对端就绪→按口令逐板加载 bit+ELF/DMA→两向 3 帧→两侧单次连续 ≥180 s→完整 IP/DROP/ARP 不跨板/无乒乓；先正向后负例；每类 DROP 独立 run_id/计数差分。
- 旧 V3 是**B→A 反向计数一致性核对**（用旧 P1/B1 位流），不是“反向 mem2 闪断”；反向 mem2 恢复归 #23，G5 引用其证据，不重复制造故障。
- 旧 `CFA98553`/`F16FCE70` 永不作回退验收流。

### 4.4 G6 A3/GPP2

- 顺序：**同路径裸 UDP/iperf2 能力基线 → GPP2 默认参数（W8/RTO250ms/retry12）→ 单因素 W/RTO → 故障/API**；不把协议限制误判管道上限。
- 工具：iperf 安装/版本/exe hash/直连基线；iperf3 需 TCP 5201，若同路径 TCP 不可用则记工具前置失败，不判 UDP 数据面 FAIL；RAW L2 只作旁证。
- 单位：UDP payload 含 GPP2 头；GPP2 Tensor goodput 只计唯一有效 Tensor 字节；另报 UDP/IP/wire 开销。
- 协议语义：
  - **空 Tensor：count=0（仅 META/META ACK，无 DATA）**；K4 语义勘误 v1.1，不改 wire；空 Tensor 向量入库前该用例 **BLOCKED**；
  - labels 作为独立 transfer、`int64`、`[batch]`；J1 需做配对测试；
  - 无 HELLO/session；重启/旧包按 transfer_id+RTO，J2 前需测；
  - 8 MiB 上限、窗口 8/RTO 250 ms 属**待实测/可调**，不是 wire 缺陷；不足时另提 v1.1。
- **500 ms 仅作 CPU 微基准**；网络窗口 10–20 s × ≥3。允许 W0/W1 空余 5–10 min `P1_REFERENCE_ONLY` 冒烟，数字不进 A3/能力/协议准入。
