**UART 协议速查**（C 侧 `sw/src_j3/main.c`，脚本自动执行无需手动）：
`'M'/'A'/'B'` 首发=SEQ 预热窗（PC 刷 ARP；RND 下板发不出 ARP 应答）→ 同字符再发=GO
（C 切 RND+稳定基线 → 自动"等写满 256 → 逆序读 → DONE 计数行"）；`'S'`=恢复 SEQ；`'I'`=计数快照。

## 三、判读表（J_B2 = 三轮全 PASS）

| 轮 | C 侧行（COM5） | PC 侧判据（脚本自动） |
|---|---|---|
| **M 主轮** | `[B2] READY t=M wr0=*` → `RD 64..256/256` → `DONE t=M wr+256 rd+256 stall=0` | **J3**：逆序对 >0（逆序读满格 ≈3.2万）+ 到达序=命令序 + 每帧槽位严格对应；**J3′**：集合相等 0 缺/0 多/逐字节一致；**计数**：wr+256 rd+256 |
| **A 漏发** | `DONE t=A wr+256 rd+255` | **恰缺 1 帧 = 帧#100**（seq=本轮 base+100）；无多余无字节差；rd+255 |
| **B 重发** | `B-DUP-NODATA s=*` → `DONE t=B wr+256 rd+256` | 重读槽**无数据帧**（读完即退休）；命令 257 实收 256；集合仍相等；rd+256 |
| 总结行 | — | `[B2-SOFT-VERIFY] PASS (board COM=COM5)` |

**失败模式速查**：
- `WAITWR-FAIL` / wr+<256：写阶段丢帧（PC 侧 ARP 未刷新/链路问题——确认预热窗内 probe 发出）
- `STALL s=*`：某槽读出超时 300ms——若非 B 重读槽即为真异常，留 COM5 日志 + ILA 抓 `dbg_mem_*`
- `B-DUP-UNEXPECTED`：重读槽仍有输出（退休语义破坏）——真缺陷
- 帧#0 载荷非法/跨轮污染：串口行残留或预热回显泄漏（脚本已做清行/清缓冲，复现即报）
- 全轮卡 READY：C 侧基线不稳定（rd_reg 轮询无进展）——发 'I' 看计数是否走动
- **坑 #39 残余**：C 已全面 rd_reg 冲刷；若仍见"落后一笔"读数，ILA 取证（Lite 总线 AR/R 需重建位流）

**计数对账口径**（与 B1 ILA 证据链同源）：`wr+/rd+` 来自 C 侧 DONE 行（rd_reg 读，含冲刷）；
`ill_rd` 不经寄存器暴露，负向 B 的 ill_rd +1 佐证 = ILA `dbg_mem_*`（板场次可选加项，非 J_B2 门槛）。
