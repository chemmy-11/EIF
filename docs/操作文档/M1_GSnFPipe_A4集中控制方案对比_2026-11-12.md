# A4 集中控制方案对比与决策建议（A/B/C/D/E）

> **本文只做方案对比与决策建议，不做实现**（EIF issue #5 的交付物）。
> **归属**：GSnFPipe 里程碑 **M1** 的 **A4 决策项**，**不归属 prj12**——A4 问的是"一台 PC 怎么控两板"的控制面架构，跨 A/B 两组与后续所有工程；`prj12` 只是被评估方案（B/D）当前落点工程，本文引用它的代码/位流/引脚仅作**现状事实**，不代表本方案属于它。
> 所有"工作量"是**估算**不是实测；所有"时延/带宽"凡未标注【实测】的都是【计算】或【推断】。
> 结论一律带四态：`PASS / FAIL / BLOCKED / NOT_TESTED`（对齐 A 组 v1.1 §10 验收四态，`:409-411`）；
> 依据等级一律带 `L0–L4`（对齐 `AGENTS.md §6a:115-133`：低于 L2 只能称假说，禁止写成"判定/根因"）。

## 0. 一页结论

**三行结论**

1. **A（双 USB-UART 集中）今天就能做、是唯一能在 M1 内落地的方案；但它不满足正式控制面要求**——9600 8N1 下单事务约 54 ms（计算）、抖动源在 USB 帧与 OS 调度、且两板内部定时器不同步（v1.1 §7.2:306），`SET_WINDOW` 类时窗无法用它做主控。
2. **B（以太网复用业务口）是正式目标，且比 issue 初稿估计的便宜**——业务口上**已经存在**一套 RTL UDP 命令通道（`cmd_channel`，prj10 W5 单板形态板上验证过，端口 1235/magic `P10C`，`prj/project_12/rtl/aurora_mem_bridge.v:681-714`；**未在 prj12 双板形态复测**）；B 的真实代价不在"建网络栈"，而在 **① 每板唯一 IP/MAC（当前两板完全相同）② 管理消息与数据面隔离 ③ A4/A5 协议层**三件事。
3. **C（独立控制口）卡在第一道门**：第二组 GE 引脚在官方 `KU_IO.xdc:245-258` 里**有定义**，但对应丝印 GE0 的装配与可用性**未被任何工程验证过**，且 2026-11-12 勘误把"段名↔丝印"对应关系降级为 `TO_VERIFY`；建议先花 0.5 人日做装配裁决，再决定 C 去留。**D 扩展性最好但耦合最差，留 M3；E（PC2 代理/逻辑集中，含 `team-link` 传输层）按项目决策 2026-11-12 直接出局、不进交付（F8/§5.5，仅留否决记录）；F（JTAG）按导师 §7.4 直接否决。**

**推荐路线（一句话）**：`A 立即可用作 M1 最小演示 → B 作 A4 正式控制面（复用 cmd_channel）→ A 保留为带外应急通道 → D 留 M3 多板阶段`；C 由导师答 Q5 后二选一。

**四态总表**

| 方案 | 现在能否做 | 能否作正式控制面 | 依据等级 | 一句话理由 |
|---|---|---|---|---|
| **A** 双 USB-UART 集中 | **PASS**（PC 侧今天可跑；含 A4 语义需 0.5–1 人日固件小改） | **FAIL** | L2（代码+硬件配置已核实，未上板计时） | 带宽/抖动/两板时钟不同步三重不满足 |

- **R8 + R3 ⇒ 任何"PC 侧 sleep / PC 时间戳 / 两个串口同时发"的控制方式都不能作正式控制面。** 这把 **A 和 E 从"正式方案"里划掉**，只留作过渡。

## 5. 逐方案：现在能否做 / 最小验证实验 / 明确缺口

> 每个方案三段式。**所有"上板类"实验本次一律未执行**（本任务不占板卡窗口），只给可直接照做的设计与判据。

### 5.1 A — 双 USB-UART 集中

**现在能否做：PASS（今天就能跑最小演示）**
零 RTL、零位流改动；把两板 CH340 都插到 PC1，两个 COM 各自 `serial_dma_mode.ps1` 即可。含 A4 语义需 0.5–1 人日固件小改。

**最小验证实验（本次未执行；设计如下）**

1. `Get-PnpDevice -Class Ports` 记录两个 CH340 的真实 COM（**不许写死**，F5.6）。
2. 两路并发：`PING` × 100 每板，记录 中位/p95/最大 往返；同时记录**端口号在插拔 3 次后的变化**。
3. 交叉验证 R3：两板各发 `SET_MODE`，用 ILA 抓各自 `u_wr_frame` 首帧时刻，量**两板生效时差**——预期会大于命令发送时差（证明"同时发≠同时启动"）。
4. 判据：往返 p95 < 100 ms（计算下界 ≈54 ms，见 D2）；断线可报错；非法命令有明确回包。

**明确缺口**

- **G-A1 时窗确定性**：R3 明文两板定时器不同步；9600 + USB 1 ms 帧 + OS 调度 ⇒ **拿不到 μs–ms 级送达保证**，只能"提前下发 + PL 定时器生效"。这是**原理性**限制，不是优化能解决的。
- **G-A2 端口号不稳定**：本机已实证同一 CH340 换口换号（F5.6）；须做"按 VID/PID + 板卡标签绑定"的识别层（PC 侧 0.5 人日），否则两板会串。
- **G-A3 固件无 ID/ACK 语义**：现状单字符+补码（F1.5），进验收前必须加 `board_id`/`command_id`/状态码。
- **G-A4 工位**：两板 USB 必须够到同一台 PC（延长线/移动机箱），属物理前提。
- **G-A5 校准窗口盲区**：`uart_rxd=AE33` 落在 DDR4 校准字节组，已标 `UNAVAILABLE_DURING_CALIBRATION TRUE`（`xdc:212-218`）→ **上电/DDR 校准期间发来的控制命令会丢**。A4 客户端必须带"等板就绪再发 + 超时重发"，否则会出现"发了两遍才生效"的假象。
- **G-A6 死锁态无能为力**：F7 已实证"闪断 → 通路死锁 → **串口命令无效、只能整板重烧**"。所以 A 不是万能保底：它保的是"链路掉但通路没锁"，保不了"通路已锁"。

**变体 A′（可把带宽这一条从"硬伤"降为"可调"，但不改结论）**：UARTLite 波特率是 BD 参数（`create_bd_b.tcl:102` 的 `C_BAUDRATE 9600`），改成 115200 只需改一行 + **BD regen + 位流重出**（约 0.5 人日 + 位流重出风险），D2 带宽 ×12（单事务 ≈4.5 ms）。但 **A′ 仍然过不了 R3/R8**（两板时钟不同步、PC 时间戳不可作硬件事件），所以只提升"演示与状态轮询手感"，不改变"A 只作过渡"的四态结论。

### 5.2 B — 以太网复用业务口

**现在能否做：BLOCKED**（技术基础在位，三处硬缺口未解）

**最小验证实验**

- **B-0 离线设计评审（0 人日，今天就能做，也是本任务建议的下一步）**：把 `cmd_channel` 现有 5 opcode（F3.6）映射到 A5 五命令，确认 12 B 载荷（F3.5）够不够放 `board_id + command_id + 生效时刻`——**这是 B 的唯一真问题**，与写码无关，评审即可定。
- **B-1 上板（需板卡窗口，本次不做）**：静态 ARP 指向板卡；发 `dst=广播 IP / port 1235 / magic P10C` 的 `SET_MODE`，观察 `cmd_rx_cnt` 与响应帧；再做**负载扫描**：数据面 0 / 10% / 50% 负载下各 100 次命令，画"命令 p95 时延 vs 数据面负载"曲线。这条曲线就是 D1/D3 维度从【推断】升到【实测】的唯一途径。

**明确缺口（逐条点名到模块/字段）**

- **G-B1 每板唯一身份**：`BOARD_IP`/`BOARD_MAC` 是**编译期 parameter 且两板相同**（F3.8）。一 PC 控两板必须区分 → 要么**参数化出两版位流**（每板一份，位流重出+判据重跑），要么加**运行时板 ID strap**（拨码/引脚，需改管脚与 RTL）。**这一条不解决，B 根本无法成立**——把两板接到同一台 PC（两个网口或同一交换网段）后，同一个 `192.168.1.10` 会被两块板同时认领：ARP 抢答、UDP 应答来源歧义，PC 无法定向寻址任一块板。
- **G-B2 管理消息与数据面隔离**：命令帧确实不占槽（F3.3），但**应答经数据泵**（F3.4）⇒ 控制时延被数据面负载调制。要满足 R1/v1.2:111"PL 按硬件时钟执行 + 控制不承担业务"，需**另开管理队列/独立通路**（RTL 2–4 人日）。
- **G-B3 A4/A5 协议层**：12 B 载荷无 `board_id`/`command_id` 字段（F3.5）；opcode 只有 5 个且语义是 prj10 的（F3.6）→ 需扩载荷 + 重定义 opcode + ACK 四态/生效时刻。属协议设计工作（2–3 人日），**不是**"加个网络栈"。
- **G-B4 物理**：一 PC 控两板需 **2 个网口或 1 台交换机**（现状两 PC 各一网口，F3.9/手册 `:33`）；且**两 PC 同为 `.102`** 的路由冲突也要一并解决。
- **G-B5 不要走 lwIP 这条死路**：MicroBlaze 本地内存只有 **64 KB**（F1.9），加 lwIP 属高风险；B 应走"PL 侧 RTL 端点"（F3），**不要**引 lwIP。

### 5.3 C — 独立控制口（第二 PHY / 丝印 GE0）

**现在能否做：BLOCKED（第一道门 = 装配/可用性裁决未过）**

**最小验证实验（三档结论，逐档给证据）**

1. **档① 引脚已定义**——**已完成（本文）**：`KU_IO.xdc:245-258` 的 `#GE1` 组存在，13 脚齐全、与在役 `#GE2` 组同构；**厂商引脚表**该段标题即「以太网\*2」并给出两套 RGMII + 各自 MDC/MDIO（F2.4b）。→ `PASS（引脚层，L2）`。
   - ⚠️ 但**"引脚定义"与"器件存在"是两件事**：8 个在役/历史工程的**自建** XDC 一律只用 `#GE2` 组，`#GE1` 组**从未被任何正式工程采用过**（F2.10）→ 即"**从未被板上验证过**"，这一点与"引脚有定义"必须分开陈述。
2. **档② PHY/RJ45 已装配**——**未做（两件证据都缺）**：需 ① **目视**丝印 GE0 处是否有 RJ45/变压器/PHY 位号，② **图纸**核对（底板原理图 `XCKU040(060)_BASE_1V3.pdf` 本次**未读**——本机无 PDF 抽取库）；对照板卡手册表 43.5.1（`hardware_inventory.md:9` 已有"现场丝印↔手册表 43.5.1"对照列）。厂商引脚表只给球号、**不含 PHY 型号/变压器/位置**（F2.4c）。→ 约 0.5 人日，且**必须在板卡在工位时做**（本任务不做）。

**明确缺口**

- **G-C1 装配未知**：只有引脚定义（F2.4），**没有任何装配/贴片/链路证据**；`hardware_inventory.md:12` 明写丝印 GE0"未使用（本工程不接线）"。

- **G-C3 工程成本**：第二 `eth_rxc` 是**新时钟域**，按 `AGENTS.md:97-101` 必须声明时钟组并选合法 CDC 形式；RGMII RX 还要复刻 `rgmii_rx_fix2`（IDELAY 1250 ps，`AGENTS.md:64`）——这不是"复制一段 XDC"。
- **G-C4 与导师口径冲突**：R4/`:310` 已明确"**不能默认额外 GE1 已可用**"；C 立项必须先拿到装配证据再说服导师。
- **G-C5 PC 侧**：仍要解决"一 PC 两网口"与唯一 IP/MAC（同 G-B1/G-B4）。

### 5.4 D — Aurora 带内控制

**现在能否做：NOT_TESTED**（无设计、帧格式无类型字段）

**最小验证实验（本阶段只做"格式草案"，不实现）**

1. 在现帧格式（`8 B 前导+SFD + 完整 ETH/IP/UDP 帧`，`main.c:912`；应答帧形状 `cmd_channel.v:37-48`）上评估两条路：**(a) 复用 UDP 目的端口分流**（零格式改动，风险最低）、**(b) 新增帧类型/类型位**（需改两端 pack/unpack）。
2. 只写"控制消息格式 + 分流点"草案：谁在 A 侧判断"这帧是给 B 的控制"、判断依据是什么字段、误判时怎么办。
3. 推演"光链断 → B 是否还可控"的处置（预期：不可控，需 A 侧兜底转发或第二通道）。

**明确缺口**

- **G-D1 无类型字段**：现帧是固定形状的完整以太帧（F3.5），**没有**"控制/数据"区分位。
- **G-D2 两端强耦合**：改格式 ⇒ **两板位流必须同版**，与"两板同序列号禁广播烧录"（F6.1）叠加后，现场升级成本高。
- **G-D3 分流点不存在**：PC1→A→Aurora→B 的路径上，**A 侧没有"按目的转交本地控制"的逻辑**；现在 A 只是把帧往链路送。
- **G-D4 故障域**：光链断即对 B 失控（D8=低），而且不是"断了重连就行"——F7 已实证闪断会把**下游通路锁死**，串口也无效、只能整板重烧（`汇报_双板互联进展与板B稳定性问题_2026-11-09.md:48-54`）。与 R6"断线有明确报告"只能做到"报错"，做不到"仍可控"。

### 5.5 E — PC2 代理（**对照 · 否决：不进交付**）

**现在能否做：不做。** 决策（2026-11-12，项目负责人）：**E 及其传输层一律不进交付**——不作候选、不进推荐路线、不占 M1 排期。理由见 §2 F8 与本节的语义/时延证据；本节保留为**否决记录**（含复议条件），供导师追问时引用。

**为什么否掉（三条独立理由，任一成立即可否决）**

1. **违反字面**：v1.1 §7 标题是"**一台 PC** 集中控制两块 FPGA"，E 只做到"逻辑集中"，PC2 仍要各自操作本板（G-E1）。
2. **时序原理性不满足**：R8 明文"不可依赖 PC `sleep` 或串口发出时刻作为硬件事件真实时间"（v1.2:220）；而 E 的全部时序建立在 PC 时间上（G-E2）。且通道的 `message/send` **是信箱不是执行**（F8.2），时延由对端 agent 轮次决定（本机 selfloop ack ≈0.95 s，F8.3），掉线即退 issue 轮询 900 s（F8.4 ⇒ 最坏 15 min）。
3. **当前物理不可用**：对端 `10.194.20.154` ICMP/TCP 全不通、本机无入站放行规则（F8.5），且判据工具假阴性（F8.6）——**连"能用"这个前提都还不成立**。

**复议条件（什么情况下允许把这页翻回来）**

- 导师明确接受"逻辑集中/物理分布"作为交付形态（修改 Q1 口径）；**且**
- 通道跨机实测达标：双向可达 100%、ack 往返 p95 ≤ 2 s、PC2 在线率 ≥99%（§5.5 四步验收）；**且**
- 有硬件侧时间基准（板内计数器/PL 时间戳）承担"时窗真实边界"，PC 只投计划。

> 三条同时满足才复议；只满足一条不足以翻案——尤其第 3 条，它决定"E 永远进不了正式控制面"，这是设计约束不是实现问题。

**遗留证据（供追问，不作为待办）**

- 传输层定位与通道：A2A 7310 / MCP 18790 / stdio，跨机需显式放开，硬拒 `192.168.1.x`（F8.1）。
- 语义：`message/send` 只回 `[ack] received N bytes`、`state` 恒 `completed`（`team-link-a2a.mjs:251-284`，F8.2）。
- 本机 selfloop ack ≈0.95 s（`a2a.log` 11:48:53.482→54.432，F8.3）。
- 通道不可用三层根因与本机实测命令（F8.5/F8.6、§9「PC↔PC 协作工具」条）。

### 8.3 依据等级汇总（L0–L4）

| 结论 | 等级 | 理由 |
|---|---|---|
| B 的业务口上**存在**可直接复用的 UDP 命令端点 | **L3** | 顶层例化+参数+opcode 静态可查（F3.1–F3.7），且有 prj10 W5 **单板形态**上板验证记录；**未在 prj12 双板形态复测** |

| "两板同 IP/MAC 会使一 PC 控两板失效" | **L2** | 两条实测事实（F3.8 + F3.9）交叉推出，未做对照实验 |
| `team-link` 通道**当前不可用**（对端不可达 + 本机无入站规则） | **L3** | 双向 TCP/ICMP 探测失败 + 防火墙规则清单为空，均为本机可直接复现的实测（F8.5） |
| E 的时延由**对端 agent 轮次**决定，而非网络 RTT | **L2** | 读码证明 `message/send` 只回 ack 不执行（F8.2，静态）+ 本机 selfloop ≈0.95 s（F8.3，实测）；跨机端到端未测 |
| C 的第二 PHY "有引脚定义但装配未知" | **L1** | 只有 XDC 引脚与丝印记录，无装配/链路证据；勘误本身标 `TO_VERIFY` |
| A 的时延量级（ms 级、抖动不可控） | **L1** | 物理下界可算（54 ms），抖动无实测 |
| E 的抖动量级（跨机端到端） | **L0–L1** | 跨机无实测；只知"agent 轮次"决定下界（L2），分钟级上限属推断 |
| D 的扩展性最好、故障域最差 | **L1** | 拓扑推断，无实验 |
